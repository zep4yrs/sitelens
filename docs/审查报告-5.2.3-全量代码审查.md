## 1. 执行摘要

### 1.1 一句话结论

SiteLens 的**检测工程**与**安全防护设计**在同类 DAST 项目中属上乘（浏览器拨号层 SSRF 防护、zip 解压防护、报告 HTML 转义、脱敏诊断、并发信号量都是真实现），但**产品化最后一公里存在系统性裂缝**：

- **交付默认姿态不安全**：桌面版与 `serve` 默认起一个**无鉴权、无 Host/Origin 校验**的本地 API，任意网页（DNS rebinding / 简单请求 CSRF）即可驱动本机扫描器、清空历史、改配置、创建持久化定时任务；桌面更新器**信任链断裂**（校验可跳过、无签名、启动即静默执行下载物）。
- **企业化能力"宣称已交付、实际不可用"**：RBAC 矩阵与真实路由资源名不匹配（operator 角色基本不可用）、多租户隔离**零接线**（跨租户 IDOR）、PostgreSQL 迁移后自增序列不推进（首次写入必撞主键）。
- **质量门禁与验收材料失真**：`.cnb.yml` 一处转义写坏把 `benchmark/score.mjs --selftest` 整条门禁变成了 YAML 注释（**从未在 CI 执行**），而两份发布文档把它当"必过门禁"；验收报告仍写着"无数据库后端"等与代码相反的结论；`-race 全绿` 的表述被 Lead 的实测数据竞争证伪（现有单测没覆盖该并发组合）。
- **检测可信度有硬伤**：软 404 判定退化为"响应长度严格相等"（动态 404 页使整站软 404 防护一次性失效，`env-leak`/`bak-dump` 等高危 check 全站误报）；空 `Match` 的 check 恒命中；子域接管 CNAME 后缀丢点边界（`mygithub.io` 被当成 GitHub Pages）；WAF/兜底 200 页识别仍有漏网（`f7c4e0a` 修复未实现注释宣称的尺寸挡板）；表达式求值层 4 处已复现的语义错误（字节串转义、`raw_header`、协议模板伪造环境、`compare_versions !=` 反向）；情报层的 OSV 覆盖区间与版本比较语法不兼容，`data/intel_overrides.json` **128 条 affected 全部永不命中**并静默把 69 条 possible 推成 excluded。

## 2. 阻塞项（Blocker）

> 判定标准：不修复则**不应发版**（安全/信任），或**发版后核心宣称不成立**（能力/验收）。

### BL-1 [安全] 默认交付形态是"无鉴权的本地 API + 无来源校验"

**合并自**：A-01（Blocker）、D-02（P0）、Lead L-01（P0，独立验证 D-02）
**位置**：
- `internal/server/server.go:397-414`（`guard`：`api_token` 为空且 `auth_mode=none` 时**整段跳过**）
- `internal/server/server.go:417-423`（`headers`：仅 `Server` + `nosniff`，不看 `r.Host`）
- `internal/config/config.go:394-395`（默认 `Listen: 127.0.0.1:5000`、`AuthMode: "none"`）
- `.sitelens.example.yml:134-136`（`api_token: ""`）
- `desktop-wails/main.go:124-130`、`409-445`（壳只写 `web.listen`，**从不生成 token**）
- `desktop-wails/internal/usercfg/usercfg.go:69-78`（受管键只有 listen）

**证据**：

```go
// internal/server/server.go:397
func (s *Server) guard(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		if s.authMode() == "token" && strings.HasPrefix(r.URL.Path, "/api/") { ... }
		if tok := s.token(); tok != "" && strings.HasPrefix(r.URL.Path, "/api/") {  // tok=="" 时整段跳过
			if subtle.ConstantTimeCompare([]byte(r.Header.Get("X-Token")), []byte(tok)) != 1 { ... }
		}
		next.ServeHTTP(w, r)   // 默认配置：无任何校验
	})
}
```

```go
// desktop-wails/main.go:439
body = []byte(fmt.Sprintf("web:\n  listen: %s\n", listen))   // 不写 api_token / auth_secret
```

**影响**：全仓 `grep -rn 'Origin|Referer|Sec-Fetch' internal/**.go`（非测试）**命中 0**，`r.Host` 也从未被读取。于是：

1. **DNS rebinding**：攻击者页面把自有域名解析到 `127.0.0.1`，浏览器以 `Host: evil.example` 请求 `http://evil.example:5000/...`，服务端照常响应 → 同源，JS 可读全部 API 响应并写操作：拖走扫描历史（目标+漏洞+证据）、`PUT /api/settings` 改配置/锁死 token、`POST /api/batch/schedules` 落持久化定时扫描、`POST /api/loginbrute`、`POST /api/netsec`。桌面壳端口随机但可探测。
2. **本机任意进程/任意用户**直接操控引擎（多用户 Windows 风险）。

**验证**：读码 + 全仓 grep（Lead 独立复核，命中 0）；D 组从桌面壳侧独立确认"壳不生成也不传递 token"。
**修复建议**：
1. 桌面壳生成 128 位随机 token → 写入用户配置 `web.api_token`（或专用 `auth_secret`）→ 通过启动参数/首帧注入交给 SPA；
2. `headers` 中间件加 **Host 白名单**（`127.0.0.1:<port>`、`localhost:<port>`、`[::1]:<port>`）与 `Sec-Fetch-Site` 校验（`same-origin`/`none` 放行，`cross-site` 403）；
3. 监听回环但未配 token 时**启动即警告并在 UI 显式提示**；非回环监听且无 token 时拒绝启动（现在只打日志）。

### BL-2 [安全] 桌面更新器信任链断裂：校验可跳过、无签名、启动即静默执行

**位置**：`desktop-wails/update.go:33,107,123-128,172-189`；`desktop-wails/main.go:302-305`；`internal/updater/updater.go:133-153`

**证据（D 组核实的要点）**：
- `verifySHA512` **fail-open**：清单未提供 `sha512` 时直接 `return nil`（等同"跳过完整性校验"）；
- 更新物**无 Authenticode/签名校验**（`docs/release-5.2.3-发布欠账.md` 亦自承"未签名占位"）；
- **启动约 8 秒后自动下载，并以 `/S` 静默执行安装包**（无用户确认）；
- 下载源可被 `SITLENS_UPDATE_URL` 覆盖且**不校验 scheme**（接受明文 `http://`）；
- 只信 manifest 自称版本，**无版本下限**（可被降级）。

**影响**：更新通道的可信度完全依赖"manifest 服务器不被劫持/不被篡改"。任何能改写 manifest 或做 MITM（明文 http 时）的攻击者，即可在用户下次启动时**静默执行任意安装包**。对一款"安全扫描器"产品，这是最刺眼的信任缺陷。
**修复建议**：① 强制签名（Authenticode）+ 内置公钥验证；② sha512 缺失即拒绝，不接受"无摘要放行"；③ 版本单调递增（拒绝低于当前版本的更新）；④ 仅 https，禁 `SITLENS_UPDATE_URL` 覆盖或要求显式 `--allow-unsigned`；⑤ 执行安装包前必须用户显式确认。

### BL-4 [企业化] RBAC 默认矩阵与真实路由资源名错配，`operator` 角色实质不可用

**位置**：`internal/authz/authz.go:83-92`（默认矩阵）；`internal/server/authz_guard.go:69-76,92-101`（资源名 = 路径首段）

**证据**：默认矩阵 —— `viewer: *:read`；`operator: scan:* / report:* / asset:* / triage:*`；`admin: *:*`。而 `apiResourceOf` 取 `/api/<首段>`，真实路由资源名是 `job`、`history`、`export`、`assets`、`batch`、`settings`、`diagnostics`…（`server.go:247-304`）。A 组用探针跑出完整矩阵：

```
viewer    read =[version stats settings ... triage whitelist]   write=[]
operator  read =[scan triage]                                    write=[scan triage]
admin     read/write = 全部
```

**影响**：
1. `operator` **读不到自己刚发起扫描的进度/结果**（`/api/job/{id}` 资源名 `job` 不在白名单）、不能 `/api/history`、`/api/export`、`/api/batch` —— 与文档"运营：发起扫描、处理复核、导出"直接矛盾，实际只能全给 admin（最小权限形同废设）；
2. 资源名不一致（`asset`≠`assets`、`report`≠`export`）说明该矩阵**从未对着真实路由测试**；
3. `viewer` 的 `*:read` 覆盖 `settings` → 可读 `api_token` 明文（V-11）。

**修复建议**：由 `Handler()` 路由表生成"路由→资源名"映射并加单测守护；`viewer` 改显式枚举，排除 `settings`/`diagnostics`/`admin`。

**位置**：`internal/server/authz_guard.go:61-68`；`internal/authz/tenant.go:88-97,123-133`；`internal/server/server.go:1010-1022,1055-1065`；`graph_api.go:22-31,59-77`

**影响**：`authz.Isolate`/`VisibleTo` 在 `internal/server` **零调用**；`internal/store`+`internal/engine` 中**不存在任何 tenant 字段**（已 grep 确认）。因此 token 里的 `tenant` 只用于"拒绝别人显式声明的租户"，**数据面没有归属**。任何合法租户令牌（哪怕 viewer）可遍历 `id` 读取他租户扫描记录（目标、漏洞、证据、导出报告）、`/api/graph/{id}` 攻击链、`/api/diff` 跨租户对比。
**修复建议**：落库写 `tenant_id`（store 模型+迁移），所有 `{id}` 路由统一走 `loadRecordForClaims(id, claims)`，不匹配一律 404（不泄露存在性）。
**判定待产品确认**：若"多租户"仅为认证基座而非已交付能力，必须在 README/api-docs 明写"当前无跨租户数据隔离"。

### BL-6 [企业化] PostgreSQL：JSON→SQL 迁移后 identity 序列不推进，首次新扫描必撞主键

**位置**：`internal/store/sqlstore.go:503`（`postgresAutoIncRE`）、`:509`（`migrationStatementForDialect`）、`:593`（迁移 INSERT 列含 `id`）、`:635`（`scanInsertArgs` 返回 `rec.ID`）、`:164`（PG 常规插入不带 id）

**证据**：迁移时以**显式 id** 插入；PG 的 `GENERATED BY DEFAULT AS IDENTITY` **不会**因显式插入而推进序列；迁移后第一次 `SaveScan` 走 `:164` 不带 id 的分支，序列仍从 1 开始 → 主键冲突。C 组捕获了实际下发的 7 条 PG DDL 作为证据（本机无 PG 实例，未真跑；SQLite E2E 已验证正常）。

**影响**：`docs/release-5.2.3-发布欠账.md` P0-6「PG 驱动/DDL 已就绪」结论不成立；企业用户迁移到 PG 后**下一次扫描即报错**（且按 C-03 会被静默吞掉）。
**修复建议**：迁移结束后执行 `SELECT setval(pg_get_serial_sequence('scans','id'), COALESCE(MAX(id),1))`（或迁移 SQL 直接 `OVERRIDING SYSTEM VALUE` + 重建序列）；补一条真实 PG 的迁移→写入集成测试。

## 3. 安全漏洞

### 3.1 P0

#### V-05 CSRF：9 个 POST 不校验 Content-Type，`/api/history/clear` 不读 body
**位置**：`server.go:588,841,1213,1285`、`preflight.go:132`、`apispec_api.go:71`、`batchschedule_api.go:26,62`、`triage.go:227-235`；`server.go:1051`
**证据**：
```go
// hScan：不校验 Content-Type；text/plain 的 JSON 属"简单请求"，不触发 CORS 预检
_ = json.NewDecoder(io.LimitReader(r.Body, 1<<20)).Decode(&body)

// hHistoryClear：完全不读 body
func (s *Server) hHistoryClear(w http.ResponseWriter, r *http.Request) {
	writeJSON(w, 200, map[string]any{"cleared": s.st.ClearAll()})
}
```
**影响**：任意网页用 `<form method=POST>` 即可清空历史（`/api/history/clear`）、强制重载（`/api/admin/reload`）、创建持久化定时批量、提交审计上传（multipart 天然简单请求）；`text/plain` 形态可打全部 JSON POST 端点。与 BL-1 叠加即可在用户仅"打开一个网页"的情况下完成上述操作。
**修复**：统一中间件——非 GET/HEAD 拒绝 `Sec-Fetch-Site: cross-site`；有 `Origin/Referer` 必须同源；要求 `Content-Type: application/json`（multipart 白名单端点除外）；危险管理端点额外要求自定义头 `X-Requested-With`（简单请求无法伪造）。

#### V-06 `GET /api/replay/{id}` 有副作用（`<img>` 可驱动批量外发请求）
**位置**：路由 `server.go:297`，handler `server.go:1025-1039`
**证据**：`stats, details := replay.Batch(replay.NewFetcher(timeoutMS), rec.Result.Verified)` —— GET 一次即对历史发现的目标重放全部 DAST 探针。
**影响**：违背 GET 幂等；`<img src="http://127.0.0.1:5000/api/replay/1">` 即可反复触发（简单请求、无需 CORS），服务端与目标站点流量白耗；重放前无 `target.Validate`/`Allowed`（V-07 ③）。
**修复**：改 POST + CSRF 校验 + 每 id 限流；重放前逐 URL 过 SSRF 闸。
