# 前端设计令牌与结果页覆盖度（5.2 P0）

> 目标：把"视觉/交互"从散落在 `app.css` 里的硬编码，收敛成**单一来源的令牌**，
> 并让结果页先说清"这次扫了多少、有没有被拦"，再进明细。对应 `open-claude-ui`
> 逆向报告里 Anthropic 的做法：令牌可复用、契约可校验、状态可解释。

## 1. 令牌层（`web/css/tokens.css`）

- **唯一来源**：颜色/表面/边框/语义色、圆角、间距、阴影、字体、动效时长、焦点环、
  布局常量（`--top-h`）全部在 `tokens.css` 定义；`app.css` 只许 `var()` 消费。
- **浅/深两套**：浅色在 `:root`，深色在 `.dark`；`common.js` 按偏好
  `light | dark | auto` 切换 `html.dark`，`auto` 跟随系统 `prefers-color-scheme`
  （默认值已改为 `auto`；老用户已保存的偏好不变）。
- **动效**：三档时长 `--t-fast:150ms / --t-med:250ms / --t-slow:400ms` + 签名缓动
  `--ease:cubic-bezier(0.2,0,0,1)`；`prefers-reduced-motion` 已有全局降级。
- **纪律**：新颜色/圆角/时长先加令牌，再到 `app.css` 用 `var()`；不要在组件里写死色值。

### 门禁

`web/js/tokens.test.mjs`（CI 已接入 `.cnb.yml` 前端转义回归步骤）：

1. `app.css` 里每个 `var(--x)` 都必须在 `tokens.css` 有定义（防拼错/漂移）；
2. `tokens.css` 只允许 `:root` / `.dark` 令牌块（不许混组件样式）；
3. 颜色令牌浅/深两套齐全；动效四件套（三档 + 缓动）齐全。

## 2. 结果页「扫描覆盖度」卡（`Result.Diagnostics` → 前端）

位置：结果页摘要之后、指纹/发现明细之前。展示：

| 字段 | 来源 | 含义 |
|---|---|---|
| 访问页面 | `result.pages.length` | 实际进入分析集的页面数 |
| 实际请求 | `diagnostics.requests` | 实际发出的 HTTP 请求数（去重命中不计） |
| 去重省下 | `diagnostics.dedup_hits` | DAST 基线/只读页面复用省下的请求 |
| 被 WAF/限流拦截 | `diagnostics.blocked` | 被拦响应数（**不参与任何判定**） |
| 平均速率 | `diagnostics.avg_rps` | 本次扫描平均 req/s |
| 限速档 | `rate_mode` / `max_rps` | balanced ≤N req/s 或 polite 固定间隔 |

- 若 `waf_reasons` 非空，显示原因分布（如 `429 ×3 · retry-after ×1`）。
- 阶段明细表：阶段（首页/JS 端点/爬取/指纹/安全头/DAST）、请求、去重省下、被拦、耗时。
- **覆盖声明**：未列出的模块（未开启或未命中）不在覆盖内；被拦 >0 时提示
  "可能造成漏报，建议降低速率/更换出口后重扫"。
- 旧扫描记录无 `diagnostics` 字段时整块不渲染（additive，不影响历史记录）。

## 3. 证据呈现增强

- 每条「已验证漏洞」行增加 `证据 N/5` 徽章（复现命令 + 请求 + 响应 + 信号 + 二次确认）。
- 「最值得关注」前三卡补充**修复建议**（原先只有明细表有）。
- 每条发现仍保留可展开的「证据链」（curl 复现/请求/响应/信号），支持一键复制。

## 4. 改版回退

改动前的 `web/` 原样备份在 `%TEMP%\sitelens-web-backup-<时间戳>\`（本机），
且改动前 HEAD 已记录在备份目录 `HEAD.txt`；需要回退时：
`git checkout -- web/`（已提交的旧版）或从备份目录覆盖回来。
