# 5.3 内置验证集实跑验证报告

> 日期：2026-11-13
> 对象：内置验证 check 全量（1,010 条 = 60 手写核心 + 167 手写扩展 + 783 模板转译）
> 工具：`tools/checkvalidate`（本轮新增）+ `tools/checkvalidate/fixtures/*`

## 1. 为什么要跑这轮

1,010 条 check 里 783 条来自 afrog/nuclei 模板转译，离线门禁只能证明“不命中通用页面样本”。
真实 HTTP 链路还有软 404 基线、二次确认、同路径聚类、回显剔除等逻辑，必须端到端验证：

- **误报门禁**：正常站点不应有命中；
- **漏报门禁**：真实暴露的文件/端点必须被命中；
- 顺带检查：全量跑一轮的请求量、耗时、稳定性。

## 2. 方法

`tools/checkvalidate` 直接调用 `checks.AllChecks()` + `checks.RunList`（与引擎扫描同一执行路径），
对目标跑全量 check，输出命中与请求数；支持：

- `-expect-zero`：有命中即失败（误报门禁）；
- `-expect-hits a,b,c`：指定 check 必须命中（漏报门禁）；
- `-only`：只跑指定 check（调试）；
- `-interval`：本地靶场加速（默认 120ms，本地验证用 20ms）。

三个靶场：

| 靶场 | 构造 | 期望 |
|---|---|---|
| `fixtures/generic.js` | 任何路径返回 200 + 通用 HTML（模拟 SPA 软 404），带 nginx/Express 头 | **0 命中** |
| `fixtures/vulnerable.js` | 30 个路径返回真实暴露内容（.git/.env/actuator/凭据/备份/日志/K8s 等），其余路径返回通用页 | **30 条期望 check 全部命中** |
| SiteLens 引擎自身 | `sitelens-engine serve`（正常 Web 应用，非靶场） | **0 命中** |

## 3. 结果

| 目标 | check 数 | 请求数 | 命中 | 耗时 | 结论 |
|---|---|---|---|---|---|
| 通用站点靶场 | 1,010 | 924 | **0** | 18.5s | 误报门禁通过 |
| SiteLens 引擎自身 | 1,010 | 928 | **0** | 18.5s | 误报门禁通过 |
| 暴露靶场 | 1,010 | 951 | **30/30** | 19.0s | 漏报门禁通过 |

暴露靶场命中（部分）：

```
[critical] aws-credentials      /.aws/credentials
[critical] kube-config          /.kube/config
[critical] tfstate              /terraform.tfstate
[critical] ssh-private-key      /.ssh/id_rsa
[critical] heapdump             /actuator/heapdump
[high]     git-leak / git-config / env-leak / env-local
[high]     backup-sql / config-php-bak
[high]     actuator / actuator-env-root / k8s-namespaces
[medium]   es-cluster-health / k8s-version / tomcat-manager / dockerfile
[low]      server-status / actuator-health
[info]     tpl-* 系列（swagger-ui/php-ini/phpinfo/vernemq/kube-api/compose 等）
```

请求数 924–951 而非 1,010：同路径聚类（如 `/`、`/status`）共享一次请求，符合设计。

## 4. 发现并修复的真实误报

首轮对 SiteLens 引擎自身跑出 1 条命中：

```
[info] tpl-developer-notes  /  "Developer Notes"
判据：RegexBody: ["<!--(.*?)-->", "/[*][*](.*?)[*][*]/"]
```

该正则**只有语法、没有字面量**，任何带 HTML 注释的页面都会命中——是真实误报。
修复在转译器（`tools/tpl2check`）：

- 新增 `literalAlnum()`：正则里字母数字字面量 < 6 个不算强特征；
- 重新生成转译集后该 check 被剔除（783 条），引擎自身复跑 **0 命中**。

## 5. 复现

```bash
# 1) 通用站点靶场（误报门禁）
node tools/checkvalidate/fixtures/generic.js 18081
go run ./tools/checkvalidate -target http://127.0.0.1:18081 -expect-zero -interval 20

# 2) 暴露靶场（漏报门禁）
node tools/checkvalidate/fixtures/vulnerable.js 18082
go run ./tools/checkvalidate -target http://127.0.0.1:18082 \
  -expect-hits git-leak,env-leak,phpinfo,actuator,heapdump,backup-sql,aws-credentials,kube-config,tfstate,ssh-private-key,config-php-bak,server-status,tomcat-manager,dockerfile,backup-zip,es-cluster-health,k8s-namespaces,k8s-version,tpl-php-ini,tpl-kube-api-scan-r1,tpl-vernemq-status,tpl-phpinfo-files-p2,tpl-comprehensive-swagger-ui-version-detection-p26,tpl-docker-compose-yml \
  -interval 20

# 3) 正常应用（SiteLens 引擎自身）
./sitelens-engine -config /tmp/sl.yml serve   # web.listen 127.0.0.1:18090
go run ./tools/checkvalidate -target http://127.0.0.1:18090 -expect-zero -interval 20
```

## 6. 结论与边界

- 内置验证集在「通用页面 / 正常应用」上零误报，在「已知暴露靶场」上 30/30 命中；
- 783 条转译集仍以**暴露面检测**为主（info/low 居多），不是利用级验证；
- 本报告只覆盖受控靶场；对真实授权站点，建议先跑「标准档」（不含扩展/转译集），
  再按需开「完整/穷尽」档并人工抽样复核命中；
- 下一步：ARES 借鉴设计稿 P0（ScopeGuard 双层 + MCP 危险操作确认）。
