## 0. 一分钟速览

**SiteLens 站点透视** = 单二进制、零外部依赖的**验证型** Web 漏洞扫描器。

## 2. 本机开发环境

### 2.1 能跑起来的最小命令 ✅ 实测

```bash

```

> ⚠️ **`go test ./internal/...` 不覆盖 `desktop-wails/`**——它是独立 Go 模块（`sitelens-wails`），CI 单列一步。改壳的代码必须单独 `cd desktop-wails && go test ./internal/...`。

### 2.2 本机坑：可执行文件会被清理 ✅ 实测

在 Windows 上构建/运行可执行文件时踩到两个坑：

1. **工作区内的 exe 曾被杀毒软件删除**：`go build -o bin/sitelens.exe` **构建成功、文件 35MB 落盘**，但几秒后 exe 消失；复制成 `sitelens.bin` / `sitelens.txt` 同样消失（**按 PE 内容识别，换扩展名无效**），目录本身留着。
   **根因：本机杀毒软件**（2026-10-28 由使用者确认并关闭）。关闭后二进制可正常产出并跨命令存活。
   → 遇到"编译成功但文件消失"，**第一反应查杀毒软件隔离区**，不要怀疑构建脚本或 `.gitignore`。
2. **`%TEMP%` 下的 exe 同样不可靠**：即使杀毒已关，放在 `%TEMP%` 的 exe 仍会被拦截（"拒绝访问"）。
   → **构建产物请放工作区内**（如 `bin/`，已被 `.gitignore` 忽略），不要放 TEMP。

快速验证可用 `go run ./cmd/...`（临时 exe 由 go 自己管理，可用）。

> **5.2 架构变更：引擎与 CLI 拆成两个二进制。**
>
> 此前**一个 exe 既是引擎又是 CLI**，带来两个具体问题：① 桌面壳（GUI 子系统）
> 拉起它时必然弹出一个黑色控制台窗口，退出时树杀用的 `taskkill` 又闪一个；
> ② CLI 能力被整个塞进桌面安装包，白占体积与维护面。
>
> 现在：引擎（`cmd/sitelens-engine`）只做 `serve` + `update-seed`，由桌面壳拉起；
> CLI（`cmd/sitelens`）独立分发（**走 npm 线**），**不随桌面安装包发布**。
> 两者共用同一套 `internal/` 库代码，`update-seed` 抽在 `internal/seedcmd`。
>
> ⚠️ **引擎必须保持控制台子系统**——CLI 形态要靠 stdout 输出 `scan --json` 的结果，
> 引擎侧 `update-seed` 也要输出交付报告。「不弹控制台窗口」只能由桌面壳在拉起时
> 用 `CREATE_NO_WINDOW` + `HideWindow` 解决，**不能靠给引擎加 `-H windowsgui`**。
> npm 线（`tui/scripts/build-engines.mjs`）构建的正是 `./cmd/sitelens`，**不受拆分影响**。

> **5.2 变更：CLI 融入 TUI。** npm 线原本有**两个 CLI**（Node 的 `sitelens` 与平台包里的
> Go 二进制），现已收口为**一个入口**：
>
> | 层 | 职责 |
> |---|---|
> | `tui/`（Node） | **唯一用户入口**：交互式 TUI（首屏「选功能」）+ 全部非交互命令。命令表 `src/commands.mjs` 是唯一事实源，`--help` 由它生成 |
> | `cmd/sitelens`（Go） | 退回**内部实现**：npm 平台包装它，用户不再直接面对 |
> | `cmd/sitelens-engine`（Go） | 桌面线内部引擎：`serve` + `update-seed`，收到未知子命令**直接报错**（不静默当 serve 跑） |
>
> 两种命令实现形态：**编排型**（TUI 自己起 serve 走 HTTP API：scan / doctor / history /
> verified）与**直通型**（spawn 引擎执行原生命令，stdio 与退出码透传：serve / audit /
> correlate / graph-read / regression / migrate-pg / update-*）。
>
> **用户区统一到 `~/.sitelens/`**（npm 线没有安装目录可写）：`config.yml`（TUI 管理）·
> `data/`（资产）· `data/state/`（历史）。首次运行自动用引擎的 `update-seed` 把平台包内置的
> 指纹库交付到用户区（按引擎版本收敛，同版本 no-op）。

## 4. 子系统交接要点

### 4.1 主动验证层（DAST / exploit / netx / replay / beacon / target / httpx）

**探针模型**：把"探针类"抽象成 `{kind, values[]}`，逐类逐值探测，**某类命中即 break 该类**，但其他类继续跑（`internal/dast/dast.go:319-373`）。所以"类内短路"≠"全局短路"。

**判定通道**：

| 通道 | 判据 | 位置 |
|---|---|---|
| 报错特征差分 | 正文命中 `sqlErrors` 且基线不含 | `dast.go:890-900` |
| 报错**状态**差分 | 基线 <400 且注入后 ≥500 | `dast.go:901-915` |
| 时间差分 | 基线→注入→复测，两次都超阈值 | `dast.go:667-734` |
| 运算结果回显 | 结果串**独立成串**出现 | `deep.go:349-378` |
| 布尔尺寸差分 | 真分支贴基线(≤15%) 且真/假差 ≥5% | `blind.go:139-151` |
| 响应头集合差分 | CRLF 后新增头名 | `deep.go:882-892` |

**二次确认不是一个统一 pass，而是各通道内建**：timeBlind 注入两次、boolBlind 整套再跑一轮、cmdInject 再打一次。真正的"命中后重放复核"在 **exploit 层**——用**全新随机 marker** 再探一次证明影响（`exploit/exploit.go:70-74`），三档 `proven/observed/none`。

**回显剔除三道**（DAST 侧）：① 每参数先取原 URL 响应作基线，标记不在基线才算命中；② `matchMarkerNotIn` 跳过"出现在 payload 字面量里的标记"（自指剔除，`deep.go:531-544`）；③ `cmdEchoConfirmed` 要求结果不紧贴算式。

> 软 404 基线**不在 DAST 里**（DAST 用的是"原参数 URL 基线"）。它在 checks 层：`soft404Baseline` 请求一个不存在路径 `__sitelens_probe_none__`，回传**原始长度 / 剔回显后长度 / 小写 200 字符前缀**三元组，命中时长度相符且前缀匹配则整组抑制（`internal/checks/runner.go`）。

**证据链统一入口** `chainEvidence`（`dast.go:818-827`）：填 `Request`（GET 语义报文，用 `RawQuery` 保留原始编码）、`Replay`（`curl -sk --path-as-is '<URL>'`）、`Response`（状态/长度/240 rune 摘要）。

**SSRF 三层**（`internal/target/validator.go`）：协议白名单（只 http/https）→ 保留地址黑名单（`metadata.google.internal` **永久阻断**、**`gov.cn` 代码级硬保护无开关可关**）→ DNS 逐 IP 检查（loopback/private/link-local/unspecified/CGNAT 100.64.0.0/10）。`allow_private` 只放宽私网与本地主机名，**不放宽 metadata 端点与 gov.cn**。重定向逐跳复检由 httpx 手动跟随时实现（禁用自动重定向，每跳重跑 `target.Validate`，最多 6 跳）。

**硬上限**（摘要）：DAST MaxParams 24 / MaxProbesPerClass 12 / MaxURLLen 2048；httpx 限速 / Timeout 20s / MaxHops 6 / body 3MB；netx Timeout 5s / MaxReadBytes 64KB / MaxRounds 4；beacon 512 hits / 30min TTL。

### 4.2 模板漏斗 + DSL + 情报

**漏斗链**：`nuclei.Index(dir, cachePath)` → 扫盘 → 缓存命中（`cacheSchema = 8`，`nuclei.go:51`）→ 单文件读取（>512KB 拒）→ `convertAny` 转换 → 协议旁路（`ConvertNetwork`）→ 元信息提取 → 去重（**仅 legacy 轮**）。

**三前端形态**（`convertAny` = `Convert` → `ConvertRaw` → `ConvertAfrog`，`nuclei.go:847-855`）：

| 形态 | 入口 | 关键约束 |
|---|---|---|
| nuclei path | `nuclei.go:508` → `normFromTpl:547` | 仅 GET/POST；path 必含 `{{BaseURL}}`；后缀不得含其他 `{{}}`；必须有 matchers |
| raw 请求 | `nuclei.go:656` → `parseRawRequest:613` | 首行 `METHOD 路径`；**除 Content-Type 外请求头全丢** |
| afrog rules+expression | `afrog.go:123` | expression 只许纯 `&&` 链或纯 `\|\|` 链的 `rN()`；AND 链要求各 rule 请求等价，否则整条拒收 |

**DSL 安全子集**：支持比较、逻辑、`contains/contains_all/contains_any/icontains/regex/starts_with/ends_with/to_lower|to_upper/len/compare_versions`；变量 `status_code/body/host/header[s]`。
Compile 拒绝：未知函数、未知变量、元数错、嵌套 >64 层、表达式 >8192 字符、纯排除式。
**关键语义：DSL 是整模板级一票否决**——任一表达式编译失败 → 整模板拒收（`nuclei.go:737-759`）。

**MoE 三路调度**（`SelectWithCVE`，`nuclei.go:272`）：CVE 命中桶 > tag 命中桶 > 轮转池。命中集预算 `n*2/3`，超配部分**退回轮转池不丢弃**。轮转顺序 = `lastRun` 升序 → 词频余弦相似度降序 → path 升序。`lastRun` 持久化在 `data/state/nuclei_schedule.json`。

**情报三级判定**（`intel.MatchWithNVD`）：
- `confirmed`：版本落在 `data/affected_ranges.json` 的受影响区间内
- `possible`：同名提示（无版本或无区间数据）
- `excluded`：版本不在区间 → 丢弃不展示
- NVD CPE 通道**恒为 possible**（NVD 已砍掉版本边界字段）

**rex 受限回溯引擎**：RE2 无环视/反向引用，社区服务指纹库有数百条此类模式，丢弃即盲区。仅在 `regexp.Compile` 失败后回退，10 万步预算（`defaultBudget = 100000`），耗尽则整个匹配放弃（宁少报）。

### D1 🔴 CLI 全局 flag 放在子命令后会被静默忽略

**位置**：`cmd/sitelens/main.go:76`（`flag.Parse()`）

**现象** ✅ 实测：

```
A) sitelens -config <cfg> scan <target>   →  ✅ 扫描成功
B) sitelens scan <target> -config <cfg>   →  ❌ exit 1
   "error": "目标解析到内网/保留地址，已拦截"    ← cfg 里的 allow_private:true 完全没生效
```

**根因**：Go 的 `flag.Parse()` 遇第一个非 flag 参数即停止解析，于是 `serve` / `scan` 之后的 `-config` / `-graph` / `-ast` 全部落进 `flag.Args()` 被丢弃。

**作者已知但没推广**：`main.go:86-97` 为 `update-seed` 单独补了一个局部 `FlagSet` 来处理 `--seed-dir` / `--user-dir`，同样的手法没用到 `-config`。

**影响**：所有用户按"子命令 + 参数"的自然直觉写命令，配置**静默失效**——不报错，只是不生效。这是本仓库最容易踩且最难自查的一个。

**修复方向**：把 `-config` / `-graph` / `-ast` 的解析移到子命令 switch 内部（对每个子命令做一次局部 `FlagSet` 解析），或在 `flag.Args()` 里补扫已知全局 flag。

### D2 🔴 afrog 模板 100% 过不了漏斗，整个来源贡献 0 条检查

**位置**：`internal/nuclei/afrog.go:24-36`（`afrogRule` 结构体）、`:93`、`:103`

**现象** ✅ 实测（直接扫 `packs/nuclei-templates.tar.gz`）：

| 指标 | 实测值 |
|---|---|
| afrog 模板总数 | 1,699 |
| 有 rule 级 `expression` | **1,687（99.3%）** |
| 有 `response:` 块 | **0** |
| 有 `status_code:` | **0** |
| **通过漏斗** | **0** |

**根因链**：
1. afrog 模板的判定逻辑写在 **rule 级 `expression`**（真实样本）：

   ```yaml
   rules:
     r0:
       request:
         method: GET
         path: /include/thumb.php?dir=http\..\admin\login\login_check.php
       expression: response.body.bcontains(b"<?php") && response.body.bcontains(b"login_met_cookie($metinfo_admin_name);")
   expression: r0()
   ```

2. `afrogRule` 结构体**没有 `expression` 字段** → yaml.v3 默认忽略未知字段 → **判定条件被静默丢弃**
3. `afrogNorm` 只能从 `response.status_code` / `response.body` 拼 matcher，而 afrog 模板**从不写 response 块** → `len(matchers) == 0` → `afrog.go:103` **整条拒收**
4. 另有 694 条因路径含 `{{}}` 占位符在 `afrog.go:93` 被拒

**定性**：这是"少报"不是"误报"（fail-closed，方向正确），但意味着 **afrog 这个来源目前一条都没生效**。README / 开发文档把 afrog 1,699 条算进了"117,889 条可运行模板"。

**修复方向**：给 `afrogRule` 补 `Expression string \`yaml:"expression"\`` 字段，并实现该表达式的求值（至少支持 `response.status == N` / `response.body.bcontains(...)` / `&&` / `||`）。**修复前必须评估误报**——一旦放行，这 1,699 条会真正开始产生发现。

### D3 🟠 DAST 预编码载荷被二次编码，CRLF / 反序列化两条通道实际不生效

**位置**：`internal/dast/dast.go:865-874`（`setParam`）

**现象** ✅ 实测（独立 Go 程序复现 `setParam` 逻辑）：

```
crlfInject "%0d%0aX-Sitelens-Crlf:%20sl9z7"  →  ?q=%250d%250aX-Sitelens-Crlf%3A%2520sl9z7
deserProbe "%AC%ED%00%05sl"                  →  ?q=%25AC%25ED%2500%2505sl
```

**根因**：`setParam` 用 `url.Values.Encode()`，它对 value 做 percent-encode，`%` → `%25`。预编码载荷被**编码两次**，服务端单次解码拿到的是**字面文本 `%0d%0a` / `%AC%ED`，不是 CR/LF 字节、不是 Java 序列化魔数**。

**为什么单测是绿的**：`internal/dast/deep_test.go:53-58` 的桩件按**头名子串**匹配，从不校验真字节；`blind_test.go:9-11` 的注释已明说"setParam 落盘的是 url.Values.Encode 编码形态"。

**修复方向**：这类"要注入原始字节/原始控制符"的探针不能走 `setParam`，需要一条**原始注入**构造路径（直接字符串拼接 URL，或用 `url.URL{Opaque:...}` 绕开 encode）。

## 8. 不可放松的红线

改这个仓库时，下面几条是产品立意，**动了就等于改了产品**：

1. **宁少报不误报**——模板 DSL 编译是整模板级一票否决（`nuclei.go:737-759`）；`rex` 回溯预算耗尽宁可放弃匹配也不无限回溯；`chain.NewChainEdge` 无证据直接报错。**不要为了"提高通过率/覆盖率"放松这些闸**——D2 修 afrog 时尤其危险。
2. **每条发现必须可复核**——证据链四件套（重放请求 / 响应快照 / 命中信号 / curl 复现命令）是产品分界线。D4 那种"replay 复现不了真实请求"的问题属于红线破损，不是小 bug。
3. **主动能力默认关闭 + 硬上限**——`exploit.enabled` 默认 false；DAST 各通道独立开关；`target.allow_private` 默认 false。
4. **`gov.cn` 代码级硬保护**——无任何配置可关（`internal/target/validator.go`）。`metadata.google.internal` 同理。
5. **凭证只从配置读取**——不写日志、不落证据、不进报告。
6. **数据快照一致性**——单次扫描全程用同一份 matcher/kb（`engine.go:129-134`），热替换不影响进行中的扫描。
7. **可再生数据不入库**——全量模板池靠 `update-*` 镜像；`packs/` 与 `models/` 是打包产物，不是手工维护源。
