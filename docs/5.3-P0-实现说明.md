# 5.3 P0 实现说明：ScopeGuard 双层 + MCP 危险操作确认

> 日期：2026-11-13
> 对应设计稿：`docs/5.3-ARES借鉴设计稿.md` §4.1（ScopeGuard）、§4.5（MCP 危险操作）
> 状态：**已落地并合并 main**

## 1. ScopeGuard：从"入口检查"升级为"入口 + 拨号双层"

### 1.1 问题

此前 `scan.allow_hosts` 只在**引擎入口**做一次应用层检查（`target.Allowed`）。一旦
入口校验通过，后续所有实际网络行为都不再复核：

- 页面里的 302 跳到白名单外主机；
- 子请求/协议探测/资产查询使用独立客户端；
- DNS 重绑定窗口（校验时解析 A，拨号时解析 B）——`httpx` 的 BUG-021 修法关掉了
  重绑定，但**没有关掉"跳到白名单外"**。

### 1.2 实现（四层落点）

| 层 | 文件 | 行为 |
|---|---|---|
| HTTP 拨号层 | `internal/httpx/client.go` | `ClientOptions.AllowedHosts`；`dialContext` 在**任何**建连前校验 `target.Allowed(host)`，命中失败直接返回 `scope: ... allow_hosts`。重定向逐跳都走拨号层，因此越权跳转被拒。`Resolve=false`（本地靶场姿态）同样过白名单。 |
| 非 HTTP 拨号层 | `internal/netx/netx.go` | `Config.AllowedHosts`；`Dial` 在安全闸之后、拨号之前校验；`DNSQuery` 同样校验（防止用 DNS 查询探测白名单外域名）。 |
| 网络探测逐跳 | `internal/netsec/netsec.go` | `CheckHTTP(rawURL, allowHosts)` 每一跳都校验 allow_hosts（原来只校验 SSRF/gov.cn/跨主机）。 |
| 接线 | `internal/engine/engine.go`、`netproto.go`、`internal/server/server.go`、`internal/apispec/graphql.go` | 所有扫描/探测路径透传 `cfg.Scan.AllowHosts`；GraphQL introspection 也走拨号层白名单。 |

语义：`allow_hosts` 为空 = 不限制（保持既有行为零变化）；非空 = 精确域名或
`*.example.com` 后缀（不匹配 apex），与引擎入口同一套 `target.Allowed`。

### 1.3 测试

- `internal/httpx/scope_test.go`：白名单外请求零外发被拒、白名单内放行、拨号层
  直接拒绝（含 IP 字面量）；
- `internal/netx/scope_test.go`：`Dial` / `DNSQuery` 白名单外拒绝；
- `internal/netsec/*_test.go`：`CheckHTTP` 新签名（逐跳 allow_hosts）；
- 全量 `go test ./internal/...` 通过。

### 1.4 边界（如实说明）

- `dast` 上传探测与 `replay` 回放使用独立 no-redirect 客户端，目标来自**已校验入口**
  且不跟随重定向；它们未接拨号层白名单（下一步可统一收口到 `httpx` 的 guard dialer）；
- `netx.DialForTest` 明确跳过安全闸（仅测试/本地靶场），产品代码不用。

## 2. MCP 危险操作确认（单次令牌 + Pre-flight 范围检查）

### 2.1 问题

MCP 工具面此前只有 `--allow-active` 一个总闸：拿到主动工具的智能体（或被提示注入
的模型）可以直接发起 `scan` / `graphql_introspect` / `assets`，没有"单次授权"概念，
也无法把授权绑定到具体工具+参数。

### 2.2 工具分级

| 级别 | 工具 | 约束 |
|---|---|---|
| 只读 | capabilities / scan_status / scan_result / history / history_get / graph / export / apispec / confirm_action | 无额外约束 |
| 危险（主动） | **scan / graphql_introspect / assets** | `--allow-active` + `confirm_action` 一次性令牌 + `allow_hosts` Pre-flight |

### 2.3 流程

```
1) confirm_action(tool="scan", params={"url":"https://example.com/"})
   → Pre-flight：allow_hosts 必须非空，且 params 里所有目标（url/endpoint/host…）
     都命中白名单；否则拒绝签发。
   → 返回 confirm_token（HMAC-SHA256 绑定「工具名 + 规范化参数」，TTL 60s，单次有效）

2) scan({"url":"https://example.com/", "confirm_token":"..."})
   → callTool 校验：令牌签名/过期/重放/工具/参数全部匹配，且再次 Pre-flight 范围
   → 通过后删除 confirm_token，交给原 handler
```

### 2.4 fail-closed 规则

- 未配置 `allow_hosts`（`--allow-hosts` / `SITELENS_MCP_ALLOW_HOSTS`）→ **拒绝签发**；
- 参数里没有可识别目标 → 拒绝（无法做范围校验）；
- 任一目标越权 → 拒绝，并指明 host；
- 令牌过期 / 重放 / 工具或参数被改 → 拒绝；
- 密钥生成失败 → `conf=nil`，危险工具全部拒绝。

### 2.5 配置与兼容性

```bash
# 旧行为（只读工具）不受影响
sitelens mcp

# 危险工具：显式开启 + 授权范围
sitelens mcp --allow-active \
  --allow-hosts example.com,*.corp.example \
  --api-token "$SITELENS_API_TOKEN"
```

**行为变更**：以前 `--allow-active` 后可直接 `scan`；现在必须多一步 `confirm_action`。
这是 P0 的预期安全语义（危险操作需显式单次授权），MCP 客户端/智能体需要按新流程调用。

### 2.6 测试

`internal/mcp/p0_test.go`：
- 令牌签发/核销、重放拒绝、参数/工具绑定、篡改拒绝；
- Pre-flight：未配置白名单拒绝、无目标拒绝、越权拒绝、`*.example.com` 放行子域；
- 端到端：无令牌调用 scan 被拒；越权目标签发被拒；合法签发→调用成功→重放被拒；
  未配置 allow_hosts 时危险工具拒绝。
