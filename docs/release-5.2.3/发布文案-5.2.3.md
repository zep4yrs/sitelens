## 1. 核心定位

**一句话**
> SiteLens（站点透视）：把“扫到了什么”变成“为什么可信”的验证型 Web 安全扫描器。

**副标题**
> 二次确认、证据链、黑白盒关联——少一点“可能”，多一点“确认”。

**三个卖点**
1. **验证驱动，不堆告警**：42 条内置无害验证 + 二次确认 + 回显剔除 + 软 404 基线；WAF 拦截不参与判定。
2. **证据链可复核**：每条发现带复现命令/请求证据；黑盒发现可与白盒 AST 污点通过 `evidence_link` 关联成攻击链。
3. **部署与 Agent 友好**：Windows 一键安装/覆盖升级；`sitelens mcp` 提供 13 个工具，辰极 Lodestar 可直接调用。

**定位边界（内部话术）**
> 综合对标 3.68/5，第二梯队上沿；验证 4.75、部署 4.90 两项对标第一；覆盖/召回仍在补实测，目标 12 个月内进第一梯队。

## 2. 发布公告（公众号 / 长文）

**标题备选**
- 《SiteLens 5.2.3：从“扫到”到“确认”，我们把验证做重了》
- 《不堆功能的一版：SiteLens 5.2.3 发布》
- 《5.1.0 之后唯一正式版：SiteLens 5.2.3 带来了什么》

**正文**

5.2.3 是 SiteLens 在 5.1.0 之后的**唯一正式发布**。原计划拆成 5.2.0/5.2.1/5.2.2 的三批内容——代码库体检修复、5.2.x 工程批次、G09/G10 高级检测与企业化基座——这次一次性合并交付。

**先修“会误导人的地方”**

5.2.0 的 36 条体检缺陷修了 35 条：CVSS v3.1 计分与 NVD 官方 29 万条向量逐条对拍，不符率从 41.42% 降到 0；四段版本号不再误判“确认受影响”；复现命令全量 shell 转义；云 metadata 永久阻断 + DNS 重绑定封堵；afrog 模板 expression 求值器把通过率从 0 拉到 51.7%。

**再把“慢”和“重”降下来**

指纹匹配 24.7ms→5.3ms，多页扫描 102ms→6.2ms，模板索引热路径 1.1s→6ms；限速层重做为 per-host 共享令牌桶，WAF 特征自动降速、被拦响应不参与判定，4 页带 DAST 的实测墙钟从 155.1s 降到 98.1s。默认安装包不再携带 ONNX 资产，ML 资产 748.9 MiB→约 106 MiB。

**这一版新增什么**

- **高级 Web 检测（G09/G10）**：越权矩阵、业务逻辑、上传绕过、反序列化入口、WebSocket/h2c 协议面——默认全关，逻辑/上传默认 dry-run，需显式授权与会话材料；不是“打开就自动打”。
- **企业化 6.x 基座**：`store.driver=json|sqlite|postgres`、RBAC/租户、worker 池；SQLite 已实测落库/历史，PostgreSQL 驱动与方言 DDL 就绪（真机实例待验）。
- **MCP 接口**：13 个工具，把扫描/状态/结果/事实图/导出/审计接入 Agent 工作流。
- **URL 自动修正**：补协议、去标点、hxxp/[.] 还原、全角转半角，只改格式不改目标。

**验证到了哪一步**

自建合成靶场 10 目标 P/R/F1=1.0；WSL 标准靶场子集（DVWA/xsslabs/upload-labs）7 目标 P/R/F1=0.8333；真机安装/升级/启动/卸载/重装通过；`check.ps1 -Strict -RequireSigned` PASS=12。完整的 DVWA/pikachu 矩阵还没跑，PostgreSQL 真实实例还没连，这两项会作为下一阶段的第一优先级。

**适合谁**

需要“少而可信”的发现、要给开发复现证据、要把安全能力接进 Agent/自动化流程的团队。不适合追求“一次扫出所有漏洞”的堆量场景。

安装包：`SiteLens-Setup-5.2.3.exe`，135,605,744 字节，SHA256 `32ACC9113B722E6B3992C34CE6336060C8F00C50BD3BE3674947D5F4053C5104`。当前为内部自签名版本，正式公网分发前会替换受信任证书。

## 9. 知乎 / 技术社区长文（深度版）

**标题**
> 为什么我们宁愿跳过 5.2.0，也要先把“误报”修掉

**正文节选（可直接扩写）**

做扫描器最难的从来不是“扫到”，而是“扫到之后敢不敢信”。

5.1.0 之后我们排了三批功能，但越写越发现一个更基础的问题：CVSS 计分和 NVD 对不上、四段版本号会误判受影响、复现命令在特殊字符下跑不起来、云 metadata 和 DNS 重绑定还有口子。这些问题不修，功能越多，误导越大。

所以我们做了三件事：

1. **把结论修准**：CVSS v3.1 与 NVD 29 万条官方向量逐条对拍，不符率 41.42%→0，并固化成门禁；afrog 模板 expression 求值器把通过率从 0 拉到 51.7%。
2. **把性能做轻**：指纹匹配 4.7×、多页扫描 16.4×、模板索引热路径 1.1s→6ms；WAF 特征下自动降速，被拦响应不参与判定，实测墙钟 -36.8%。
3. **把高级能力关进笼子**：越权/业务逻辑/上传/反序列化/WS 检测默认全关；逻辑与上传永远 dry-run；IDOR 没有多角色会话就不跑。我们不想做一个“打开就乱打”的扫描器。

5.2.3 是 5.1.0 后的唯一正式版。它不完美：完整 DVWA/pikachu 矩阵还没跑，PostgreSQL 还没连真机，CLI 五平台包还没发。但验证这件事，我们想先做扎实。

## 13. 常见质疑 FAQ（对外应答）

**Q：为什么跳过 5.2.0/5.2.1/5.2.2？**
> 三批内容本来就是连续工程批次，拆版本号只会让升级路径和文档更乱。5.2.3 是 5.1.0 后唯一正式发布，CHANGELOG/发行说明按累计口径写全。

**Q：实测 P/R/F1 到底多少？**
> 自建合成靶场 10 目标 P/R/F1=1.0；WSL 标准子集 7 目标 0.8333。完整 DVWA/pikachu/Juice Shop 矩阵还没跑，我们不把子集当全量。

**Q：为什么高级检测默认关？**
> 越权/逻辑/上传/反序列化/WS 会改状态或依赖会话，默认 dry-run/关是安全姿态；显式授权与会话材料才启用。

**Q：为什么安装包是自签名？**
> 当前是内部验收版，正式公网分发前会替换受信任代码签名证书。

**Q：ML 模型是什么？**
> 三个本地线性模型（cve-tech/cwe-type/sev-linear），只做先验/富化，不产生 finding；ONNX 可选高级包默认不带。

**Q：和 Invicti/AWVS 比怎么样？**
> 按内部对标模型综合 3.68/5、第二梯队上沿；验证 4.75、部署 4.90 两项对标第一；覆盖/召回仍在补完整矩阵。我们不拿排名当卖点。

**Q：能替代人工渗透吗？**
> 不能。它是验证型扫描器，负责把可自动确认的部分做扎实，不能替代人工业务逻辑与社工测试。
