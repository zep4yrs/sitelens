# SiteLens 5.0 模型卡

三个自有模型 + EXP-1004 对比系统。训练/评测全部真实执行，本卡记录可复现要点
与已知局限。

**推理资产口径（现状，勿按旧稿理解）**：Go 引擎默认只带**线性模型**
`models/go/ml_assets/`——`cve-tech.*` / `cwe-type.*` 为纯文本系数与词表，
`sev-linear.*` 为 0.7MB 严重度回归兜底，另含 `fixtures.json` /
`sev-fixtures.json` / `sev-linear-fixtures.json` 对拍夹具；源码克隆即可跑，
无需另拉模型。`sev-prior-v3.1-a/b.onnx`（fp32 双种子）与 `-int8` 版本自 **5.2
仓库瘦身**起已移出仓库（分发默认不带，可选 ONNX 高级包需手动放入），详见
[release-5.2.0/仓库瘦身-5.2.0.md](release-5.2.0/仓库瘦身-5.2.0.md)。
训练/评测的中间产物与指标留档在 `data/ml/`（不进 git）。
模型名册的唯一事实源是 `ml/model_registry.json`（公开名 / 现役与前版本 /
质量口径），本卡与它冲突时以名册为准。

## 自有模型（EXP-1001 / EXP-1002，最初两模型）

> sev 线的现役版本已从 EXP-1001 配方演进到 EXP-1017（v3.1），见文末
> 「2026-09-29 部署升级轮」；下表是 5.0 立项时的原始卡，保留作对照。

### EXP-1001-severity-model

| 项 | 内容 |
|---|---|
| 任务 | CVE 描述 → 严重度四分类（critical/high/medium/low） |
| 数据 | kb-5.0.0 `kb_cve`：NVD base severity，291,439 有标签 CVE；时间切分 train pub<2024 / test≥2024（148,356 / 143,083） |
| 特征 | TF-IDF word 1-2gram，min_df=3，max_features=120k，sublinear_tf |
| 模型 | SGDClassifier(log_loss, alpha=1e-6, class_weight=balanced) |
| 性能 | acc 0.5738 / macro-F1 0.484；ROC-AUC OvR critical 0.8266 / low 0.7738 |
| 跨源验证 | cve_ms 一致率 36.6%（微软公告严重度口径不同，如实记录）；vuln_kb CVSS 分带 81.2% |
| 消融 | 仅元数据 HistGB acc 0.4733——文本承载主要信号 |
| 局限 | 严重度四类界线本身模糊（跨源一致率差异即证据）；不能当作绝对真值使用 |

### EXP-1002-product-relation-model

| 项 | 内容 |
|---|---|
| 任务 | 新 CVE 描述 → 受影响产品/技术 Top-K（top-200 vendor/product 类） |
| 数据 | kb-5.0.0 `kb_cve_product`（NVD CPE 约束），train 1,066,892 边 / test 31,130 CVE |
| 模型 | OneVsRest SGD(log_loss)，TF-IDF 同上 |
| 性能 | P@5 0.9085 / P@10 0.9425 / MRR 0.864（随机 P@5=0.025，36 倍提升） |
| 对 SiteLens 价值 | 类名与引擎技术目录匹配 35/200；新 CVE 免查 CPE 即得技术先验 |
| 局限 | 类宇宙限 top-200 高频产品；CPE 命名与引擎技术名非一一对应 |

### 标签语义（两模型通用）

- source=nvd，source_type=supervised / weak(relation)，label_type 与 label_confidence
  见各自 metrics 的 label_provenance；样本级字段齐全
  （source/source_type/label_type/label_confidence/sample_id/data_version）。
- 严重度标签=NVD base severity（高可信）；产品标签=CPE 约束（中等可信，非攻击标签）。

## EXP-1004 对比系统（2026-09-28，预注册 a062d10）

| 系统 | 说明 | 资源（本机实测） |
|---|---|---|
| 基线（自有） | 上述两模型 + P6 四基线，在同一抽样评测行重算 | MB 级，1500 行批量秒级 |
| 零样本代表 | Qwen3-0.6B-Instruct-Q8_0（kev 路线底座）+ 决策提示词 + GBNF 读出头，llama.cpp b11222 CPU×24 | 峰值 RSS 13.1GB（8 槽×4K ctx 配置） |
| 决策模型正主 | Jev-Style-0.8B-Decision-v3（chaoliangUNSW，Apache-2.0，Qwen3.5-0.8B 决策微调），官方 torch 参考实现 + 原生 decide() 接口（选项→校准概率，分组温度校准内置） | 进程 RSS ~3.9GB（bf16）；GGUF Q4_K_M 0.53GB 为轻量替代形态 |

对比结果与闸门判定见 `docs/5.0-总报告.md`（数字以 `data/ml/bench/results/` 为准）。

## 明确不采用的东西

- Severity 不作 Label（项目红线）；本卡中的严重度是任务目标，不是排序标签。
- LLM/生成式模型不作 5.0 核心；EXP-1004 是用户授权下的一次性边界实验。
- 未知/未命中/缺失永远不充当负类。

## 更新记录

### 2026-09-28 过拟合诊断轮

用户质疑过拟合 → 诊断实证部分成立，两模型重训持久化：

- **EXP-1006-severity-v2-model**：alpha 1e-6→1e-5（val 选型），严格三段切分
  （train<2022/val 22-23/test≥2024）下 test acc 0.5221 / macro-F1 0.3941，
  对比同协议原配方 0.5041/0.3768；相邻带 94.4% 维持。**该版本此后已退居
  前版本**（名册「前版本」保留其追溯 id），现役见下条。
- **EXP-1005-cwe-model 重训**：加 class_weight=balanced，acc
  0.7586→0.7709、macro-F1 0.5794→0.5899（即现役 `cwe-type`）。
- 诊断留档：metrics/DIAG-overfit-and-cwe.json（alpha 扫描 + 学习曲线）。

### 2026-09-29 sev-prior 部署升级轮（现役口径）

- **现役 = `sev-prior` v3.1（EXP-1017-sev-prior-v3.1，分数输出版）**，取代 v2
  档位配方成为产品主呈现：CVE 描述 → CVSS 分数回归（0-10），呈现【分数 ± MAE】。
  部署版（148k 全量 + Huber + 双种子集成）test **MAE 1.07**、相邻带容忍
  acc **0.9654**（v3 为 0.9549）。
- **v2.2 档位集成版（EXP-1009，acc 0.6024）降为辅助档位标注**；两版本口径不同，
  数字不可直接比较（口径注记见 `ml/model_registry.json`）。
- 完整训练参数、数据切分与发布资产对拍见 `docs/release-5.0.0/TRAINING_PARAMS.md`。
  👉 旧稿「v2 新现役 / acc 0.5221」是 09-28 诊断轮的历史结论，已不适用。

### 2026-10-30 阶段 1：`sev-linear` 线性严重度上线（默认后端）

- **新增公开模型 `sev-linear`（线性回归）**：CVE 描述 →
  CVSS 0-10 分（TF-IDF 一元词 + ridge，单输出）；资产 0.7MB，训练/导出脚本
  `ml/train_sev_linear.py`（纯 numpy，CPU ~25 秒可复训），推理口径与 Go 侧
  `internal/ml/ml.go` 逐位一致。
- **质量口径**（与 sev-prior 不同，不可直接混用；2026-10-30 NVD 刷新后复训）：
  - 时间切分 pub<2024 训练（220,744 条）/ pub≥2024 抽 20,000 留出，留出 **MAE 1.1802**
    （RMSE 1.4820 / p95 2.933 / 落在 ±1 内 50.2%）；
  - 同一 600 条 NVD 抽样对照（A/B 快照）：sev-prior fp32 双种子 **1.079**、
    sev-linear **1.189**（+0.11 分，10%）；手写 CVSS 3.1 规则 1.427（更差，不作替代）；
  - Go 侧 120 条夹具门禁实测 **MAE 1.0858 / max 5.24**（阈值 1.30）。
  - 口径：NVD 镜像 280 字符截断描述（生产路径同口径），与 sev-prior 的 1.07
    （全长描述、148k、双种子）不是同一评测集，仅作量级对照。
- **定位变更**：严重度默认后端改为「NVD/情报行查表（误差 0）→ sev-linear 兜底」；
  sev-prior ONNX 降为**可选高级包**（`ml.sev_onnx` 默认关，需 `-tags onnx` 构建 +
  onnxruntime + 模型随包）。决策依据见
  `docs/release-5.2.0/ML-算法替代A-B实验-5.2.0.md` 与
  `docs/release-5.2.0/阶段1-线性severity与ONNX下线-5.2.0.md`。
- **数据事实**：现有引擎输入里 tpl_intel 99.94%、vuln_kb 99.31% 的 CVE 在 NVD 已有分数；
  模型价值区间只剩「本地 NVD 快照未同步到的新 CVE」这一时间窗。

### 2026-10-30 阶段 2：模型降为查表兜底（`mlEnrich` / `mlPrior`）

- **产品/CWE/严重度统一查表优先**：`tech_top5` 优先 NVD CPE（`prods[].vp`）与
  finding 自带 `product`；`cwe_type` 优先 NVD `cwes`；`sev_score` 优先 CVSS 分；
  只有查不到时才惰性加载模型资产（查表全覆盖时不读 94MB cve-tech）。
  预测契约新增 `tech_source`（nvd/intel/model）与 `cwe_source`（nvd/model），
  查表结果的 `prob` 固定为 1（非概率）。
- **前置通道改为指纹先验**：`res.Technologies`（指纹确认的技术名）→ 产品映射表
  （8 个可行动产品键）→ check 提权 + 扩展集增量纳入；指纹无命中才回退 cve-tech
  文本模型。指纹通道不依赖模型资产、不读正文，避免被泛化词带偏。
- **模型定位**：cve-tech / cwe-type 从「全量预测」降为「查表盲区兜底」，
  资产不变；`ml.predict` 仍是总闸。落地与验收见
  `docs/release-5.2.0/阶段2-查表优先与指纹先验-5.2.0.md`。
