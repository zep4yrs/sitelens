# SiteLens 企业版（6.x）技术方案（设计稿，**未实现**）

> **状态**：设计稿 v0.1（2026-11-01）。本文只做**技术设计与迁移路线**，不对应任何已合入代码；
> 6.x 企业化能力（G16/G17/G20/G22）按《竞品对标与追赶方案》Phase 3–4 推进，5.2.x 明确不做。
>
> **现状基线（5.2.x，可作迁移起点）**：
> - 存储：文件型 `store.Store`——`history.json`（默认上限 500 条）+ 超限裁剪归档
>   `history.archive.jsonl`（JSON Lines、0600）+ 事实图独立文件；job 状态在内存 `JobManager`，
>   重启不保留；已有 `migrate-pg`（`cmd/sitelens/migrate_pg.go`）把 Python 时代 PG 历史迁入
>   文件库的先例，`go.mod` 已含 `github.com/jackc/pgx/v5`（仅迁移工具使用）。
> - 鉴权：单一 `X-Token`（`web.api_token` / `SLENS_API_TOKEN`）+ 目标白名单 `scan.allow_hosts`；
>   无用户/角色/租户概念。
> - 执行：单机单进程（`max_concurrent` 信号量）、cron 定时批量在本机内存调度 + 状态文件；
>   无队列、无 lease、无跨节点协调。
> - 桌面：Windows x64 Wails 单机壳 + 内嵌引擎；CLI/TUI 独立 npm 线（5 平台引擎包）。
>
> **设计原则**：默认部署仍是「单机单进程、零外部依赖」；企业能力全部**按需启用**，不开启时
> 行为与 5.2.x 等价（additive），避免把自托管小用户拖进数据库/集群运维。

## 1. 目标与非目标

| 类别 | 内容 |
|---|---|
| 6.x 目标 | ① 可选 SQL 后端（SQLite 单机 / PostgreSQL 企业）② RBAC + 多租户隔离 ③ 企业 SSO（OIDC/SAML，设计先行、实现分期）④ 分布式 worker（队列/lease/死信）⑤ 可审计、可备份、可回滚的升级迁移路径 |
| 非目标（6.x 不做） | 不做 SaaS 多区域托管；不做代码托管平台级 CI 插件市场合规认证；不做内核/协议级沙箱；不做计费系统（只预留 entitlement 接口） |
| 兼容承诺 | 现有配置文件字段只增不减；不启用企业能力时 `sitelens serve` 行为与 5.2.x 一致；历史数据可双向迁移（文件 ↔ SQL）；CLI 参数保持兼容 |

## 2. 数据库后端：`SQLStore` 抽象与 schema

### 2.1 抽象边界（先抽象，后实现）

保持 `internal/store` 现有导出面（`Store` 的方法签名）不被破坏，新增可替换实现：

```go
// internal/store 新增（示意）：不改变现有文件实现的行为。
type Backend interface {
    Save(rec ScanRecord) (int64, error)        // 保留：调用方不感知落盘介质
    Get(id int64) (*ScanRecord, bool)
    List(offset, limit int) ([]*ScanRecord, int)
    Delete(id int64) error
    Import(rec ScanRecord) (int64, error)      // 迁移/幂等导入（已有语义）
    Close() error
}
// FileBackend = 现有实现（默认）；SQLBackend = 6.x 新增，二选一由 config 决定：
//   storage.backend: file | sqlite | postgres   （默认 file）
```

- **读路径**：`Ticket`/HTTP handler 只依赖接口；SQL 后端必须保持 JSON 结构兼容（`Result` 原样存
  JSONB/TEXT，不拆表），避免把引擎结果模型绑死在关系 schema 上。
- **写路径**：`Save` 内做「记录 + 图 + 索引」事务；文件后端保持现有「图独立文件 + 归档」语义。
- **迁移期双写不做**：不做运行时双写（一致性风险高），采用「停机迁移 + 只读校验」路线（§5）。

### 2.2 Schema（PostgreSQL 13+ / SQLite 3.35+，语义一致）

| 表 | 关键列 | 说明 |
|---|---|---|
| `schema_migrations` | `version BIGINT PK, applied_at, checksum` | 迁移版本（单向递增，禁止改历史脚本） |
| `scans` | `id BIGINT PK, tenant_id, url, host, status, severity_max, tech_count, vuln_count, duration_ms, scanned_at, options JSONB, result JSONB, partial BOOL` | 主记录；`result` 保留完整 `engine.Result`（JSON） |
| `scan_findings` | `scan_id FK, fingerprint, category, severity, title, url, evidence JSONB` | 供跨扫描查询/台账；由 `result` 派生（可重建） |
| `scan_technologies` | `scan_id FK, name, version, confidence, source` | 指纹（CP-11 置信度可查询） |
| `scan_pages` | `scan_id FK, url, status, size, depth` | 页面清单（可选，量大时可关） |
| `graphs` | `scan_id FK, format, payload JSONB/BLOB, sha256` | 事实图（替代文件式 graph 目录） |
| `triage_entries` | `scan_id, fingerprint PK(scan_id,fingerprint)`, `verdict, note, actor, updated_at` | CP-08 复核结论 |
| `whitelist` | `tenant_id, host, rule_id, reason, actor, created_at` | CP-08 白名单 |
| `schedules` | `id, tenant_id, cron, entries JSONB, enabled, tag, next_run_at, last_run_at` | BT-03 定时任务 |
| `jobs` | `id TEXT PK, tenant_id, kind, status, progress, message, payload JSONB, created_at, updated_at` | 持久化 job（替代内存 `JobManager`） |
| `tasks` | `id BIGSERIAL, tenant_id, job_id, kind, payload JSONB, state, attempts, available_at` | 分布式队列（§4） |
| `task_leases` | `task_id PK, worker_id, expires_at, heartbeat_at` | lease（§4） |
| `task_dead_letters` | `id, task_id, reason, payload JSONB, failed_at` | 死信（§4） |
| `users` / `roles` / `role_bindings` | `id, tenant_id, subject, role, scopes, created_at` | RBAC（§3） |
| `audit_log` | `id, tenant_id, actor, action, target, detail JSONB, at` | 不可变审计（追加写） |
| `intel_snapshots` | `version, channel, digest, published_at, payload_ref` | 情报/模板快照元数据（§生态文档） |

**约束**：所有业务表带 `tenant_id`（单租户=固定 `default`），唯一键均含 `tenant_id`；`audit_log`
只 INSERT；大字段（`result`/`payload`）在 PostgreSQL 用 `JSONB`、SQLite 用 `TEXT` 并由应用层校验。

### 2.3 索引与容量

`scans(tenant_id, scanned_at DESC)`、`scans(tenant_id, host)`、`scan_findings(tenant_id, fingerprint)`、
`tasks(state, available_at)`、`jobs(tenant_id, created_at DESC)`；归档策略：`scans` 超期/超量
按租户裁剪 → 归档表 `scans_archive` 或对象存储（复用现有 JSONL 归档格式，可回灌）。

## 3. RBAC 与多租户

### 3.1 角色矩阵（最小可用集）

| 角色 | 扫描/批量/定时 | 查看历史/证据 | 复核/白名单 | 配置（allow_hosts/限速/webhook） | 租户/用户管理 | 审计日志 |
|---|---|---|---|---|---|---|
| `owner`（租户管理员） | ✅ | ✅ | ✅ | ✅ | ✅（本租户） | ✅（本租户） |
| `operator`（安全工程师） | ✅ | ✅ | ✅ | 只读 | ❌ | 只读 |
| `viewer`（只读） | ❌ | ✅（只读） | ❌ | ❌ | ❌ | ❌ |
| `auditor`（审计员） | ❌ | ✅ | 只读 | 只读 | ❌ | ✅（本租户） |
| `platform_admin`（平台运维，仅企业部署） | ❌（默认不落业务数据） | 运维视图 | ❌ | 全局基础设施配置 | 租户创建/配额 | 全局审计（不含证据正文） |

- 权限点用 `resource:action`（如 `scan:create`、`history:read`、`triage:write`、
  `config:write`、`tenant:manage`、`audit:read`）；角色=权限点集合，可自定义但不可越权。
- 鉴权入口：HTTP middleware 解析 token → `(tenant_id, subject, roles)` → 权限判定；
  CLI 走本地 `--token`/环境变量，桌面壳走本地回环 token。
- **Token 设计**：企业部署签发签名 token（JWT/Ed25519，短时效 + 刷新），claim 含
  `tenant_id/subject/roles/scopes/exp`；单机模式保持现有 `X-Token` 静态值兼容（升级不破坏脚本）。
- **多租户隔离**：所有 SQL 查询强制 `tenant_id` 条件（store 层注入，不依赖 handler 自觉）；
  文件后端暂不支持多租户（企业模式必须 SQL）；导出/报告文件名带租户前缀；图/附件路径按
  `tenant/<id>/` 隔离；跨租户访问返回 404（不泄露存在性）。
- 审计事件：登录/授权变更/配置变更/扫描创建与取消/复核/白名单/导出/情报更新，写 `audit_log`。

### 3.2 与现状差异

5.2.x 的 `X-Token` + `allow_hosts` 保留为「单租户/单机」路径；企业模式启用后：
`allow_hosts` 变为租户级授权配置（平台级硬闸门 SSRF/gov.cn 仍不可关闭），`api_token` 仅作为
bootstrap 管理 token，不再作为业务鉴权。

## 4. 分布式 worker（队列 / lease / 死信）

### 4.1 模型

```
API/调度器（无状态，可多副本）
  └─ 写 tasks（kind=scan|batch-item|netsec|audit、payload、tenant_id、available_at）
       └─ worker 拉取（SELECT ... FOR UPDATE SKIP LOCKED，PG）
            ├─ 获取 lease（task_id, worker_id, expires_at=now+TTL，TTL 默认 90s）
            ├─ 心跳续租（每 TTL/3），执行引擎扫描（复用现有 engine.Scan）
            ├─ 成功：写 scans/jobs + 删除 tasks/lease（事务）
            ├─ 失败：attempts+1，指数退避（30s/2m/10m），超上限 → dead_letters
            └─ 取消：job 取消标记 → worker 轮询检查 → 释放 lease 并置 cancelled
```

- **幂等**：`task.id + tenant_id` 为幂等键；落库使用「scan 记录 upsert + 图覆盖」策略，
  重复执行只覆盖同一次任务的结果，不产生重复历史条目（或按 `dedupe_key` 去重）。
- **lease 语义**：租约过期视为 worker 死亡，任务回队列；心跳失败立即退避；禁止时钟敏感逻辑
  （以 DB `now()` 为准）。SQLite 单机模式可用「进程内 lease + 文件锁」，但**不支持多 worker**。
- **调度**：cron 定时任务由中央调度器（单实例选主：PG advisory lock）转为 tasks；桌面/单机模式
  维持进程内 cron（5.2.x 既有行为）。
- **安全**：worker 不信任 payload 中的目标地址——执行前仍走 `target.Validate` + `allow_hosts`
  （租户级），SSRF/gov.cn 硬闸门在 worker 侧再校验一次；worker 只接受签名任务（API 签名）。
- **可观测**：队列深度、lease 超时数、死信数、worker 心跳、任务时延；指标走 `GET /api/stats`
  （企业字段 additive）。
- **部署形态**：单机（file/sqlite，无队列）→ 单机 + 队列（sqlite 单 worker）→ 企业（PG + N
  workers + 可选对象存储）→ HA（PG 主备 + 多 API 副本 + 独立调度器）。air-gapped 环境：
  全离线包 + 本地镜像，不依赖外部队列服务。

## 5. 部署拓扑与迁移路线

### 5.1 拓扑

| 形态 | 组件 | 适用 |
|---|---|---|
| T0 单机（默认，5.2.x 现状） | 桌面安装包 / 单进程 `sitelens serve` | 个人、单团队、离线 |
| T1 单机 + SQLite | 同上 + `storage.backend=sqlite` | 需要持久化 job/多用户轻量 RBAC |
| T2 企业单节点 | `sitelens serve`（PostgreSQL）+ N 个 worker（同机/容器） | 中型团队、多租户 |
| T3 企业 HA | 2×API（无状态）+ M×worker + PG 主备 + 对象存储（报告/图） | 大客户、SLA 场景 |
| 桌面混合 | 桌面壳可连接企业 API（`server.url` + token），本地引擎仅离线用 | 顾问/分散团队 |

### 5.2 迁移路线（版本分期，均为可选启用）

| 版本 | 能力 | 迁移动作 | 回退 |
|---|---|---|---|
| 6.0 | `Backend` 抽象 + SQLite 后端 + jobs 持久化（schema v1） | `sitelens migrate --to sqlite` 从 JSON 导入；保留文件库只读 | 切回 `storage.backend=file`，数据仍在 |
| 6.1 | PostgreSQL 后端 + RBAC + 租户 + audit_log | `migrate --to postgres`（复用 `migrate-pg` 的连接/幂等模式）+ 建租户/角色 | 导出 JSON 回文件库（`Export` 工具） |
| 6.2 | SSO（OIDC 先行，SAML 同期设计） | IdP 配置 + claim→role 映射；保留本地账号 break-glass | 关闭 SSO 开关，恢复本地 token |
| 6.3 | 分布式 worker + 队列/lease/死信 + 中央调度 | 开 `queue.enabled=true`，worker 注册；把 cron 任务迁到调度器 | 关队列 → 回单机进程内调度 |
| 6.x 后续 | 对象存储、配额/计费 entitlement、SIEM 导出 | 增量能力，不阻塞 | — |

**迁移可靠性要求**：迁移工具必须**幂等、可重复执行、保留原始 id**；迁移前自动备份（文件库
整目录 / PG `pg_dump`）；提供 `--dry-run` 与 `--verify`（条数/摘要/抽查证据一致性）；迁移失败
不得破坏源数据；升级前提示备份，回退只允许「回退到迁移前备份」而不做反向写。

### 5.3 兼容与升级

- 配置：`storage.backend`/`storage.dsn`/`queue.*`/`auth.*` 只增不改；未设置=旧行为。
- API：现有 `/api/*` 契约不变；企业字段（tenant/role）在单机模式返回空值/忽略。
- 数据：SQL schema 版本化，启动时自动迁移（仅向前）；大版本升级前强制备份检查。

## 6. SSO 设计（**6.2 设计稿，暂不实现**）

| 项 | 设计 |
|---|---|
| 协议 | OIDC（Authorization Code + PKCE）为首选；SAML 2.0（SP-initiated）为兼容大企业 IdP 的次选 |
| 流程 | 浏览器/桌面壳打开系统浏览器 → IdP 登录 → 回调 `localhost`/内网回调地址 → 换 code → 校验 id_token（iss/aud/exp/nonce/signature，JWKS 缓存+轮换）→ 建立会话（HttpOnly Cookie 或短期 bearer） |
| 会话 | 服务端会话（PG `sessions` 表或签名 cookie），默认 8h 空闲过期；refresh 可选；登出支持 RP-initiated logout |
| 映射 | `groups`/`roles` claim → 平台角色（配置化正则/映射表），默认最小权限 `viewer`；首次登录 JIT provisioning，可关闭改由 SCIM 预置 |
| 多租户 | 按 IdP issuer/tenant claim 路由租户；跨租户 admin 不默认授予 |
| 安全 | state/nonce/PKCE 必须；HTTPS 强制；JWT 验签用 IdP 公钥；重放防护；SSO 关闭时保留本地 break-glass 管理账号 |
| 桌面壳 | 壳不内嵌 IdP 页面（避免 WebView 内嵌登录被判风险）：系统浏览器 + 回环回调；token 只存内存/系统凭据库 |
| 明确不做 | 不实现自有 IdP、不做密码同步、不做 LDAP 直接绑定（用 IdP 代理） |

**分期**：6.2 先落 OIDC（覆盖 Entra ID/Okta/Authing/Keycloak），SAML 视客户需求排期；两者共用
`authn.Provider` 接口与角色映射层。

## 7. 风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 文件→SQL 迁移丢数据/重复 id | 历史不可信 | 幂等迁移 + `--verify` + 迁移前备份 + 保留源库只读；先小客户灰度 |
| 多租户隔离漏条件 | **跨租户数据泄露（最高危）** | store 层强制注入 tenant 条件 + 集成测试矩阵 + 代码评审红灯；单机模式不启用 |
| SQL schema 演进破坏旧版本 | 回退困难 | 只向前迁移 + 大版本前备份；文档记录 schema 版本 |
| 分布式 lease 脑裂/双跑 | 重复扫描、配额/限速异常 | DB 时钟 + `FOR UPDATE SKIP LOCKED` + 幂等落库；worker 心跳与超时指标告警 |
| worker 侧 SSRF/白名单绕过 | 打内网 | worker 执行前二次校验（与 API 同源函数）+ 单测覆盖 |
| SSO 配置复杂/锁死管理员 | 无法登录 | break-glass 本地管理员 + 配置校验器 + 文档化回退 |
| 企业功能拖慢单机启动/包体 | 个人用户反感 | 企业能力按需启用、默认关闭；SQLite/PG 仅在企业构建或运行时按需加载 |
| 审计日志含敏感信息 | 合规风险 | 审计只记动作/对象/结果，不落证据正文与凭据；脱敏规则复用现有 |
| 无加密静态存储（当前文件/未来 DB） | 数据泄露 | 6.x 评估 PG TDE/磁盘加密 + 敏感字段脱敏；文档明确边界 |

## 8. 验收口径（企业能力）

1. **DB**：SQLite/PG 后端跑通同一套 store 测试；`migrate --dry-run/--verify` 条数与摘要一致；
   回退切 file 后历史可读。
2. **RBAC/租户**：3 角色 × 3 租户矩阵用例全绿；跨租户访问 404；审计日志覆盖 8 类动作。
3. **SSO**：OIDC 用 Keycloak 测试 IdP 完成登录/登出/过期/token 校验；SAML 仅设计评审。
4. **分布式**：2 worker + 100 任务故障注入（kill worker / lease 过期 / 重复投递）无重复结果、
   无任务丢失；死信可查可重放。
5. **兼容**：不启用企业配置时 `go test ./...` 全绿、行为与 5.2.x 一致；旧配置升级不报错。
