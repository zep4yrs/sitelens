# 网络层 / 登录爆破 / 源码审计 P0（5.2.0）

本批 5.2 只做「低风险、可独立验收」的增量；其余能力列入 5.3（见《新功能路线图》）。

## NS-01 网络层 P0

### 现状
`internal/netsec` 仅：TLS 证书过期/临期/自签名/旧协议 + SPF/DMARC/MX 存在性。

### 新增检测
| 检测 | 方法 | 严重度 |
|---|---|---|
| 证书 hostname/SAN 不匹配 | `cert.VerifyHostname(host)` + SAN 列表比对 | high |
| 证书链不完整/无法验证 | 采集 PeerCertificates 逐级校验 Issuer/Subject | medium |
| 签名算法过弱（SHA-1/MD5） | `cert.SignatureAlgorithm` | medium |
| RSA 密钥 < 2048 | `cert.PublicKey` 类型断言 | medium |
| DMARC 策略为 none / 缺失 rua | TXT `_dmarc.<domain>` 解析 `p=`/`rua=` | low/medium |
| SPF 查找数 >10 或语法异常 | TXT 解析 `include`/`redirect` 计数 | low |
| CAA 缺失 | TXT `CAA`（或 `issue`）查询 | low |
| HSTS 缺失/过短 | 一次 HTTP GET 响应头 `Strict-Transport-Security` | low |
| HTTP→HTTPS 未跳转 | HTTP 请求最终 URL/scheme | medium |

### 约束
- 只增加 **1 次 HTTP GET**（复用预检响应更佳）+ 少量 TXT 查询；不新增端口扫描。
- 既有 TLS/DNS 发现语义不变（旧 finding 的 check/title/severity 保持）。
- 全部只读，不发送 payload。

### 验收
- 单测覆盖：SAN 不匹配、SHA-1、RSA-1024、DMARC none、CAA 缺失、HSTS 缺失；
- 一次检测的额外网络请求数 ≤ 2（HTTP 1 + 可选 TXT 若干，均为 DNS）。

## LB-01 登录爆破安全护栏

### 现状
form/basic/JSON 三模式、隐藏字段、验证码（外部 ddddocr）、MaxTries 总量上限、全局限速；**无锁号保护、CSRF 不重取、成功判定无证据**。

### 新增
| 能力 | 行为 |
|---|---|
| 锁号保护 | 响应含「锁定/冻结/locked/too many attempts」或 429/403 → **立即停止**该目标；连续失败 N 次（默认 5）→ 指数退避或停止（可配） |
| 每账号上限 | 同一用户名最多尝试 M 次（默认 3），避免锁死真实账号 |
| CSRF/hidden 重取 | 每次 POST 前重新 GET 登录页，刷新 hidden/CSRF token；一次性 token 场景不误判 |
| 成功证据 | 记录响应差异摘要 + Set-Cookie + 跳转 URL + 可复制 curl；命中判定仍走「失败基线 + 响应差异」 |
| 授权确认 | UI 侧保持现有说明；新增服务端目标白名单校验（配置 `loginbrute.allow_hosts`，空 = 不限制但日志警告） |

### 约束
- 不增加验证码破解能力（法律风险）；OCR 仍为可选外部组件。
- 总量上限 `MaxTries` 与全局限速继续生效，不得被新逻辑绕过。

### 验收
- 锁定页/429 → 停止并给出原因，不继续发请求；
- 一次性 CSRF token 靶站命中率不下降；
- 成功证据含 curl 与 Set-Cookie；`MaxTries` 上限仍生效。

## AU-01 源码审计 SARIF 导出

### 现状
17 条正则规则（PY/JS/PHP/GEN）+ AST（Py/JS/PHP/Java/Go）+ Python TAINT-lite + 目录/压缩包上传 + Monaco 预览；仅 JSON 报告。

### 新增
- SARIF 2.1.0 导出：`version/runs[].tool.driver.rules[]`、`results[]`（ruleId/level/message/locations[physicalLocation.artifactLocation.uri + region.startLine]）、`partialFingerprints`（ruleId+file+line 的稳定哈希）。
- CLI：`sitelens audit <dir> --sarif out.sarif`；API：`POST /api/audit` 响应含 `sarif` 或 `GET /api/audit/{id}/sarif`（按现有审计实现方式定）。
- 规则元数据：ruleId → name/shortDescription/helpUri（无则省略）。
- 既有 JSON 报告键位不变（additive）。

### 验收
- SARIF 通过 schema 校验；GitHub code scanning 可解析；
- 同一输入两次导出 `partialFingerprints` 稳定；
- 既有 JSON 报告逐字节不变（除新增可选字段）。

## 风险
- NS-01 的 HTTP GET 可能触发 WAF：复用预检/只读、单次、UA 可配；
- LB-01 锁号保护可能降低命中率：默认「停止」优先于「继续打」，宁少不锁号；
- AU-01 只做导出，不改规则/基线（5.3 再做）。
