# 扫描前轻量预检与建议卡（5.2.0）

## 1. 背景与目标

用户输入 URL 后、点「开始扫描」前对目标一无所知，只能凭感觉选档位；选错（对 WAF 站用激进档、对静态站用完整档）既浪费请求又容易漏报。本功能在输入完成后发 **1 次只读轻量预检**，给出目标摘要与扫描建议，由用户一键应用或忽略。

## 2. 结论与取舍

**预检必须是「扫描首页请求的前置复用」**，否则用户不扫时就是白打请求。

| 方案 | 额外请求 | 扫描前可决策 | 结论 |
|---|---|---|---|
| 纯预检（不复用） | 输入 +1，扫描再 +1 | 能 | ❌ 浪费 |
| **预检 + 首页复用（本方案）** | 输入 +1；扫描复用 → 总请求不变 | 能 | ✅ |
| 预检作为扫描第 0 阶段 | 0 | 不能（已在扫） | 备选 |

## 3. 预检规格

- **请求**：用户输入的 URL 本身；`GetFollow` ≤3 跳；与扫描同一 `httpx.Client`（尊重 browser_ua、认证 Cookie、per-host 限速）；`target.Validate` SSRF 校验前置；5s 超时；正文截断 256KB。
- **提取**：status / final_url / title / server / content_type / 关键响应头（cf-ray、x-sucuri、via、x-powered-by 等）/ WAF 判定（`Resp.Blocked/BlockReason`）/ 响应耗时 / 技术指纹（`sitelens.Extract`）/ 正文（供复用）。
- **不做**：robots（多 1 请求）、TLS 证书详情、安全头评分（扫描阶段已有）。

## 4. 复用链路

- `POST /api/preflight` → `{preflight_id, ...展示字段}`；服务端内存缓存：`map[preflight_id]` + `map[归一化URL]`，TTL 120s、上限 32、同 URL 30s 去重、in-flight 去重。
- `POST /api/scan` 可选 `preflight_id`：命中且 URL/Cookie 哈希一致、年龄 <120s → `Options.Preflight`；否则忽略正常抓取。
- 引擎首页采集命中则用缓存响应构造 `httpx.Response`（含 Blocked 标记），跳过 `client.GetFollow`。
- `Result.Diagnostics` 增 `preflight_reused`（additive）；覆盖度卡显示「含预检 1 次（已复用）」，不重复计请求。
- 预检不写历史/报告、不入库；跨主机重定向只提示不复用。

## 5. 建议规则

| 信号 | 推荐 | 理由 |
|---|---|---|
| WAF/限流（429/503/challenge/CF 头） | polite 或低 `rate_max_rps`，降强度 | 激进档会被拦导致漏报 |
| CMS/框架（WordPress/Drupal/ThinkPHP/Spring…） | 标准档 + 对应专项 check，保留 DAST | 专项检测命中率更高 |
| 静态/无框架、无参数 | 快速档，关 DAST/目录 | 完整档只会多打请求 |
| 401/403 | 提示补认证 Cookie / 开浏览器 UA | 目标要求认证或按 UA 拦截 |
| 响应慢（>2s） | polite/低速率 | 高速率可能拖垮或触发限流 |
| 跳转到其他主机 | 提示确认范围、按最终主机重填 | 确认授权范围 |
| 预检失败 | 显示原因，仍允许扫描 | 无法给建议但不阻断 |

建议卡只展示前 3 条理由；「应用建议」只写 scope/verify/strength，不自动开始扫描。

## 6. 接口

**POST /api/preflight**
```json
// req
{ "url": "https://example.com", "browser_ua": false, "auth_cookie": "" }
// resp 200
{
  "preflight_id": "pf_xxx", "status": 200, "final_url": "...", "title": "...",
  "server": "nginx", "waf": { "blocked": false, "reason": "" },
  "tech": ["WordPress", "nginx"], "response_ms": 123, "content_type": "text/html",
  "suggestion": { "strength": "std", "verify": ["afp","dir","ws","dast"],
    "reasons": ["..."], "warnings": ["..."] },
  "expires_in": 120
}
```
错误：400（URL 非法/SSRF 拒绝/配置关闭）、429（限流）、502（目标不可达，带原因）。

**POST /api/scan** 增可选 `preflight_id`（不传则行为不变）。

## 7. 开关与限流

- `scan.preflight: true|false`（默认 true，服务端总闸）；关闭后 `/api/preflight` 返回 400，前端隐藏开关。
- 前端「输入后自动预检（1 次只读请求）」默认开，localStorage 记忆。
- 批量/历史重扫不自动预检（避免批量放大请求）。

## 8. 失败与边界

- 预检超时/失败：显示原因 + 重试；不阻断扫描。
- 预检被 WAF 拦：建议卡强提示；扫描复用时按 WAF 终止逻辑处理。
- 缓存过期/URL 不一致/Cookie 不一致：静默回退正常抓取。
- 预检期间用户改 URL：取消上一个请求，只认最后一次。
- 预检不跟随跨主机的后续请求；3 跳上限。

## 9. 验收

- 预检 ≤1 请求/URL/30s；关闭开关后 0 预检请求。
- 预检后开始扫描：目标侧首页请求数 = **1**（非 2）。
- 预检失败不阻断；WAF 目标建议正确；建议不自动改选项。
- `diagnostics.preflight_reused` 正确；历史/导出格式不变。
- Go/JS 单测 + 本地 4 页靶站 E2E；CI 全绿。
