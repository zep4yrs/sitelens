# 效率轮（5.2 第三轮）：WAF-aware 自适应限速 + 请求去重 + 诊断账本

> 背景：第二轮把 CPU 成本压掉了（指纹 4 页 6ms、模板索引热路径 6ms/次），但实测一次
> deep+DAST 扫描的墙钟里 **≈99.6% 是限速睡眠**（本地 4 页带表单站：775 请求，
> `rate_interval_ms=400` 墙钟 155s，降到 1ms 后仅 0.6s）。于是本轮目标从「算得快」
> 转向「**单位时间产出更多、同时不伤害被扫目标**」。

## 1. 设计红线（用户前提）

- **不影响被扫描机器**：默认平均 **≤8 req/s/主机**（代码级绝对上限 10 req/s，任何配置
  无法突破）、并发不增加、目标响应变慢自动退避、检测到 WAF/限流立即锁定低速。
- **宁少报不误报**：被 WAF/限流拦截的响应不参与任何判定；payload 请求绝不复用；
  去重只做语义安全的只读复用。
- **SSRF 语义零改动**：一次解析 → 全量校验 → 只拨已校验 IP 的链路不变。

## 2. 交付一：httpx 限速层重做（WAF-aware 自适应）

旧实现缺陷：`wait()` 先把 `last=now` 再 sleep，N 个并发调用者会各自睡一个 interval
后齐发 → 实际速率 = N/interval（400ms 配置实际跑出 ~5 rps、峰值 6，而不是 2.5 rps）。

新实现：

| 能力 | 行为 |
|---|---|
| per-host 共享令牌桶 | 按归一化 host:port 全进程共享（引擎多 Client 不再叠加翻倍），容量 1 不攒突发；空闲 5min TTL 回收 |
| polite 档（`rate_mode: polite`） | 与旧配置语义一致：固定 `rate_interval_ms`，0=不限速、1ms=1ms；**修正 pairing 缺陷后** 400ms 才是真正的 2.5 rps |
| balanced 档（默认） | 400ms 起步，连续 5 次干净成功后间隔减半，**默认硬下限 125ms（平均 ≤8 req/s/主机，`rate_max_rps: 8`）**；代码级绝对上限 10 req/s（100ms，配置无法突破）；间隔高于下限时 ±20% 抖动（固定节奏易被 WAF 指纹化），下限处不抖动以保证目标速率 |
| 保守档 | `rate_max_rps: 5` → 硬下限 200ms（平均 ≤5 req/s/主机）；调低只会更保守 |
| RTT 反馈 | RTT EWMA 绝对上升（≥20ms 且连续两次）自动翻倍退避（上限 2s）——目标变慢就不再加速 |
| WAF/限流检测 | 429/503、`Retry-After`、WAF 特征头（cf-ray/x-sucuri/x-akamai/server 含 cloudflare/akamai/safedog/yunsuo/waf…）、强挑战页（cf-chl/challenge-platform 等）、同 URL 2xx→403/406 降级；命中即锁定低速（400ms→1s→2s，只增不减），本次扫描不再加速 |
| 拦截标记 | `httpx.Resp.Blocked/BlockReason`；上层据此跳过判定（WAF 错误页会回显 payload，直接判定会产生假阳性） |
| 指标 | `Client.Stats()`：Requests / Interval / AvgRPS / Blocked / Backoffs |

目标侧实测（httptest 目标记录到达时间，2 Client 同 host + 并发调用者）：

| 场景 | 峰值(1s) | 峰值(2s) | 平均 | 最大并发 |
|---|---|---|---|---|
| polite 400ms | 3 | 6 | 2.5 rps | 1 |
| balanced 默认（`rate_max_rps: 8` → 125ms） | 9 | ≤17 | **7.9 rps** | 1 |
| balanced 保守（`rate_max_rps: 5` → 200ms） | 6 | 11 | **5.0 rps** | 1 |
| 旧实现 400ms（pairing 缺陷） | 6 | 12 | ≈5.0 rps | 1 |

> 峰值比平均多 1 是目标侧到达抖动（半开窗口边界/调度）导致；硬口径是**平均 ≤
> `rate_max_rps`**。polite 400ms 从旧实际 5 rps 修正为真实 2.5 rps。

## 3. 交付二：请求去重 / 流式分析 / 诊断账本（engine + dast + crawler）

- **DAST benign 基线复用**：同一 URL+参数集的 benign GET 在 Run baseline / 时间差分
  （timeBlind、cmdInject）/ authz 原值 / 表单空提交之间共享一次真实请求；时间差分
  复用会携带首次真实 RTT，避免把基线测成 0 造成误报。**payload 请求一律不复用。**
- **只读页面复用**：首页/种子/爬取页在单次扫描内复用响应（指纹/被动/安全头/JS 端点
  二次读取不再重抓）；DAST payload、登录、目录探测不入缓存。
- **逐页流式**：crawler 新增 additive `SetPageHook`（默认 nil 行为逐字段等价），
  每抓到一页立即启动该页指纹匹配/被动检查，与限速等待窗口重叠；favicon 整站只取一次；
  结果按页序合并，progress 回调串行。
- **WAF 拦截隔离**：首页被拦直接报错终止；爬取页被拦不进分析集；jsmap 走
  `blockedAwareFetcher`；DAST 被拦响应按「无响应」处理（不算命中）；checks/nuclei
  命中按 blocked URL 过滤。
- **诊断账本（additive）**：`Result.Diagnostics`（JSON `diagnostics`）——总请求数/
  blocked/backoffs/WAF 原因分布/去重命中数/平均 RPS/实际生效间隔/是否流式，以及
  每阶段 `phases[]{phase,requests,blocked,dedup_hits,duration_ms,avg_rps}`。
  既有结果键位不变（只增不改）。

## 4. 同 fixture 实测（4 页带表单/带参；deep+DAST）

| 组 | 请求数 | 墙钟 | findings |
|---|---|---|---|
| 旧实现 af60716（fixture A，独立 worktree 测） | 775 | 155.1s | — |
| **新 balanced 默认（8 req/s）** | 771（-0.5%） | **98.1s（-36.8%）** | 与旧等价（dast 层「复用 vs 不复用」对照测试 + 旧/新逐字节等价用例） |
| 新 balanced 保守档（`rate_max_rps: 5`） | 776（-2.88%） | 156.09s | 2 条，逐字节等价（fixture B） |
| 新 polite 400ms | 776 | 310.01s | 2 条，逐字节等价（fixture B） |

- 默认 8 rps 相对旧实现墙钟 **-36.8%**；目标侧平均 7.9 req/s、峰值 9（1s 窗口）、
  最大并发 1（未增加）。
- 保守档（5 rps）与旧实现同速（旧 pairing 缺陷实际 ≈5 rps），墙钟只快 2.4%，收益来自
  请求数下降；默认改 8 后才有实质提速。
- 请求下降与 `diagnostics.dedup_hits` 对账（fixture B：-23 个）；DAST 复用按 target/
  字段数线性增长。
- balanced 相对 polite 墙钟 **↓约 68%**（8 rps vs 2.5 rps）。
- 如需最保守（严格 5 rps 或更低）：`scan.rate_max_rps: 5`；代码级绝对上限 10 req/s
  （调高超过 10 也无效）。

## 5. 配置

```yaml
scan:
  rate_interval_ms: 400   # polite 档固定间隔（balanced 档作为起步间隔）
  rate_mode: balanced     # balanced=自适应（默认）/ polite=固定间隔（兼容旧行为，最保守）
  rate_max_rps: 8         # balanced 档硬上限（req/s/主机；默认 8，绝对上限 10，调低更保守）
```

未知 `rate_mode` 值按最保守的 `polite` 处理（宁慢不扰民）。

## 6. 回归与遗留

- 测试：httpx 13 个新用例（令牌共享/上限/polite 不夹/WAF 识别/RTT 退避/目标侧峰值）、
  dast 复用五件套（含「复用 vs 不复用 findings 等价」）、engine 流式顺序/blocked 隔离/
  diagnostics、crawler pageHook 默认等价。
- 遗留：
  1. **模板/DAST 未并行**：共享令牌桶下并行不提高 RPS，却会引入 Verified 合并顺序与
     `-race` 风险，收益为 0，故保持串行。
  2. blocked URL 过滤目前覆盖 checks/nuclei；默认关闭的目录/子域模块内部请求未做
     URL 过滤（其响应不进 DAST 判定，影响面小）。
  3. 本机无 CGO/gcc，`-race` 需 CI 复核（本轮新增共享令牌桶/流式并发，CI 已跑）。
  4. 目录探测/登录爆破的限速沿用各自模块节奏（未纳入 host 令牌桶语义变更）。
