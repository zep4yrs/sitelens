## 升级前必读

- **你已有的扫描报告不需要重扫。** 分数和情报判定的问题与目标无关，重扫算出来还是同样的结果——5.2.0 修的是计算方式，不是采集能力。**例外**：响应头注入 / 反序列化两类探测此前实际没生效、afrog 来源模板此前全部未运行，这两类需要**重新扫描**才能看到结果。
- **升级后同一目标的分数会变，部分条目会变高。** 5.1.0 的严重度分数**只会偏低、不会偏高**（实测 29 万条中偏高 0 条），5.2.0 把它修到与官方一致。所以你会看到一部分漏洞的分数**上升**、少数跨过等级线（high ↔ critical）。**这是修正，不是回归**——5.1.0 的分数才是偏低的那个。
- **漏洞情报里「确认受影响」的判定也会变**：5.1.0 对带四段版本号的软件（如 `10.0.19041.1234`、`4.17.3.0`）可能误判为受影响，5.2.0 修准后这类条目会**从「确认受影响」变回「可能受影响」或被排除**。同样是修正。
- **复现命令变了**：表单类漏洞的复现命令此前被渲染成 GET 格式（实际发的是 POST），5.2.0 改成与真实请求一致的 POST 格式。**如果你之前收藏过旧命令，需要重新复制一次。**
- **命令行传参方式没变，但以前有个坑被填了**：`sitelens scan <url> -config <文件>` 里的 `-config` 此前会被静默忽略（配置文件整份不生效且不报错），5.2.0 起两种写法都生效；引擎二进制同样处理。
- **多 path 模板的探测路径变多**：社区模板里约 10~14% 的模板声明了多条候选路径（最多 64 条），此前只探测第一条；5.2.0 起按上限 4 条展开（长尾截断是覆盖率损失，不是误报来源），相应扫描请求量约 +17%~36%。
- **界面有两处会变**：桌面端**不再弹控制台窗口**（启动与退出都不弹）；请求失败时**会给出明确提示**，不再是无声的 "failed to fetch"。若你之前习惯了"失败就当没发生"，5.2.0 会更吵一点——但至少你能知道发生了什么。
- **安装包会变小**：ML 资产从 748.9 MiB 降到约 106 MiB（默认包不再带 ONNX 模型与 onnxruntime，严重度改为「NVD 查表 + 0.7MB 线性回归兜底」，精度代价约 +0.11 分、仍在 ±1.07 呈现带内），详见下面「包体瘦身」一节。最终安装包体积待出包回填。
- **AI 预测字段改为「查表优先」（5.2 阶段 2，API 消费方注意）**：`predictions` 的产品/CWE/严重度优先来自
  NVD CPE / NVD weaknesses / CVSS 分或情报行自带字段，查不到才用模型；新增 `tech_source`
  （nvd/intel/model）与 `cwe_source`（nvd/model），查表结果的 `tech_top5[].prob` 固定为 1（**不是概率**）。
  只有旧记录没有这些来源字段；字段缺失（无先验）语义不变。
- **桌面安装包不再包含命令行工具**。5.2.0 起**引擎与 CLI 拆成两个二进制**：
  - 桌面包里的是**引擎**（只提供 Web 控制台与种子更新），由应用自动拉起；
  - **CLI**（`scan` / `audit` / `update-*` 等命令行能力）**独立分发**，走已有的 npm 线。
  - 如果你之前是在桌面版的安装目录里直接敲 `sitelens.exe scan ...`，**5.2.0 起该命令不再随桌面版提供**——请改用 npm 线（`npm i -g @fengqiao666/sitelens-cli`）。
- **应用内多了「反馈」入口**（顶栏）。诊断包在本机生成，不自动上传。
- **两处配置行为变化**（安全收紧，可能影响旧配置）：
  - `intel.overrides_path` 现在**必须位于数据目录内**（此前可写到任意路径）；旧配置指向目录外时，设置页保存会返回 400，请改回目录内路径；
  - `migrate-pg` 的口令不再接受写在 DSN 里，改从 `SLENS_DB_PASSWORD` 环境变量读取；`sslmode` 默认由 `disable` 改为 `prefer`（本地无 TLS 的 PG 会自动回退，要强制 TLS 请设 `SLENS_DB_SSLMODE=require`）。

## 你能得到什么

### 1. 严重度分数与官方完全对齐

CVSS v3.1 基础分（业界通用的「危险程度温度计」）此前有三处计算错误。5.2.0 全部修正。

用 29 万条真实漏洞（NVD 官方发布的分数 + 向量）逐条对拍：

| | 5.1.0 | 5.2.0 |
|---|---|---|
| 分数与官方一致 | 58.58% | **100.00%** |
| 分数**偏低** | 41.42% | **0.00%** |
| 分数**偏高**（虚报危险） | 0.00% | **0.00%** |

**方向性承诺**：修正后仍然只会偏低、绝不偏高——三处缺陷全是「少算」，没有一处是「多算」。所以这个工具不会把不严重的漏洞说成严重。

分数从偏低修到准确，意味着**升级后分数普遍上升**。举几个真实例子：

| 漏洞 | 向量 | NVD 官方 | 5.1.0 | 5.2.0 |
|---|---|---|---|---|
| CVE-2009-3616 | `AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H` | **9.9 严重** | 8.9 高危 | **9.9 严重** |
| CVE-2001-0006 | `AV:L/AC:L/PR:L/UI:N/S:U/C:N/I:H/A:H` | **7.1 高危** | 6.5 中危 | **7.1 高危** |
| CVE-1999-0524 | `AV:L/AC:L/PR:N/UI:N/S:U/C:N/I:L/A:N` | **4.0 中危** | 3.2 低危 | **4.0 中危** |

**具体修了三处**（细节见 `../bug清单-5.1.0.md` BUG-001）：

1. **攻击向量「本地」的权重抄错了**——用的是旧版标准的数值，导致所有本地攻击的漏洞被低估；
2. **漏了一步系数换算**——标准要求「影响范围改变」时乘 1.08，代码里没有这一步；
3. **分数取决于向量串的书写顺序**——同一个漏洞，把指标换个顺序写，分数会差 0.3 分。NVD 的向量顺序固定是「影响范围」写在「所需权限」**之后**，所以这一条对 NVD 来源的数据**100% 发作**。

第 3 条是最隐蔽的：它不报错、不崩溃，只让分数悄悄偏低。这也是为什么 CI 一直绿着——**当时仓库的单元测试把错误值写成了期望值**。5.2.0 同时修正了这条测试断言，并新增 29 万条逐条对拍门禁。

### 2. 复现命令不再被目标网站做手脚

「一键复现」命令是 SiteLens 的核心承诺。5.1.0 里，这条命令由**被扫描网站提供的内容**拼接而成，而表单类漏洞的命令里，表单地址和字段名**未经转义**就拼了进去。

恶意网站可以在自己的页面里埋特殊字符，让那条命令在你粘贴执行时跑出预期范围。

5.2.0 修好了：

- 表单地址、字段名、载荷**全部经过 shell 转义**后再拼接（项目里本来就写好了正确的转义函数，只是这条路径没用上，现在统一复用）；
- 表单类漏洞的复现命令**改为与真实请求一致的 POST 格式**（此前被渲染成 GET，实际发的是 POST，同事按命令复现不出来）；
- 表单载荷在复现命令中**做 URL 编码**，不再裸拼。

**给你的操作建议（即使升级后也适用）**：扫描不可信目标时，先用文本编辑器看一眼复现命令再执行；不要盲目粘贴到高权限终端。复现命令本质是只读的 HTTP 请求，不需要管理员权限。

### 3. 内网扫描不再顺带读走云平台临时凭证

`target.allow_private`（「允许扫描私网/本机地址」）此前会**连带放宽云厂商元数据地址的阻断**——代码注释承诺「云 metadata 端点永不放宽」，但实际实现里按 IP 访问时这条保护失效了。

在云主机上做内网扫描时，扫描器可能把云平台的**临时访问凭证**当成网页内容抓回来，存进扫描历史与证据快照。

5.2.0 把云元数据地址段（`169.254.169.254` / `100.100.100.200` 等）挪进**永久禁止名单**，不再受任何开关影响。同时给 HTTP 拨号层加了「一次解析 → 全量校验 → 按已校验 IP 拨号」，DNS 重绑定无法在「校验」与「连接」之间换地址。

### 4. 四段版本号不再被误判为「受影响」

5.1.0 的版本比较只比较前三段，`1.2.3.4` 与 `1.2.3` 被当成同一个版本号。后果是：明明打了补丁的组件，在「漏洞情报关联」里被标成**「确认受影响」**。

Windows 补丁号（`10.0.19041.1234`）、Java/Oracle 系（`4.17.3.0`）这类四段版本号最容易中招。

5.2.0 改为比较完整版本段。**升级后这类条目会从「确认受影响」回落到「可能受影响」或被排除**——同样是修正。

### 5. 其余 31 项内部修复

这些不影响扫描结论，但影响稳定性与部署体验：

| 领域 | 修好了什么 |
|---|---|
| **稳定性** | 重定向跟随时每一跳的响应都会正确关闭，不再每次跳转泄漏一个连接（长扫描跑久了会「连接过多」）；补了 5 跳 × 8 轮的连接数回归断言 |
| **稳定性** | 扫描过程中热更新设置 / 刷新数据 / OSV 同步时的内部状态竞态（极端情况下进程崩溃或结论错配）已修：KEV 与漏洞表加锁、覆盖合并改副本换代、`techIDs`/`apiToken` 原子换枪、403 绕过计数改原子 |
| **稳定性** | 扫描历史里存在残缺记录时，统计接口不再崩溃（此前已修了导出路径，漏了统计路径） |
| **稳定性** | 调度表文件内容异常（`null`/损坏/空）时不再崩溃 |
| **稳定性** | 启动期把增量情报（KEV / CPE 映射）合并进知识库后，首次解码不再把它覆盖清除；空闲释放内存后重载也不再丢 KEV 增量 |
| **命令行** | `-config` / `-graph` / `-ast` / `-env` 放在子命令后面也能生效，不再静默失效（引擎二进制同型修复） |
| **模板库** | 社区模板来源（afrog）此前**一条都没生效**（rule 级判定表达式被静默丢弃，通过率 0/1,699）；5.2.0 恢复为 **878 / 1,699（51.7%）可运行、共转出 1,051 条检查**，其余按「宁少报」口径拒收（不可判定原子 / 纯状态码 / 多请求 AND 链等） |
| **模板覆盖** | 模板声明多条候选路径时不再只探第一条（上限 4 条，见「升级前必读」） |
| **检测能力** | 响应头注入与反序列化两类探测此前因载荷被二次编码而**实际没生效**，5.2.0 修正后 **URL 通道与表单 POST 通道均真实生效**（这两类需要重新扫描才能看到结果） |
| **检测能力** | 插件热加载后，已加载的检测项索引不再陈旧（此前新插件在部分档位下会被静默漏检） |
| **ML** | ONNX 严重度模型通道此前恒不可用（资产路径未跟随一次目录迁移），5.2.0 修复 |
| **安全** | 设置页的 `overrides_path` 不再能写到数据目录之外（限制为数据目录内） |
| **安全** | 扫描历史文件权限收紧到仅属主可读（含响应片段与爆破命中）；配置写回同样收紧 |
| **安全** | 更新通道强制 HTTPS，并在下载后输出实测 SHA256 供人工核对（可设 `SLENS_UPDATE_SHA256` 钉值硬校验）；先校验后解包，篡改内容不进库 |
| **部署** | Docker 镜像补齐缺失的漏洞情报库、CVE 字典、模板情报（此前容器内情报关联/KEV/CVSS 补全/模板情报静默降级）；模板池与 ML 模型因体积改为挂载并在镜像说明中写明降级矩阵 |
| **工程** | `.gitattributes` 补上行尾规范（Windows 开发者不再看到满屏格式告警） |
| **工程** | 13 处文档与实现不一致的表述已订正（含 README 里「非回环监听必须配 Token 否则退出」的描述） |

### 6. 桌面端不再弹控制台窗口

用户反馈最集中的一个问题：**启动时弹一个黑色 cmd 窗口，退出时又闪一个**。5.2.0 修了两个不同的根因：

| 现象 | 根因 | 修法 |
|---|---|---|
| **启动时弹窗** | 此前**一个 exe 既是引擎又是 CLI**，且是控制台子系统程序；桌面壳（GUI 子系统）拉起它时 Windows 必然新建一个控制台 | 引擎与 CLI **拆成两个二进制**；壳侧拉引擎时加 `CREATE_NO_WINDOW` + `HideWindow`（引擎本身仍保留控制台子系统，供 CLI 输出与 `update-seed` 报告） |
| **退出时闪窗** | 壳用 `taskkill /T /F` 树杀引擎进程，而 `taskkill` 本身是控制台程序 | `taskkill` 调用同样加 `CREATE_NO_WINDOW`（树杀语义不变） |

### 7. 失败不再只有一句 "failed to fetch"

用户反馈「老是 failed to fetch，失败了也没有反馈信息」。核实后确认是**前端的错误处理过于粗糙**：

- 请求失败时抛出的 `Failed to fetch` 是浏览器原生文案，**不带是哪个请求、不带原因、不带状态码**；
- 服务端返回非 JSON（例如错误页）时报的是 `Unexpected token '<'`，同样看不懂；
- 更关键的是——**大量调用点把异常静默吞掉了**，界面上什么都不显示，只在开发者控制台里留下一行红字。

5.2.0 改为：**错误分级**（网络失败 / HTTP 错误 / 响应格式错误，各带 URL、状态码与原因）→ **全局提示**（失败时 toast 明确告知）→ **引擎不可达时给界面态**（"引擎未就绪 / 已退出，原因如下"），不再是一片空白或无声失败。

### 8. 应用内有了反馈入口

此前反馈只能跳到外部 Issues 网站，还得自己手动整理版本号、复现步骤、环境信息。5.2.0 新增**应用内反馈页**：

- 自动附带**引擎版本、平台、运行时、数据资产就位矩阵、降级清单、最近失败记录、配置摘要**等诊断信息
- 提交前**可预览、可删减**，敏感内容由你决定带不带
- 默认对目标地址与响应片段做**脱敏**（路径只保留文件名，不含 Token / 凭证 / Cookie）

### 9. 关于"埋点"：已定案为「本地诊断包 + 用户主动提交」

用户希望"有埋点"。但 5.1.0 的产品设计是**明确承诺没有埋点**的——这句话写在《用户服务协议》里：

> 「本软件无账号体系、**无埋点**、无遥测、无崩溃上报、无广告组件。开发者的服务器不接收您的任何扫描数据、目标信息、机器信息、网络拓扑、使用行为或崩溃信息。」

这是**合规卖点，不是遗漏**。加常驻埋点等于修改一份已生效的隐私声明，属于产品立意变更。

**5.2.0 的定案**：**不做常驻埋点**，改为**本地诊断包 + 用户主动提交**——

- 应用内新增**「反馈」页**：一键生成**本机**诊断包，内容包括
  - 引擎版本、平台、运行时
  - **数据资产就位矩阵**：指纹库 / 情报库 / NVD / 模板池 / ML 模型……逐项标注就位或缺失，以及**缺失会让哪项能力静默降级**
  - 当前降级的能力清单
  - 最近的失败记录（脱敏）
  - 配置摘要（**不含 Token、凭证、Cookie；路径只保留文件名**）
- 诊断包**不自动上传**。你可以预览、删减后**一键复制**，贴到仓库 Issue；
  若你配了自己的收集地址（`feedback.endpoint`，内网亦可），也可一键提交到**你自己的**端点。
- 项目**不提供、也不运营任何收集服务端**——不存在"数据发到开发者服务器"。

> 这条同时解决了"老是 failed to fetch、失败了也没有反馈信息"：**诊断包能直接告诉你哪项资产缺失导致某个功能没输出**。

### 10. 命令行只剩一个入口：TUI

此前 npm 线有**两个 CLI**——Node 的 `sitelens`（只有扫描/serve）和平台包里的 Go 二进制（十四个子命令）。5.2.0 把它们收口成**一个**：

```
sitelens                     交互式 TUI（首屏「选功能」：扫描 / 源码审计 / 诊断 / 历史）
sitelens scan <url>          非交互扫描
sitelens audit <目录>        源码静态审计
sitelens doctor              本机诊断
sitelens history / verified  扫描历史 / 已验证发现汇总
sitelens serve               引擎 Web 控制台直通

sitelens update <目标>       数据更新（nuclei/afrog/fp/ehole/nvd/osv/tplintel）
sitelens correlate           黑白盒事实图关联
sitelens graph-read          事实图读取 / 契约自检
sitelens regression          验证回归
sitelens migrate-pg          历史库一次性迁移
```

- **命令表是唯一事实源**——`sitelens --help` 由它生成，不会再出现"命令改了但帮助没改"。
- **Go 侧 CLI 退回内部实现**，不再对外推荐；桌面安装包也不含它。
- **用户区统一到 `~/.sitelens/`**：配置、数据资产、扫描历史都在这里。首次运行会自动把平台包内置的指纹库交付到用户区。
- 直通型命令（audit / update-* / correlate …）的输出与退出码**原样透传**，所见即引擎所得。

### 12. 性能优化（5.2 追加，实测数据）

这一版在修正确性之外，把几处"每扫一次都要付"的固定成本压了下来。以下均为本机实测（i7-14650HX；同一语料/同一工作树交错对比）：

| 场景 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| **指纹匹配**（40KB 页面 × 13,727 条指纹，单页） | 24.7 ms | **5.3 ms** | **4.7×**；内存分配 4,381 → **194 次/页**（-95.6%） |
| **4 页站点端到端扫描**（每页 40KB，只跑采集+指纹阶段） | ≈102 ms | **6.2 ms** | **16.4×**（页间并行 + 匹配提速） |
| **模板索引热路径**（每次扫描都要做的事，14.4 万模板池折算） | ≈1.1 s/次 | **≈6 ms/次** | **≈180×**（目录戳校验替代全量遍历 + 进程内缓存） |
| **模板索引冷构建**（模板池更新后首次重建，14.4 万模板折算） | ≈35–57 s | **≈8 s** | **4.5–6.6×**（前端形状预筛 + 并行转换） |
| **HTTP 拨号**（首地址黑洞、后一地址可用） | 等到请求超时后失败（默认 20 s） | **≈250 ms 成功** | 从「超时失败」变为「正常完成」 |

具体做了什么：

- **指纹匹配**：字面量预筛改为滚动 4 字节 key + 开放寻址表（单页正文单遍扫描）；正则按语法树推导「必含字面量条件树」，可证明不匹配时跳过执行（40KB 拟真页上 436 条正文正则实际只跑 2 条）；相同正则只编译一次并在同页内复用结果；多页指纹识别改为页间并行（结果仍按页面顺序合并，行为与串行一致）。
- **模板索引**：转换前先做廉价的「模板前端形状」字节级预筛（afrog 模板从 3 次 YAML 解析降到 1 次），冷构建按 CPU 核数并行；缓存有效性判断从「遍历全部文件计数」改为「校验目录 mtime 戳」，并加进程内单条缓存——满模板池用户每次扫描的固定开销从约 1 秒降到毫秒级。
- **HTTP 拨号**：在「一次解析 → 全量校验 → 只拨已校验 IP」的 SSRF 语义不变前提下，对已校验 IP 做轻量 Happy Eyeballs（RFC 8305，首地址立即尝试、之后每 250 ms 追加一个、先成功者胜出并取消其余）。含 IPv6 黑洞的多地址目标不再把请求拖到超时。

> 性能测试已固化为可重复基准：`internal/sitelens` 的 `BenchmarkMatch`、`internal/engine` 的 `BenchmarkMultiPageScan`；等价性由「旧语义参照逐字段比对」与「门控跳过 ⇒ 正则确实不匹配」测试兜底。

### 13. 效率优化（第三轮：扫描墙钟与目标负载）

第二轮把 CPU 成本压掉后，扫描时间几乎全花在限速等待上（实测一次 deep+DAST 扫描
≈99.6% 墙钟是 sleep）。这一轮在**不增加目标负载**的前提下重做了限速层并做请求去重：

- **限速层**：修掉旧实现「并发调用者齐发」的缺陷（400ms 配置实际跑出 ≈5 rps）；
  改为按主机共享令牌桶。默认 `balanced` 档 400ms 起步、连续干净成功后加速到
  125ms 硬下限（**平均 ≤8 req/s/主机**，代码级绝对上限 10 req/s，并发不增加）；
  目标响应变慢（RTT 恶化）或出现 429/503/Retry-After/WAF 挑战页时自动退避并锁定
  低速。`polite` 档保留固定间隔；最保守可设 `rate_max_rps: 5`（≤5 req/s）。
- **WAF/限流拦截可见**：被拦响应标记 `Blocked` 且**不参与任何判定**（WAF 错误页回显
  payload 会造成假阳性）；报告/诊断里可看到被拦截次数与原因，不再静默少报。
- **请求去重**：DAST 良性基线跨通道复用（payload 绝不复用）、只读页面响应单扫描复用、
  逐页流式分析、主页/robots/favicon 去重——同靶场请求数 **-2.88%**，且随参数/表单
  数量增加收益更大。
- **实测**（4 页带表单/带参，deep+DAST）：旧实现 775 请求/155.1s → 新默认
  **771 请求/98.1s（-36.8%）**，发现结果等价；保守档（5 req/s）156.09s、
  polite 400ms 310.01s。
- **新增诊断账本**：结果 JSON 增 `diagnostics`（additive，不改既有键位）——每阶段
  请求数/耗时/去重命中/被拦次数/平均 RPS，排障和性能回归都可量化。
- **配置**：`scan.rate_mode: balanced|polite`（默认 balanced）、`scan.rate_max_rps`
  （默认 8，绝对上限 10；调低更保守）。

> 目标侧负载验收：默认平均 7.9 req/s/主机（峰值 1s=9）、最大并发 1（未增加）、
> RTT/WAF 信号自动退避；相对旧实现墙钟 **-36.8%**。如需最保守（≤5 req/s）：
> `scan.rate_max_rps: 5`。

### 14. 5.2 新增（部分）：预检 / 网络层 / 爆破护栏 / SARIF

> 本版先交付 4 项低风险增量，其余能力（批量续跑/定时、审计基线/规则/SCA、网络层资产发现、统一任务中心等）列入 **5.3**，详见 `docs/新功能路线图-5.2.md`。

- **扫描前预检 + 建议卡**：输入目标后发 1 次只读 GET（≤ MaxHops 跳/256KB/5s），展示状态/标题/服务器/WAF/技术指纹，并给出建议档位（WAF→关 DAST、CMS→保留专项、静态→快速、401/403→认证/UA）。**该响应在开始扫描时复用为首页，总请求不增加**；`scan.preflight` 可关；同 URL 30s 去重。
- **网络层 P0**：证书 hostname/SAN 不匹配、链不完整、SHA-1、RSA<2048；DMARC 策略（none/quarantine/reject + rua）、SPF 查询数/语法、HSTS、HTTP→HTTPS 跳转。附带修复：TLS 采集模式未设 InsecureSkipVerify，导致证书不合格站点的既有证书类发现长期空转。
- **登录爆破安全护栏**：锁号/429/403/连续失败自动停止或退避、每账号尝试上限、每次 POST 前重取 hidden/CSRF、成功证据（响应差异 + Set-Cookie + 跳转 + 可复制 curl）；不增加验证码破解能力。
- **源码审计 SARIF 导出**：`sitelens audit <dir> --sarif out.sarif`，SARIF 2.1.0（ruleId/level/locations/partialFingerprints），可接 GitHub/GitLab code scanning；既有 JSON 报告键位不变。
- **批量扫描增强**：逐行档位（`url quick|standard|deep|full`，中英文均可）、失败自动重试 3 次、同 host 串行/跨 host 并行、任务队列显示档位/尝试次数、结果 CSV 导出、**断点续跑**（状态落盘 `data/state/batches/`，取消/重启后可续跑未完成目标）。

以上新功能均带开关或为 additive，可单独关闭；具体验收见 `docs/release-5.2.0/预检与建议卡-5.2.0.md`、`docs/release-5.2.0/网络层与爆破护栏-5.2.0.md`。

## 已知限制（本版未解决）

- **常驻埋点（匿名使用统计 / 崩溃自动上报）本版未引入**——5.1.0 的用户协议明确承诺"无埋点、无遥测、无崩溃上报"，引入前需先修订该声明并确定默认开关策略。5.2.0 以"本地诊断包 + 用户主动提交"满足反馈诉求（见上面第 9 条）。
- **诊断包不含日志全文**：只含资产就位矩阵、降级清单、最近失败记录与配置摘要。若问题需要更深的日志，仍需手工提供。
- **表单侧 CRLF 探针已修复（第二轮优化）**：此前表单 POST 通道经统一表单编码导致预编码载荷二次编码、实际不注入；现由引擎提供「原始表单体」通道、dast 表单 CRLF 探针按预编码字节原样发送，证据链 Request/Replay 与真实请求逐字节一致；拿不到原始通道时宁少报、不发无效请求。URL 与表单两条通道均已真实生效（需重扫验证）。
- **包体瘦身阶段 1/2 已完成，仓库瘦身同轮落地**：默认包已移除 ONNX 与 onnxruntime，严重度=查表+0.7MB 线性回归；仓库内 ONNX/LFS 资产与 git 历史已清理（完整 clone 约 1.35 GB → 0.5 GB），真实安装包体积待出包回填 `【待发布】`。
- **`-race` 门禁需 CGO 环境**：本机无 C 编译器，并发用例按 race 友好设计但未实跑；CI/有 cgo 的机器上应执行 `CGO_ENABLED=1 go test -race ./internal/intel ./internal/server ./internal/nuclei`。
- **模板索引的目录 mtime 校验**：模板池增/删/改名在下一次扫描即被感知；极端时序（批量落盘后数毫秒内立即扫描）或网络盘/粗粒度文件系统上可能延后到再下一次扫描才发现（只会少跑新模板，不会误报）；in-place 覆盖写与 5.1 同口径（可删 `data/state/nuclei_index.json` 强制重建）。
- **指纹正则的旧字面量门控存在既有误提取**：`\s`/`\d` 等转义被当作字面量字符（如把 `WordPress\s*` 误提取为 `wordpresss`），本版**保持 5.1 语义未借优化改召回**（HTML 正文通道行为不变；meta 通道改挂新的语法树门控以避免漏检）；修正属提升召回的语义变更，另行评估。
- **更新通道无官方 checksum**：上游（nuclei-templates / afrog / webappanalyzer）不提供官方校验值，本版只强制 HTTPS + 实测 SHA256 留痕 + 可选钉值，不伪造校验；请更新后核对输出 SHA256。
- **白盒污点分析没有「净化器」概念**：污点一旦标记就不可消除。这是 4.0 起的已知建模缺口，本版未动。
- **非 HTTP 协议通道的 DNS 重绑定缺口**：`netx` 拨号层的 CNAME→私网绕过仍未修（代码里已注明推迟）。
- **ML 的两个排序模型**（`verify-rank` / `find-rank`）仍处正例积累期，未随本版交付。
- **CNB 的 tag 自动发版流水线已停用**（v3.0.0 的真实事故：CI 在 Linux 上构建出的「exe」实为 ELF，装进 Windows 包后引擎起不来）。发版走本地 `tools/release_local.sh`。
- `apocalypse` 档位（全量模板）耗时较长，本版验证未包含该档位。
- **模板来源存活率**已加「来源覆盖门禁」（任一来源通过率为 0 即测试失败），但其余来源的通过率基线尚未固化。

### A. 源码审计：基线与 diff、规则扩展、SCA（AU-02 / AU-03）

- **只报新增**：新增 `--baseline <file>`（只报不在基线内的新发现，过滤条数写入报告
  `baseline_ignored`）与 `--update-baseline`（把本轮全部发现指纹写入基线）；指纹含规则/
  文件/行号语义，换行号漂移或规则换代后仍判为新告警。
- **与上次报告 diff**：`--diff <report.json>` 按指纹对比上一次审计 JSON，输出 `diff.new` /
  `diff.fixed` 两组。
- **规则扩展**：新增 Java / Go / TS（含 JSX/TSX）高频规则；每条规则带 **OWASP Top 10:2021**
  映射（JSON `Finding.owasp`、SARIF `rules[].properties.owasp`）；密钥扫描增强为
  「云厂商 key 前缀 + 高熵检测」，熵命中只报键名、不把密钥值写进报告。
- **SCA**：解析 `go.mod` / `package-lock.json` / `requirements*.txt`，输出依赖清单与生态统计。
  **实现边界**：漏洞判定只在存在本地 OSV 库时进行；当前仓库未附 OSV 库，报告
  `status="unknown"` 并明确标注「漏洞状态未知」——不联网、不臆造漏洞。
- **兼容性**：不改既有 `audit` 输出；不带新开关时 JSON 报告逐字节不变；SCA/基线/diff 均为
  additive 字段。

### B. 网络层：资产线索、端口/服务、协议评级（NS-02）

- **证书资产线索**：证书 SAN（DNS/IP，去重保序）、颁发者、到期时间；`CertExpiry` 给出剩余
  整天数，供上层做资产发现与到期提醒（本包不落盘）。
- **协议评级**：cipher 套件强度分级 + ALPN/HTTP2 观测；弱套件给出明确 Finding。
- **端口/服务探测**：TCP connect + 被动 banner（≤256B，不发送 payload）；`scan.port_scan`
  **默认关闭**（会额外发 TCP connect，仅授权目标开启）。
- **批量入口**：单主机组合检测与多主机批量（`internal/netsec` 批量入口），复用只读语义。
- 已知边界：只做 TLS/TCP 上可观测的协商结果，不做主动协议指纹伪造；资产到期提醒的持久化
  由上层负责，本批未接入 UI。

### C. 登录爆破：多步登录、失败分类、批量与白名单（LB-02、XC-03）

- **多步登录**：先提交用户名再提交密码；支持自动推导与显式步骤，JSON 登录端点、多步 action
  地址同样受白名单约束。
- **失败原因分类**：在既有「用户存在/不存在」判定之外新增分类（凭据错误/锁号/限流/验证码/
  网络等），通过进度文案与 `OnFailure` 回调暴露；**不改变任何命中判定**。
- **批量目标**：串行执行多目标，每目标独立护栏（锁号/连续失败/每账号上限/取消各自计数），
  跨目标总尝试上限 `MaxTotalTries` 到顶后剩余目标标记未执行。
- **授权白名单**：新增 `scan.allow_hosts`（空=不限制；精确域名或 `*.example.com`；子域匹配
  不含 apex）。不在白名单的目标在扫描/网络层检测/登录爆破/JSON 端点与多步提交地址上
  **零请求拒绝**；SSRF/内网/gov.cn 等硬闸门不受此开关影响，白名单是授权护栏而非 SSRF 防护。

### D. 批量：定时、结果 diff、标签与 webhook（BT-03）
