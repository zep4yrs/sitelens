# 阶段 2：查表优先 + 指纹先验（5.2.0）

> 状态：**代码/测试已落地（工作区改动，未 commit）**。
> 上游：[阶段 1（线性 severity 与 ONNX 下线）](阶段1-线性severity与ONNX下线-5.2.0.md)、
> [算法替代 A/B 实验](ML-算法替代A-B实验-5.2.0.md)。
> 目标：把「模型推理」从默认路径降为**盲区兜底**——引擎已经拿得到的权威数据
> （NVD CPE / NVD weaknesses / 情报行字段 / 指纹技术名）优先出结论。

---

## 1. 一句话

产品、CWE、严重度三个预测字段统一改为 **查表优先 → 模型兜底**：
NVD 镜像的 CPE / weaknesses / CVSS 分与 finding 自带字段能答的条目直接出结论，
只有查不到时才惰性加载模型资产（查表全覆盖时**连 94MB cve-tech 都不读**）；
前置调度通道（`mlPrior`）改为**指纹技术名 → 产品映射**的确定性路径，不依赖模型。
对外契约新增 `tech_source` / `cwe_source`，与 `sev_source` 一样标注来源。

---

## 2. 落地内容

### 2.1 `mlEnrich`：三字段查表优先（`internal/engine/ml.go`）

优先级：

| 字段 | 第一优先（查表，误差 0） | 第二优先（模型） | 来源标注 |
|---|---|---|---|
| `tech_top5` | NVD CPE（`prods[].vp`）；无 NVD 时 finding 自带 `product` | cve-tech 线性模型 | `nvd` / `intel` / `model` |
| `cwe_type` | NVD `cwes`（finding 回填的 CWEs 同源） | cwe-type 线性模型 | `nvd` / `model` |
| `sev_score` | NVD/finding CVSS 分 | sev-linear 回归 → 可选 ONNX | `nvd` / `linear` / `onnx` |

- **惰性资产**：`assets` 改为首次真正需要模型时才加载（`getAssets()`），
  查表全覆盖的扫描不读取 94MB cve-tech；只有缺产品/CWE/分数时才回退模型。
- **纯查表也能出预测**：即使一个模型资产都没有，只要 CPE/CWE/CVSS 存在，
  `predictions` 照常产出（此前资产缺失直接不挂字段）。
- **不臆造**：无描述、无 CPE/product、无 CWE、无分数的 CVE 仍跳过。
- **概率语义**：查表结果 `tech_top5[].prob` 固定为 1（不是概率），
  消费方以 `tech_source` 区分；模型结果仍是 predict_proba 口径。

### 2.2 前置通道：指纹先验（`internal/engine/mlprior.go`）

- **主路径**：`res.Technologies`（指纹已确认的技术名）→ `checks.MLProductChecksForTech`
  → 同一张 8 键产品映射表 → check 提权 + 低档位扩展集增量纳入；
  权重固定 0.9，`extras.ml_prior.source="fingerprint"`。
- **回退路径**：指纹无命中时才走旧 5.0 文本模型（`cve-tech` 对标题/技术清单/
  正文头部打分，`source="model"`，需模型资产）。
- **收益**：前置通道在无模型资产时仍可用；不再为「判断站点是不是 WordPress」
  去加载 94MB 模型，也不会被正文泛化词（open source/software…）带偏。
- 铁律不变：只调序/只增不删；指纹先验同样只影响执行顺序与扩展集纳入。

### 2.3 契约与展示

- `ml.Prediction` 新增 `tech_source`、`cwe_source`（omitempty，旧记录无此字段）。
- `extras.ml_sev` 增加 `tech` / `cwe` 来源计数（nvd/intel/model/none）。
- web「AI 预测」表：查表结果不显示伪概率，来源列按 严重度/产品/CWE 分别打徽章；
  摘要区 `ml_prior` 在指纹来源时显示「产品先验（指纹）」。
- 设置项不变：`ml.predict` 总闸仍管三通道；无查表数据时才需要模型资产。

## 3. 为什么能这么做（A/B 依据）

引擎真实输入上的权威字段覆盖（[A/B 报告 §2](ML-算法替代A-B实验-5.2.0.md)）：

| 数据源 | 规模 | 关键覆盖 |
|---|---|---|
| NVD 全量 | 398,118（2026-10-30 刷新） | score 96.8% · prods 81.1% · cwes 84.5% |
| `tpl_intel`（模板情报） | 29,554 | 自带 severity/product/descr 100%；CVE 99.997% 在 NVD；score 99.94%、cwes 96.0% |
| `vuln_kb` | 1,985 | 自带 severity 100% · product 94.5%；CVE 命中 NVD 36.7% |

> 注：A/B 报告（2026-06 快照）的数字为 372,542 条、score 97.8% / prods 84.7% /
> cwes 84.1%；2026-10-30 已把仓库种子刷新到 398,118 条（内容到 2026-10-30）
> 并精简到 30.7 MiB，本表覆盖数字取新快照。

- 严重度：查表覆盖 99.9% 的引擎输入，模型只服务「本地 NVD 快照未同步」的时间窗
  （阶段 1 已用 0.7MB 线性回归兜底）。
- 产品：NVD CPE 覆盖 81.1%（2026-10-30 快照），tpl_intel 自带 product 100%；剩余盲区才轮到模型。
  196 类类表与 tpl 产品空间不匹配（仅 24.4% 落在类内）——查表输出**原始 CPE
  vendor/product**，比强行映射进 196 类更接近真实产品空间。
- CWE：NVD weaknesses 覆盖 84.5%（tpl 96.0%）；关键词规则实测 61.5% vs 线性
  80.7%（见 A/B §3.3），故盲区保留线性模型，不用规则。
- 前置通道：A/B 显示 cve-tech 站点文本 Top-1 常在 0.1~0.6，而指纹技术名是
  确定性命中；8 个可行动产品键在 13,727 条指纹库中全部有对应技术名。

## 5. 未做 / 后续

- ❌ **product 词典兜底未移植 Go**：A/B 中的「词典前置 + 模型兜底」混合方案
  （Top-1 83.5% vs 纯模型 80.2%）仍留在实验脚本里；当前实现是「查表 → 模型」，
  盲区的词典收益（单产品场景几乎打平、多产品弱）暂不值得引入 1659 条人工别名资产。
- ❌ 196 类类表与 `tpl_intel` 产品空间的口径对齐（A/B 指出这是 product 预测
  「看起来不准」的最大原因）——属数据/类表工作，列 5.3。
- ❌ `vuln_kb.type`（中文攻击类型）→ CWE 的映射表未接入；当前 CWE 盲区直接用
  12MB 线性模型（80.7%，远好于规则 61.5%）。
- ❌ 查表全命中时**不加载**模型，但模型资产仍随包分发（约 106 MiB）；彻底移除
  cve-tech/cwe-type 需等「词典/查表」补足盲区后另评（阶段 3）。
- 回退：`ml.predict: false` 关闭整条通道，行为回到「不产出 predictions」。
