**外部"本地决策模型"路线已被预注册实验以真实数据否决：正主

## 三、调研结论：Jev 生态到底是什么

由调研工作流逐 URL 探测核实（详见工作流产物"今晚评测方案 runbook"）：

1. **Jev 本体（TypeSafe AI）没有公开权重**。"本地跑 Jev"的一切说法都是复刻。
2. **真实可下载的开源决策模型是存在的**：主代表
   `chaoliangUNSW/Jev-Style-0.8B-Decision-v3`（Apache-2.0，Qwen3.5-0.8B 决策微调，
   选项→校准概率的原生 decide 接口，官方 GGUF 0.53GB）；另有 kev-0.8b（LoRA+指针头，
   无 CPU 服务路线）、openJev Verdict 1.4（151M ONNX）、Laya（typed 版带
   security-incidents 标签）、Von（395M）等 13+ 个复刻，权重均逐一探测确认。
3. **按用户最初点名的 NanoJev 核实为游戏动作模型**（CUDA-only，与文本决策无关），
   搜索引擎摘要中的 GitHub 仓库名与真实仓库不符（镜像 API 实测 401）。
4. 复刻路线本身包含训练（如 kev = Qwen 底座 + LoRA + 读出头）——
   "用决策模型就不用训练"在该生态内部即不成立。

协议与闸门在**任何被测系统推理之前**提交（a062d10，git 时间戳可证）：

- **评测集**（seed=20260928，sha256 清单）：E1 严重度 1500 条（kb_cve，2024 切分

- **闸门**（先于结果写下，平局判基线）：≥2/3 任务严格胜出 且 峰值 RSS≤800MB

- **公平性**：基线在同一评测行用同一指标代码重算；正主用其官方参考实现与原生
  decide 接口（含分组温度校准），不硬套我方提示词。

## 五、结果

### 质量闸（E1/E3 实测，E2 见偏差披露）

| 任务 | 指标 | 基线（同集重算） | 零样本 Qwen3-0.6B | 正主 Jev-Style-0.8B |
|---|---|---|---|---|
| E1 严重度 | accuracy / macro-F1 | **0.5738 / 0.4903** | 0.0553 / 0.038 | 0.1633 / 0.111 |
| E2 产品关系 | P@5 / MRR@5 | **0.905 / 0.8585** | 0.010 / 0.0057 | 未测完（见 §七） |
| E3 候选排序 | nDCG@5 / P@5 | **0.2437 / 0.0947**（prior_hits） | 0.2437 / 0.0947（恒 0 分退化为 tie 序，未严格超基线） | 0.0 / 0.0 |

- 零样本轮的 E1 失败形态：语法约束下四选一，1500 条全部把 100% 概率押 "low"。
- 正主的 E1 失败形态：79% 预测押 "critical"（对 critical 召回 0.831，
  对 high/low 几乎全盲）——域外先验坍缩，校准概率没有错，错的是模型对这个域的判断。
- 正主 E3 的失败形态：nDCG@5 = 0.0，全面弱于四条规则基线。

### 资源闸（同机实测）

| 系统 | 批量吞吐 | 进程内存 | 单决策延迟 |
|---|---|---|---|
| 基线（TF-IDF+SGD） | **25,824 行/秒** | **202 MB** | 微秒级/行 |
| 零样本（llama.cpp 8×4K 槽） | — | 13,140 MB 峰值 | E2 形态 p95 9.2s |
| 正主（torch bf16） | ~0.7 行/秒（E3 实测） | **3,576 MB** | 1.4s（10 选项）/ ~25s（200 选项） |
| 正主（GGUF Q4_K_M 单槽） | — | 888 MB | 未逐项实测 |

三条件判定：质量 0/2 可判全输（E2 即使赢也凑不齐 2/3）；内存双路线超限
（GGUF 超出 11%，按实测记负）；宽选项延迟超限 12 倍。

## 六、判定与决策

**不采纳。** 依据预注册闸门（commit a062d10）与上表实测：
外部本地决策模型在可预见的部署形态下（CPU、桌面内存预算、批量候选排序）不构成
5.0 传统 ML 线的替代或叠加。EXP-1004 收案，登记于
`data/ml/metrics/EXP-1004-decision-model-comparison.json`（含 MANIFEST 与
registry 追加，adopted=false）。

**重开条件**（写入登记，任一满足可重评）：SiteLens 域内微调的决策模型权重开源；
单决策 RSS<300MB 且宽选项延迟<2s；第三方发布扫描候选排序任务上可复现的
优于规则基线的证据。

**自主开发决策**：实验输给的是我们自己的模型，因此开发投入回到自有主线——
本次已落地的增强（评测基建、可复现的基线同集重算、Jev 生态情报库）全部
沉淀为 `ml/bench/`，后续任何"要不要换个模型"的讨论先过这套基建再说话。

## 七、偏差披露（全部如实记录）

1. **仪器修正**：llama.cpp `top_logprobs` 缺省报告未掩码原始分布，第一轮零样本
   E1/E3 的概率读出读错了对象；改 `post_sampling_probs` 后重跑。坏仪器轮结果
   存档（`lm_on_same_sets_brokenprobe.json`）未删；两轮预测一致（掩码 argmax 相同），
   不影响结论方向。
2. **正主 E2 未测完**：200 选项 decide 实测 ~25s/条，全量 800 条需 5.5h+，
   为守住清晨交付时间闸停止。闸门判定不依赖它：E1+E3 双输后 ≥2/3 不可达。
3. llama-server 上下文 2048→32768 为基础设施修复（E2 提示词 2126 token 超每槽
   配额），发生在零样本阵营最终数字之前。
4. 正主 E1 指标从留存样本经同一指标实现重算（该次运行的结果 JSON 因 E2 中断
   未生成，样本文件完整可复核）。
