# SiteLens 5.0.0 发行说明

2026-09-29 发布。这一版把机器学习模型接进了扫描引擎本身：同一台机器、同一
个档位，5.0 能看见 4.0 看不见的问题。没有宣发图，下面全部是实测数据。

## 升级前必读

- 安装包从 4.0.1 的 248MB 增长到约 552MB：ML 模型资产（含 sev-prior ONNX
  fp32/int8 与 onnxruntime 运行时）已全量内嵌，开箱即用，无需额外下载。
- 扫描行为有一个真实变化：AI 产品先验会把相关检测项提前执行、并在核心档位
  增量纳入。**它只会多查、不会少查**——任何 4.0 会执行的检测项 5.0 原样执行，
  命中判定条件一字未改；不想要 AI 行为时在设置里关掉 `ml.sev_onnx` 与
  `ml.predict` 即回到 4.0 行为（逐字节一致，有回归测试护栏）。
- 扫描收尾的预测富化会带来几秒到几十秒的额外耗时（full 档实测 +61%），
  换取的是低档位的发现差异，见下面的实测对比。

## 你能得到什么（4.0.0 vs 5.0.0 同靶场实测）

| 档位 | 4.0.0 已验证发现 | 5.0.0 已验证发现 | 5.0.0 额外耗时 |
|------|-----------------|-----------------|---------------|
| quick | 0 | 0 | +1.1s |
| standard | 0 | 0 | +1.1s |
| **deep（核心集）** | **0** | **5** | +1.6s |
| full | 5 | 5 | +32.9s |

deep 档那 5 条（wp-json / wp-login / wp-readme / wp-users / wp-xmlrpc），
4.0 要开到 full 档才能看到。原因是这批检测项属于扩展集，而指纹库没有认出
目标站——5.0 的 cve-tech 模型从站点文本给出 wordpress/wordpress（0.498）的
产品先验，把相关检测项增量纳入并提到队列最前。完整表格与逐条证据见
《对比报告-4.0-vs-5.0.md》。

每条发现现在还带「AI 预测」：受影响产品 Top-5、弱点类型、严重度以
**分数 ± 1.07 区间**呈现（替代硬档位），来源徽章标注是模型推理还是 NVD 先验
回退。AI 预测是先验参考，不参与任何单条检测项的命中判定。

## 兼容升级

- 4.0.0 / 4.0.1 可直接安装升级，配置自动迁移；历史扫描记录不受影响。
- 结果 JSON 新增 `predictions` / `check_runs` / `extras.ml_prior` /
  `extras.ml_sev` 字段，均为增量（旧消费方无感）。
- `target.allow_private` 为新增显式开关（默认 false，行为与 4.0 一致）：
  扫本机靶场/授权内网时自行开启；gov.cn 与云 metadata 端点的阻断不随开关放宽。

## 启用步骤

1. 运行 SiteLens-Setup-5.0.0.exe（自动覆盖升级，无需卸载）。
2. AI 能力默认开启，无需配置：产品先验调度 + 扫描收尾预测富化 + 严重度
   模型推理（ml.sev_onnx 桌面版默认 true）。
3. 工作台扫描结果页查看「AI 预测」块与摘要区的先验行。
4. 如需回到纯 4.0 行为：设置中关闭 `ml.predict`（引擎配置文件 `ml:` 节）。

## 已知限制

- npm 分发线（@fengqiao666/sitelens-cli 0.0.1-rc 地基版）为终端形态首版：
  不内嵌漏洞情报库与 ML 资产（情报关联与 AI 预测默认回退/关闭），面向
  脚本与 CI 场景；桌面安装器是全能力形态。
- sev-prior 模型分对旧记录不回填；来源徽章缺失即旧记录。
- verify-rank / find-rank 两个排序模型仍在正例积累期，未随本版本交付。
- apocalypse 档位（全量模板）耗时较长，本次对比数据未包含该档位。
- ONNX 推理仅在桌面安装器形态可用；npm/CI 构建自动回退 NVD 先验（结果中
  有明确标注，不静默）。
