> 上一轮写成了 5.2.3 发布文案，理解错了；这篇是“进第一梯队”的冲刺文案 + 行动方案。

## 一、一页纸结论

**现状**：综合 3.68 / 5，第二梯队上沿，第 4 名；距第一梯队门槛 3.8 差 **0.12**。
**强项**：验证 4.75（对标第一）、部署 4.90（对标第一）。
**短板**：覆盖 3.35、发现 3.20、企业 3.45、生态 2.70。
**判断**：这 0.12 不是再堆功能能补的，是三张**可验证的成绩单**：

1. 完整标准靶场矩阵 + 可复现的季度对标报告（补覆盖/发现）；
2. PostgreSQL 真机 + 企业规模验证（补企业）；
3. GitHub Action/CI + 插件/模板生态 MVP（补生态）。

**目标**：6 个月内综合 ≥ 3.8（第一梯队边缘），12 个月 ≥ 3.9；验证/部署保持第一。

## 二、0.12 从哪来（可算账）

当前加权：0.25×3.35 + 0.15×3.20 + 0.15×4.75 + 0.15×3.45 + 0.10×3.70 + 0.10×4.90 + 0.10×2.70 = **3.68**

到 3.8 需要 +0.1225，可选组合：

| 路径 | 需要的变化 | 加权增益 |
|---|---|---:|
| 只补覆盖 | 覆盖 3.35→3.84 | +0.1225 |
| 只补发现 | 发现 3.20→4.02 | +0.123 |
| 只补企业 | 企业 3.45→4.27 | +0.123 |
| 只补生态 | 生态 2.70→3.93 | +0.1225 |
| **推荐组合** | 覆盖 +0.25、企业 +0.20、生态 +0.25、性能 +0.05 | **+0.1225** |

推荐组合对应的具体分数：
- 覆盖 3.35→3.60（+0.0625）
- 企业 3.45→3.65（+0.030）
- 生态 2.70→2.95（+0.025）
- 性能 3.70→3.75（+0.005）

> 这比“单点冲到第一”稳：不要求覆盖一下到 3.84，而是三张成绩单各抬一档。

## 四、三个战役与验收标准

### 战役 A：完整矩阵（补覆盖/发现）

**交付**
- [ ] OWASP Benchmark + Juice Shop + WebGoat + pikachu + DVWA + bWAPP + sqli-labs(PHP5 容器) + upload-labs/xsslabs 全量跑通；
- [ ] 20 个授权真实站点/样本（签授权书，脱敏后入报告）；
- [ ] `docs/基准评测-季度报告-Q4.md`：P/R/F1、类型覆盖、目录覆盖、逐类缺口；
- [ ] 失分项修复清单（FN 归因 → 修复 → 回归）。

**验收**
- 目录覆盖 ≥ 80%（G02 口径）；
- OWASP Top10 每类至少 1 个可复现命中；
- 报告可由第三方按脚本复跑；
- 覆盖分 3.35→≥3.60，发现分 3.20→≥3.40。

**工作量**：M（1–2 个月，1–2 人）。

### 战役 B：企业规模（补企业）

**交付**
- [ ] PostgreSQL 真机：迁移、identity、10 万条历史、并发读写、故障回退；
- [ ] `sitelens migrate --to sqlite|postgres --dry-run/--verify`；
- [ ] RBAC 三角色 × 三租户验收；多租户数据面隔离或明确“单租户生产”边界；
- [ ] job/队列持久化 + 重启恢复 + 审计日志；
- [ ] 1000 URL / 24h 压测报告。

**验收**
- 重启不丢任务/历史 ≥ 10 万条；
- 3 角色 × 3 租户权限矩阵全过；
- PG 迁移可回滚、有校验；
- 企业分 3.45→≥3.65。

**工作量**：L（2–3 个月，2 人）。

### 战役 C：CI/生态（补生态）

**交付**
- [ ] GitHub Action（PR 注释 + baseline 阻断）；Jenkins/GitLab CI 示例；
- [ ] SARIF 被 GitHub code scanning 实际解析一次并留档；
- [ ] 模板/插件市场 MVP（提交、审核、版本、评分）；
- [ ] 英文 README/快速开始/API 文档；

- 生态分 2.70→≥2.95。

**工作量**：M（1–2 个月，1–2 人）。

## 六、风险与不做的事

**风险**
- 实测可能先拉低分数（原来“没测”是模糊分）；必须接受“先真后高”；
- 20 个授权样本获取慢：优先用公开靶场 + 自建授权环境，不伪造；
- PG/多租户是功能开发，不是测试；排期不足会拖企业分；
- 生态 MVP 容易做成“文档工程”：必须有一个真实 PR 闭环。

**不做**
- 不为了分数改口径（例如把子集说成全量）；
- 不在没跑完矩阵前对外说“第一梯队”；
- 不堆“默认关”的高级检测来充功能数；
- 不跳过公信证书/CLI 包等交付项。

## 七、一句话收口

> 3.68 到 3.8，差的不是 0.12 分，是**一份完整矩阵报告、一台真 PG、一个 CI 闭环**。
> 这三件事做完，第一梯队是结果，不是口号。
