# MoE 模板调度：现状评估与替代方案

> 对象：`internal/nuclei` 的 `Select` / `SelectWithCVE`。
> 结论先说：**当前 MoE 三路调度不是“命中率最优解”，但它是“确定性 + 覆盖保证 + 可审计”约束下的优秀基线。**
> 建议保留分层/轮转骨架，把“排序信号”从 LRU+TF 升级为“质量先验 + 成本感知 + 上下文 bandit”，
> 不要推翻重写。

## 1. 现状（5.2.3）

`SelectWithCVE` 的实际行为：

1. **CVE 命中桶**（最高优先）：intel 关联出的真实受影响 CVE → 声明该 CVE 的模板；
2. **tag 命中桶**：指纹技术 tag 与模板 tags 硬匹配，按严重度升序；
3. **轮转桶**：其余模板按 `lastRun` 升序（LRU，最久没跑优先）→ TF 余弦相关度 → path；
4. 命中桶合计最多占预算 2/3，被截断的退回轮转；`⌈N/n⌉` 次扫描让全池必然各跑一遍；
5. `lastRun` 持久化在 `data/state`，重启不丢进度。

**优点**

- 确定性：无随机、可复现、可解释，适合安全产品的“结论可审计”；
- 覆盖保证：轮转桶保证任何可运行模板最终都会被执行，不会被强匹配饿死；
- 零模型依赖：TF 余弦只做排序，不需要训练/推理/外部服务；
- 目标针对性：CVE/tag 桶优先，比纯轮转更早命中“这台机器真的中的”。

**不足（为什么不是最优）**

| # | 问题 | 后果 |
|---|---|---|
| 1 | **没有结果反馈**：`lastRun` 只记录“跑过”，不记录 hit/error/FP | 无法学习哪些模板有效；低产/失效模板持续吃预算 |
| 2 | **静态 2/3 配比** | 命中集很弱时仍挤占轮转；很强时又探索不足 |
| 3 | **TF 余弦是词面相似** | 同义词/版本别名/中文技术名匹配弱；tag 粒度粗（一个 tag 可能几百模板） |
| 4 | **无去重/家族合并** | 同一 CVE/同一路径的重复模板各占一次预算 |
| 5 | **无成本模型** | 按“条数”而非“请求/耗时”分配，重模板拖慢整体 |
| 6 | **无来源质量先验** | 社区模板来源通过率/误报率差异大，当前只统计不参与调度 |
| 7 | **无探索-利用权衡** | LRU 是公平覆盖，不是收益最大化；没有 bandit 式试错 |

> 严格说：如果目标是“保证全池覆盖 + 完全确定”，当前方案接近该约束下的最优；
> 如果目标是“固定请求预算内命中最多/更早出结果”，它不是最优。

## 2. 替代方案：HQC 调度（Hierarchical Quality-aware Contextual）

保留三层硬分层（CVE / tag / explore），替换桶内排序与预算分配。

### 2.1 模板级特征

| 特征 | 符号 | 来源 |
|---|---|---|
| 命中层级 | `tier_t` | CVE / tag / explore |
| 技术相关度 | `rel_t` | 指纹置信度 × tag 特异度 × TF 余弦（后续可换 embedding） |
| 质量先验 | `q_t` | 来源通过率、历史 hit 率、误报率（Beta 后验） |
| 严重度/可利用性 | `sev_t` | CVSS / KEV / 模板 severity |
| 预估成本 | `cost_t` | 模板请求数/历史耗时估计 |
| 探索奖励 | `ucb_t` | `c·sqrt(ln(N+1)/(n_t+1))`（或 Thompson） |

### 2.2 打分与选择

```
score(t) = w1·tier(t) + w2·rel(t) + w3·q(t) + w4·sev(t) + w5·ucb(t)
```

- 预算按**成本**而不是条数：在 `Σ cost(t) ≤ B` 下按 `score/cost` 贪心（或小规模背包）；
- 动态命中桶预算：`hitBudget = clamp(n·(1/3 + 2/3·matchQuality), n/3, 2n/3)`，
  `matchQuality` 由最高 `rel_t` 与 CVE 命中比例给出；**探索配额至少 n/3**；
- 去重：`familyKey = sorted(CVEs) + normalizedPathSuffix + matcherType`，
  同 family 只保留质量最高的一个；被去重模板仍计入覆盖率统计；
- 冷启动：无统计时退化为当前 LRU+TF（保证行为不回退）。

### 2.3 反馈闭环

每次扫描记录（本地，不联网）：

- 被选模板、实际请求数、耗时；
- 结果：`hit` / `error` / `blocked` / `timeout`；
- 若用户做了 triage：`TP/FP/覆盖`（可选，缺省不惩罚）。

更新 Beta 后验：`α = α0 + hit`，`β = β0 + miss`（或按 FP 加权）；
统计落 `data/state/nuclei_stats.json`，按模板 path 稳定键；重启恢复。

### 2.4 可复现/可审计

- 默认用确定性 UCB（无 RNG），平局按 path 字典序；
- 若启用 Thompson，随机种子 = scanID，并把 seed + 每个模板 score 写入
  `Result.Diagnostics`/`extras.nuclei_schedule`，支持复算；
- 配置开关：`nuclei.schedule: legacy | quality | bandit`，默认 `legacy`，
  灰度验证后切 `quality`。

### 2.5 分阶段落地

| 阶段 | 内容 | 工作量 | 验收 |
|---|---|---|---|
| P0（1–2 周） | 质量先验 + 去重 + 成本感知；保留 LRU 探索；确定性 | S/M | 离线回放命中率 ≥ 现状；全池轮转保证不退化 |
| P1（2–3 周） | UCB/Thompson 反馈闭环；`nuclei_stats` 持久化；诊断留痕 | M | hit@budget +20% 相对；首次命中时间 -30% |
| P2（可选） | embedding 语义相关度替换 TF（本地小模型/预计算向量） | M/L | 语义同义命中提升；无外部服务依赖 |

### 2.6 离线验证与灰度

- **回放**：用历史扫描结果（已存 `verified` + 请求日志）离线重算“如果按新策略选，前 k 条是否命中”；
- **影子模式**：同一次扫描同时算 legacy 与新策略选择，只执行 legacy，比较两套选择的重合/命中；
- **靶场**：在 DVWA/xsslabs/upload-labs + 合成靶场上跑 A/B，限制同一目标轮换避免学习污染；
- **门禁**：全池覆盖保证、确定性用例、去重后预算守恒、无新 panic/超时。

## 3. 是否保留当前实现

**保留骨架，不保留排序策略作为最终态**：

- 短期（5.2.4）：保留 `SelectWithCVE` 作为默认，先加“来源通过率 + 去重 + 动态配比”的
  `quality` 模式，作为低风险增量；
- 中期（5.3）：开启 `bandit` 灰度，用真实/靶场数据验证后再切默认；
- 不建议直接上 embedding 或大模型：会破坏离线、确定性、可审计三条产品约束。

## 4. 一句话

当前 MoE 调度是“覆盖公平”的好基线，不是“预算内命中率”的最优解；
升级方向是 **分层不变、排序变质量/成本、加反馈与去重、保留探索配额**，而不是换掉整个调度器。
