# SiteLens 4.0 开发文档 —— 资源占用治理

> 立项时间：2026-09-13。起因：用户实测反馈「任务管理器里资源占用有点高」。
> 本文是 4.0 的第一篇开发文档，只覆盖资源治理主线；后续主线（攻击链视角等）
> 另行开篇。3.x 期间可先行落地的 Quick Wins 单独标注。

## 一、实测基线（2026-09-13，本机 Windows 11，任务管理器/Process 口径）

| 进程 | 常驻内存（RSS / Private） | 说明 |
|---|---|---|
| sitelens.exe（引擎，空闲） | **977 MB / 1011 MB** | 刚启动未扫描的基线，不是峰值 |
| sitelens.exe（引擎，扫描中峰值） | ~1500 MB（实测 1,522,224 K） | full 档扫描期间 |
| SiteLens（Electron 壳） | 4 进程合计 ~410 MB | main + gpu + renderer + utility |
| **合计** | **常驻 ~1.4 GB** | 引擎是大头 |

结论：引擎空闲基线 ≈1GB 是主要矛盾——扫描还没开始，内存已经上去了。

## 二、瓶颈分析（代码证据）

1. **情报库全量常驻解码**（主因）：`internal/intel` 启动时把
   `nvd_cves.json.gz`（磁盘 37MB 压缩）全量解码为 `[]NVDEntry` 常驻——
   描述全文、CPE 产品向量全是 Go string，解码后膨胀 20~30 倍；
   kev / cve_ms / tscan 索引同模式。指纹扫描（多数日常场景）根本用不到
   NVD 全表，却为它常年买单。
2. **无 GC 软上限**：全仓无 `SetMemoryLimit`/`GOGC` 调优，Go 默认堆
   翻倍增长策略把扫描期尖峰进一步放大。
3. **nuclei 模板池**：apocalypse 档 cap 6000 模板，编译期内存尖峰 +
   每次扫描重新编译（无跨扫描缓存）。
4. **并发上限分散**：crawler / DAST / 主动模块各有自己的并发键
   （`MaxConcurrent: 3` 等），没有全局内存预算约束，档位叠加时互相放大。
5. **Electron 壳 4 进程**结构固定 ~0.4GB，属于 Chromium 底价，优化空间
   有限但可挤（renderer 定时器降频等）。

## 三、4.0 目标（量化验收）

| 指标 | 现状 | 4.0 目标 |
|---|---|---|
| 引擎空闲 RSS | ~1.0 GB | **≤ 300 MB** |
| 引擎扫描峰值（full 档） | ~1.5 GB | **≤ 800 MB** |
| GUI 合计 | ~0.4 GB | ≤ 250 MB |
| 扫描时长 | 基线 | 不回退超过 5% |

## 四、方案分层

### Quick Wins（3.x 可带，风险低）

- **a) GC 软上限**：引擎启动时 `debug.SetMemoryLimit(1 << 30)`（1 GiB 软限）
  + `debug.SetGCPercent(70)`。预计扫描峰值降 20~30%，零行为变化。
- **b) NVD 字段瘦身**：常驻结构只留 cve / severity / score / products 向量，
  描述截断 200 字节（检索结果页按需取全文）。
- **c) 惰性加载**：nvd / kev / cve_ms 首次触达才解码——纯指纹/端口场景
  空闲基线预期从 ~1GB 降到 200~300MB（对齐目标主项）。
- **d) 归还 RSS**：扫描结束钩子调 `debug.FreeOSMemory()`，把堆还给 OS，
  任务管理器立即可见回落。

### 中期（4.0 主力）

- **e) 情报库列式快照**：自建只读 mmap 索引（按 CVE 随机访问）替代全量
  解码常驻；更新管线照旧，加载成本 O(1)。
- **f) nuclei 模板编译缓存**：进程级 LRU，跨扫描复用编译产物（apocalypse
  重复扫描收益最大）。
- **g) 全局内存预算器**：`engine.max_memory_mb` 配置 + 超限自动降档
  （模板 cap → 爬取页数 → DAST 参数数，逐级收缩并在事件流明示降级）。
- **h) 结果流式落盘**：大目标的 Verified/Pages 改为流式写库，不再整包
  聚合在内存 map。

### GUI 侧

- **i)** renderer 图表/轮询定时器在窗口不可见时降频（已有
  backgroundThrottling，补齐自研轮询点）；可选关闭 GPU 加速的开关
  （设置 → 桌面端）。

### 长期

- **k) 引擎/情报库进程分离**：情报库独立 sidecar 进程 + IPC 查询，
  扫描进程随任务退出全量释放；空闲态只剩情报库常驻（瘦身后的百 MB 级）。

## 五、验收口径

每项优化合入时附 before/after 实测表（空闲 RSS / full 峰值 / 扫描时长），
三个数字两个以上达标才算闭环；资源仪表（设置页显示引擎 RSS/Goroutines/堆）
随 Quick Wins 一起上线，让优化效果用户可见。
