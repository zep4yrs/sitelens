## 2. 第二轮重点改造（Wave-2）

### 2.1 A-09 配置快照化（消除实测数据竞争）

- **server**：`Server.cfgPtr atomic.Pointer[config.Config]` + `cfgSnap()`；`applySettings` 持 `cfgMu` 做 **copy-on-write**（深拷贝 → 改拷贝 → 原子换枪 → `eng.SetConfig`）；`persistSettings` 与 `api_token` 语义不变。
- **engine**：`Engine.cfgPtr` + `Config()/SetConfig()`；`scanImpl` 入口取一次快照贯穿全流程（含内部 goroutine），扫描内 helper 全部改为显式传快照。
- **残留裸读 cfg 点：0**（审计 grep 无输出；非测试代码只剩 `cfgPtr` 的 Load/Store 与 `cfgPath/cfgMu`）。
- **取证**：`go test -race ./internal/server ./internal/engine` = ok（195s / 46s，0 DATA RACE）；修正 Host 后的复现程序 `go run -race ./.tmp/leadcheck/race` = **0 DATA RACE**。
- 新增回归 5 个：快照语义（写后旧扫描不变 / 下一次读到新值）、并发 `PUT /api/settings × 请求/扫描`、扫描入口快照（扫描到 25% 换枪，本次仍用入口快照）。

### 2.2 C-01 归档平方级 → append-only

- **格式**：`archive/<year>.jsonl`（每行一条）+ `archive/index.json(v2)` + `<year>.tombstones.json`；索引项带 offset/count/total/min_id/max_id。
- **写**：O_APPEND 追加 + 一次 fsync + 更新索引，**不重写历史**；`archiveIDs` 惰性去重（O(1)）。
- **删**：墓碑 + 索引计数递减，不重写分片；墓碑持久化，索引重建后删除语义仍生效。
- **迁移**：旧 `YYYY.json` 首次打开自动迁移（temp+fsync+rename，旧文件 `.bak` 保留；解析失败不删原文件、列入 `corrupt_files`）。
- **崩溃容错**：追加前修复尾部；读侧容忍末尾半行；损坏分片跳过并上报。
- **实测**：240 条 8KB 6.54s → **0.945s**（线性）；1000 条前后半程追加字节 +0.4%（不重写历史）。

### 2.3 C-08 SQL 全表解码 → 投影分页

- 新增 `ListScansPage(offset, limit, tech)`（列表**不再解码 result_json**，tech 过滤走参数化 LIKE + LIMIT/OFFSET）、`Stats()`（一条 COUNT/GROUP BY 聚合）、`BackfillScanSummary()`（幂等回填旧行冗余列）。
- 迁移 `002_scan_summary.sql` 新增 tech_count/vuln_count/duration_ms/tech_names 四列（双方言）。
- server 接线：`HistoryStats` 改走 `Stats()`（不再 `ListScans(10000)`）；启动时一次性回填旧行并打日志。

### 2.4 C-16 / C2-10 / C2-12 / D-13

- **C-16**：seedrefresh 清单改 temp+fsync+rename 原子写；Build 按 sha256 差分（`Plan.Unchanged`）；CopyFile 加 fsync。

## 6. 修复过程中新发现并修复的真缺陷（原报告未收录）

1. **intel `Match` 按 `Entry.ID` 去重导致漏报**（`internal/intel/intel.go`）：仓库 `data/intel_dump.json.gz` 的 vuln_kb 行**没有 `id` 字段**（Entry.ID 全为 0），`seen[v.ID]` 把同一技术的所有候选行误当同一条 → **每技术最多只输出 1 条 possible**，留哪条取决于 map 迭代顺序。
   - 修复：按行身份 `map[*Entry]bool` 去重（NVD 占位负 ID 单独 seenNVD）；`vulnsFor`/`Match` 排序补 CVE/Name/Product 兜底键 + `SliceStable`，输出顺序与 maxPerTech 截断集合确定化。
   - **行为变化（需产品口径确认）**：每技术 possible 情报从"最多 1 条"恢复设计值"最多 20 条"（实测 wordpress 16 / gitlab 12 / log4j 9，含同 CVE 多来源行）。若产品希望"按 CVE 再去重"是另一种语义，可再调整。
   - 新增回归：`TestMatchRowsWithoutIDsAllEmitted`、`TestMatchCapDeterministic`，以及重写后的 `TestShippedOverridesDoNotPoisonPossibleRows`（20 连跑通过）。

2. **`compare_versions` 运算符表缺 `=` 前缀**（`internal/dsl/dsl.go`）：`compare_versions("1.0","=1.0")` 恒 false。修复时与 `!=` 反向一并修正。
