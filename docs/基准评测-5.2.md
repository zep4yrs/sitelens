# 基准评测（CP-04）— 指标定义、季度复评流程与 G01/G02 对应

> 适用范围：SiteLens 5.2.x **CP-04 基准评测体系**。
> 执行手册（命令、清单格式、靶场部署、反作弊操作细则）见 **[benchmark/README.md](../benchmark/README.md)**；本文件定义口径与流程，是评测报告的引用依据。
> 对标来源：《[竞品对标与追赶方案](竞品对标与追赶方案.md)》G01/G02、§9 评测执行手册、§10 KPI；路线图：《[新功能路线图-5.2](新功能路线图-5.2.md)》CP-04。

## 1. 定位

没有基线的召回/误报数字不写进对外材料（对标文档 §10 的硬约束）。本体系解决三件事：

1. **可量化**：在冻结版本 + 固定靶场 + 人工标注下，给出 Precision / Recall / F1 / 覆盖率；
2. **可复现**：`benchmark/run.ps1|run.sh` 产出 raw + run-meta（版本/配置哈希），`benchmark/score.mjs` 从 raw + ground-truth 重算，任何人可复跑；
3. **可对比**：同一 suite/version/口径下的季度结果可比；变更（靶场、标注、目录、被测版本）必须显式记录。

不做：不替代人工渗透/DAST 定性评估；不评测"0day 研究能力"；不做无授权公网批量（红线）。

## 2. 指标定义

### 2.1 混淆矩阵（按「用例 × 漏洞类型」计）

| 量 | 定义 |
|---|---|
| TP | 某用例的**期望类型**（ground-truth `expected[].type`）被至少 1 条检出映射到该类型 |
| FN | 期望类型未被任何检出映射到 |
| FP | 该用例的检出类型**不在**期望类型集合内（每用例每类型最多计 1） |
| TN | 安全用例（`expected=[]`）且无目录内类型检出 |

关键口径（避免常见误读）：
- 计数单位是「用例-类型」，不是 finding 条数：同一用例同类型报 10 条仍只算 1 个 TP（`score.mjs` 去重）；
- 用例 URL 不参与类型匹配（靶场 URL 常含 `sqli` 等字样，会把其它 finding 误归为 SQL 注入，实测踩坑）；
- 映射不到目录类型的 finding 记 `out_of_catalog`，**只报告、不计 FP**（否则 CSP/HSTS 等配置建议会把 DAST 误报率淹没）；
- 一个 finding 只归一个类型（最长别名优先），不做多标签展开。

### 2.2 Precision / Recall / F1

```
Precision = TP / (TP + FP)          // 报出来的有多少是真的
Recall    = TP / (TP + FN)          // 真的有多少被报出来
F1        = 2 * TP / (2 * TP + FP + FN)
```

约定：
- 分母为 0 时该指标记 **0**（报告中同时给出 TP/FP/FN 原始计数，禁止只引用比率）；
- 汇总为**微平均**（先加总 TP/FP/FN 再相除），不是逐用例宏平均——靶场用例难度差异大，微平均更贴近"总检出成本"；
- 报告必须同时给出用例数、TP/FP/FN，避免"3 个用例 100% 召回"式误导。

### 2.3 覆盖率（G02 核心）

| 指标 | 公式 | 含义 |
|---|---|---|
| `expectedTypeCoverage` | TP 覆盖的**期望类型数** / 期望类型总数 | 套件内是否漏类（如某靶场期望 5 类只检出 4 类 → 80%） |
| `catalogCoverage`（G02 ≥80% 口径） | TP 覆盖的类型数 / `coverage-catalog.json` 类型总数 | 产品整体能力面：目录中的类型至少被真实检出过一次 |
| `detectedTypes` | 原始计数（分子） | 便于横向对比季度增量 |

说明：G02 的「覆盖率 ≥80%，每来源通过率有基线」中，**覆盖率**用 `catalogCoverage`（跨季度累计的检出类型集合 / 目录类型）；**每来源通过率**属于 CP-10 模板治理范围（5.2.x 后续），本文件先定目录与口径。

### 2.4 安全用例与误报率

```
caseFPR = 有目录内检出的安全用例数 / 安全用例总数
```

安全用例（`expected=[]`）是误报控制的主要样本来源：OWASP Benchmark 的 secure testcase、教学靶场中未修复的页面、盲测中人工确认无已知漏洞的站点。若安全用例数 < 期望类型用例数的 30%，报告须注明误报率置信不足。

传统 `FPR = FP/(TN+FP)` 不直接采用：靶场安全用例不是"无漏洞页面"的均匀抽样，且我们的 FP 计数是「用例-类型」而非请求级；`caseFPR` 更保守、可解释。

### 2.5 数据健康度（必须随报告展示）

| 项 | 含义 | 处理要求 |
|---|---|---|
| `missing_raw` | ground-truth 有、raw 缺失 | 对应期望记 FN；报告注明；重跑或显式标 missing |
| `invalid_raw` | raw JSON 解析失败 | 同上，先查 `raw/<id>.log` |
| `scan_error` | raw 里 `error` 字段非空 | 记 FN 并在报告列原因（连接失败/WAF/超时） |
| `out_of_catalog` | 映射不到目录的 finding 数 | 报告列出样例；用于目录维护判断，不计 FP |
| `extra_raw_files` | raw 有、ground-truth 无 | 忽略并警告；防止清单/标注版本不一致 |
| `duration` / `exit_code` | 执行台账（`summary.csv`） | 超时/失败不得静默，归档前处理 |

### 2.6 不使用的指标（及原因）

- **按 finding 条数的 P/R**：同一漏洞多报会惩罚/奖励无意义，且各产品去重策略不同；
- **纯响应差异命中率**：无法跨产品比较；
- **扫描时长排名**：受网络/限速档位影响，只在同一档位同一靶场做参考（对标文档性能维度另有口径）；
- **对目录外配置建议的误报统计**：会把 CSP/HSTS/证书类信息性发现混入 DAST 误报率。

## 3. 检出归一（`score.mjs` 实现，评测口径的一部分）

1. 取 raw 中 `vulnerabilities[] + verified[] + extras.netsec.findings[]`；其中
   `vulnerabilities[]` 里 `verdict=possible/potential/unverified` 的**未验证情报不计分**
   （避免把 CVE/模板情报当成检出、计入 FP 污染 P/R/F1）；
2. 文本归一：Unicode 小写 + 仅保留字母/数字（`sql 注入`、`SQL-Injection`、`sqlinjection` 归一后一致）；
3. 字段优先级：先 `type/name/title/check/cve/product`，匹配不到再看 `evidence/advice/severity/src`；**URL 永不参与**；
4. 按 `coverage-catalog.json` 别名做**最长别名**匹配（`sql injection` 优先于 `sqli`），命中即归入该类型；一个 finding 只归一类；
5. 目标级 `expected[].match[]` 可追加本用例专用别名（兜底目录覆盖不到的写法）；
6. 未命中任何类型 → `out_of_catalog`（样例进报告）。

目录是**唯一**类型字典：目录没有的类型不能出现在 ground-truth（`score.mjs` 直接报错）；新增类型必须走 §8 的目录维护流程。

## 4. 评分流程（单次）

```
targets 清单 + profiles/<mode>（冻结配置）
    → run.ps1/run.sh → out/<suite>-<mode>-<ts>/{run-meta.json,summary.csv,raw/*.json}
    → ground-truth.json（双人标注 + 仲裁）
    → score.mjs → out/.../summary.md + summary.csv（P/R/F1 + 覆盖率 + FN/FP 明细）
    → 复核（20% FP 人工确认）→ 报告 → 归档
```

计分公式即 §2.2/§2.3；`summary.md` 的「汇总指标」表逐项对应，报告引用时附该文件路径与版本字段。

## 5. 阈值与判定

对标文档 §10 的目标值（6 个月 / 12 个月）：

| 指标 | 6 个月 | 12 个月 | 本体系度量 |
|---|---:|---:|---|
| 真实站点盲测召回 | ≥70% | ≥80% | `Recall`（blind-real-sites suite，standard 档） |
| 真实站点盲测误报 | ≤15% | ≤10% | `caseFPR`（+20% FP 人工复核） |
| OWASP Top10 覆盖 | 10/10 | 10/10 | `catalogCoverage` 按 OWASP 列聚合（A01–A10 各 ≥1 类型） |
| 检测覆盖维度分（基准+靶场+盲测） | 3.2 | 3.8 | 本体系输出 + 评分表 |
| 1,000 URL 扫描时长 | ≤45 min | ≤30 min | 同一档位靶场批量 `summary.csv` 汇总 |

判定建议（内部复评用，非对外承诺）：
- 基线：首个季度产出 OWASP Benchmark + 教学矩阵 + 20 授权盲测三份结果，锁定基线；
- 环比：新版 vs 基线，同 suite/version/口径；P/R 变化超过 ±3pp 才判定为真实变化（小样本噪声）；
- 门槛：`catalogCoverage` 每季度不得回退；盲测 Recall 未达阶段目标时列改进项进路线图，不修改口径解释。

## 6. 季度复评流程

### 6.1 阶段与角色

| 阶段 | 动作 | 产出 | 主责 |
|---|---|---|---|
| Q0 计划 | 确定范围（靶场/盲测样本/竞品）、时间窗、授权 | 复评计划 | 评测负责人 |
| Q1 冻结 | 版本/配置/模板库/靶场镜像/目录/标注版本全部登记 | `run-meta.json` + 冻结清单 | 评测 + 研发 |
| Q2 扫描 | `-Mode standard` 批量跑；失败按 §2.5 处理 | `out/.../raw` + `summary.csv` | 评测 |
| Q3 标注 | 双人独立标注 → 分歧仲裁；先标注后看结果/双盲 | `ground-truth.json`（带 version） | 两名标注人 + 仲裁 |
| Q4 计分 | `score.mjs`；抽查 `out_of_catalog` 与 FN/FP | `summary.md/csv` | 评测 |
| Q5 复核 | 抽取 20% FP 人工复核确认真误报；争议用例 `-Mode deep` 复现 | 复核记录 | 复核人（非标注人） |
| Q6 报告 | 季度对标报告：指标、环比、失败样例、改进项 | 报告（引用产物路径） | 评测 + 产品 |
| Q7 归档 | raw/run-meta/ground-truth/报告整体归档；更新历史表 | 归档目录 | 评测 |

### 6.2 时间表（建议）

- 每季度首月第 1 周：冻结 + 扫描（OWASP Benchmark 2,740 用例按 standard 档约数小时，建议分片并行）；
- 第 2 周：标注 + 仲裁（盲测样本 20–50 站）；
- 第 3 周：计分 + 复核 + 报告评审；
- 第 4 周：归档 + 下季度改进项进入路线图。
- 每季度更换 ≥30% 靶场/样本，避免针对固定集合调优。

### 6.3 归档检查清单（缺一不可）

- [ ] `run-meta.json`（版本/commit/配置哈希/目标清单哈希/时间/主机）
- [ ] `raw/*.json` + `raw/*.log`（完整，无手工修改痕迹）
- [ ] `summary.csv`（执行台账；失败/超时已处理或注明）
- [ ] `ground-truth.json`（含 `version`、标注人、仲裁记录）
- [ ] `summary.md` + `summary.csv`（评分，头部版本字段齐全）
- [ ] 覆盖率目录版本（`coverage-catalog.json` 的 `version`）
- [ ] 20% FP 复核记录与争议用例复现命令
- [ ] 报告终稿（对外发布需双方确认口径）

## 7. 与 G01（基准评测体系缺失）的对应

G01 要求：建立 OWASP Benchmark / WAVSEP / 靶场矩阵 / 真实站点盲测，产出"首份季度对标报告，结果可复现"。

| G01 要素 | 本体系落地 |
|---|---|
| OWASP Benchmark（≈2,740 用例） | 目标清单 + 初始 ground-truth 由官方 `expectedresults-*.csv` 生成（README §4.3，CWE→目录映射）；按标准档跑，输出 P/R/F1 与类型覆盖 |
| WAVSEP | 按官方 testcases 清单建 target（一个用例一个 URL），标注类型同目录；`run.ps1` 直接复用 |
| 靶场矩阵（DVWA/pikachu/sqli-labs/upload-labs/xsslabs/bWAPP/Juice Shop/WebGoat） | `targets/lab-matrix.sample.json` 已给出入口清单与端口约定；按模块建 target 与 ground-truth（README §8） |
| 真实站点盲测（20–50 授权） | `targets/real-sites.sample.json` 模板 + README §9 授权/双盲/复核流程 + `caseFPR` 度量 |
| 结果可复现 | `run-meta.json` 冻结 + raw 归档 + `score.mjs` 重算；报告必须引用产物路径 |
| 首份季度对标报告 | §6 流程的 Q6 产出；基线锁定后写入对标文档 §10 的"现状"列（替换"未测"） |

验收对应（路线图 CP-04）：`node benchmark/score.mjs --selftest` 通过（计分逻辑回归门禁）；三个套件各产出可复现的 `summary.md`。

## 8. 与 G02（覆盖率口径不清）的对应

G02 要求：OWASP Top10 + CNVD 高发 Web 漏洞清单；覆盖率 ≥80%；每来源通过率有基线。

| G02 要素 | 本体系落地 |
|---|---|
| 漏洞类型清单 | `benchmark/coverage-catalog.json`：类型 id / 中文标签 / OWASP 2021 / CNVD 映射 / 归一别名，当前 30 类 |
| 覆盖率 ≥80% | `catalogCoverage = TP 覆盖类型 / 目录类型`，由 `score.mjs` 输出；报告按 OWASP 列聚合展示 |
| 每来源通过率基线 | 属于 CP-10 模板治理：本体系提供"模板来源 → 用例/类型"关联所需的目标清单与结果归档；通过率基线在 CP-10 落地 |
| 口径稳定 | 目录只追加不删改（删除/重命名需版本号 + §10 变更记录）；ground-truth 类型必须存在于目录，否则评分器报错 |
| 类型覆盖可下钻 | `summary.md` 的「类型明细」表：每类型期望/TP/FN/额外误报 + OWASP/CNVD 映射 |

目录维护流程：
1. 新增类型：`id`（蛇形）、中文 `label`、`owasp`、`cnvd`、至少 1 个 ≥3 字符的别名（中英文均可）；
2. `version` 更新为 `YYYY-QN`，在 §12 变更记录写明理由与影响（历史覆盖率不可直接对比时需注明）；
3. 同步检查 OWASP Top10 映射完整性（A01–A10 每类至少 1 个类型）；
4. `node benchmark/score.mjs --selftest` 必须仍通过（fixture 使用独立小目录，不受默认目录新增影响）。

## 9. 结果解读原则

1. **同时给分母**：任何 P/R 必须附 TP/FP/FN 与用例数；
2. **不跨口径比较**：不同靶场/标注版本/目录版本/扫描档位的结果不得并列；
3. **小样本谨慎**：<100 期望条目时，结论只作趋势；报告需注明置信限制；
4. **失败用例不略过**：`missing_raw/scan_error` 计入 FN 并在报告列原因；不得从分母中删除失败用例（否则召回虚高）；
5. **目录外不遮蔽问题**：`out_of_catalog` 逐条抽查；若属于应检类型，先修目录/归一，再重算，不许手工改 summary；
6. **环比用同版本**：新版结果 vs 基线只改被测版本一个变量；
7. **对外材料**：引用报告中的数字与产物路径，禁止摘取单套件/单类型的最优值。

## 10. 变更控制与版本记录

三份版本号各自独立、都必须出现在报告头部：

| 对象 | 版本位置 | 变更规则 |
|---|---|---|
| 覆盖率目录 | `coverage-catalog.json` 的 `version`（YYYY-QN） | 只追加；类型删除/重命名需理由 + 影响说明 |
| 标注真值 | `ground-truth.json` 的 `version` | 用例/期望变更需记 diff 摘要与仲裁人；旧版本归档保留 |
| 评分器 | `score.mjs` 的 `SCORER_VERSION` + `summary.md` 头部 | 计分口径改动必须同步本文件 §2/§3 并跑 `--selftest` |
| 被测版本 | `run-meta.json`（`sitelensVer`/配置哈希） | 每次评测自动写入 |
| 靶场 | `targets/*.json` 的 `version` + 镜像 tag/digest | 每季度换 ≥30%；变更写入报告 |

## 11. 风险与限制

| 风险 | 影响 | 缓解 |
|---|---|---|
| 靶场可被针对性调优 | 基准虚高 | 每季度换 ≥30%；禁止硬编码；盲测交叉验证；评审换靶场复测 |
| 标注主观性 | P/R 偏差 | 双人独立 + 仲裁；判定依据留证；20% FP 复核 |
| 小样本/类别不均 | 指标波动大 | 报告附计数与置信说明；多套件交叉 |
| 网络/限速波动 | 结果不稳定 | 固定 polite 档位与窗口；失败重跑；同档位对比 |
| 目录别名覆盖不足 | `out_of_catalog` 偏高、覆盖率低估 | 季度维护目录；抽查样例；`match[]` 兜底 |
| 依赖外部靶场镜像 | 环境不可复现 | 冻结 tag/digest；归档部署说明；不把靶场数据打进发行物 |
| 授权/合规 | 法律风险 | 仅授权目标；`gov.cn` 不参评；流量报备；双盲与销售隔离 |
