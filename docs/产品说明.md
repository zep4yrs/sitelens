# SiteLens 产品说明与版本区别（v5.2.3）

## 产品简介

SiteLens 站点透视是一个**可复核、可编排、可被智能体调用的 Web 安全验证平台**：

> 经典扫描器给你更多告警；SiteLens 给你更少、但能复现、能交付、能被自动化的结论。

产品分三层能力：

1. **验证器（立身之本）**：从告警到结论——二次确认、证据链、curl 复现、回归复测、SARIF/合规报告；
2. **平台（企业化基座）**：SQLite/PostgreSQL 存储、RBAC/租户、worker 池、定时任务、资产台账、任务中心；
3. **Agent 工具面（生态）**：MCP stdio server（13 个工具）、辰极 Lodestar 接入、事实图/攻击链。

单二进制引擎交付，引擎侧零外部运行时依赖（前端零构建，网页外壳字体走公共 CDN、不可达时回退系统字体栈，不影响扫描能力）。

## 核心能力

- **指纹识别**：header / cookie / meta / body / script / icon_hash 六通道 +
  13,727 条规则（自建精编 372 + webappanalyzer 社区 2,377 + EHole 中文产品 10,978）；
  5.2 起加指纹置信度校准（证据计数 / 通道加权 / 冲突降权 / 版本交叉校验）。
- **模板验证**：可运行模板 **117,889 条**（官方 http+协议族 / afrog / Wordfence /
  linuxadi 40k 等，统一漏斗准入），模板治理按来源统计 runs/pass/fail/hits。
- **非 HTTP 协议检测**：tcp / dns / ssl 模板 214 条经原始拨号层（netx）执行，
  端口服务探测自动路由，安全闸全程校验。
- **漏洞情报**：31,541 条关联情报（精选 1,985 + 模板情报行 29,556）+
  NVD 字典 371,755 条 + OSV 区间补全 + KEV 在野利用红标 + CVSS 本地计分。
- **验证引擎**：1,011 条内置无害验证（60 条手写核心集 + 167 条手写扩展集 + 784 条由 afrog/nuclei 模板转译的强判据；扩展/转译集仅完整/穷尽档运行）+ 二次确认 + 回显剔除 + 软 404 基线 +
  WAF 拦截不判定；5.2.3 修复 WAF/兜底 200 页被误判为真实文件的问题。
- **DAST**：反射 XSS / 报错 SQLi / 开放重定向 / 目录遍历 / 时间盲注 /
  布尔差分盲注 / SSRF 出带 / 反序列化入口面 / CRLF / 存储型 XSS 等，
  全部带复现命令证据链。
- **高级 Web 检测（G09/G10，默认关，授权目标专用）**：
  - 越权矩阵（IDOR / 水平 / 垂直，需调用方提供多角色会话）；
  - 业务逻辑探测（数量/价格/优惠券/幂等，默认 **dry-run 只出计划**，需显式授权才发请求）；
  - 上传绕过（危险扩展名/伪造 MIME/双扩展名，upload-labs 类场景）；
  - 反序列化入口标记识别（Java/PHP/.NET/Python，只识别不做利用）；
  - WebSocket 明文/未校验 Origin、h2c/HTTP2 ALPN 协议面检查。
- **攻击面发现**：同域深度爬取（`max_depth`）+ JS/SPA 路由发现 + 链接归一化 +
  认证矩阵（Header/Bearer/Basic/Cookie）+ 多会话原语 + OpenAPI/Swagger/HAR 解析 +
  GraphQL 只读 introspection。
- **利用级无害验证**：回显 / 报错指纹 / 时延差 / 出带四通道影响证明，
  判定 none / observed / proven；授权三重闸默认关，未授权目标零请求。
- **验证回归**：`sitelens regression` 按原 payload 重放历史发现，
  present / gone / unsupported 三分，退出码表达回归。
- **事实图与攻击链**：扫描产出结构化事实图（10 类实体 / JSONL 契约），
  支持黑白盒关联（`evidence_link`）与证据驱动的攻击链（entry / exploit / recon /
  impact / priv 五类节点；无证据不成边）；白盒侧含 AST 数据流污点分析
  （py / js / php / java / go，PHP grammar 第一方自持）。
- **企业化基座（6.x）**：`store.driver=json|sqlite|postgres` + DSN + 自动迁移 +
  失败回退 JSON；`web.auth_mode=token` 下 Bearer token 验签、`X-Tenant-ID`
  租户隔离、RBAC 读写权限；批量任务可走 MemoryQueue + WorkerPool
  （同 host 串行 / 重试 / 进度 / 取消 / Webhook）。
  **默认构建已编入 sqlite（modernc，纯 Go）与 postgres（pgx stdlib）驱动**；
  SQLite 已实测建表/落库/历史读取，PostgreSQL 需自备实例（驱动与方言 DDL 已就绪）。
  **注意**：`store.driver` 默认仍为 `json`（文件式）；切到 sqlite/postgres 时若连接或迁移
  失败会打印警告并回退 JSON（不阻断启动）。PostgreSQL 尚未连真实实例验证。
- **报告与交付**：JSON/CSV/宽表/HTML/MD + **SARIF 2.1.0** + 等保 2.0 三级 /
  OWASP ASVS 4.0.3 合规评估报告（MD/HTML，可打印 PDF）+ UI triage/白名单。
- **自动化**：cron 定时任务、结果 diff（new/fixed）、tag 分组、完成 Webhook、
  任务中心/资产台账 API。
- **生态与 Agent**：`sitelens mcp` 提供 MCP stdio server（scan / scan_status /
  scan_result / scan_cancel / history / graph / export / triage / apispec /
  graphql_introspect / assets 等 13 个工具），辰极 Lodestar 通过 `CHENJI_MCP_SERVERS`
  直接接入；主动工具默认关（需 `--allow-active`）。
- **URL 输入自动修正（5.2.3）**：补协议、去首尾标点/引号、hxxp/[.] 失陷指标还原、
  全角转半角、默认端口省略、移除锚点与内嵌凭据；**只改格式、不改目标**，
  修正说明在扫描响应/结果 extras/前端 toast 留痕。
- **ML 推理（默认开；5.2 起查表优先、模型兜底）**：严重度「NVD/情报行查表 →
  `sev-linear` 0.7MB 线性回归兜底」；产品先验/CWE 优先查表；**只调序，不凭模型
  直接产生发现**；ONNX 降为可选高级包。
- **诊断与反馈**：应用内反馈页 + 本机脱敏诊断包（版本/平台/资产就位/降级能力/
  最近失败），无埋点、无遥测。
- **其他**：TLS/DNS 网络层检测、源码审计（含 SCA）、JS 攻击面、无头渲染（可选）。

### 扫描强度档位（5.3 起 5 档）

| 档位 | 内置验证 check | 社区模板池（nuclei/afrog） | 字典/端口 | 适用 |
|---|---|---|---|---|
| 快速 quick | 不跑 | 不跑（cap 300 仅占位） | 收窄 | 冒烟、批量初筛 |
| 标准 standard（默认） | core（Lv0 核心集） | **不跑**（保持 5.2.3 默认请求行为） | 标准 | 日常巡检 |
| 深度 deep | core | 跑（上限 3000） | 放大 | 需要模板库覆盖但不追求极限 |
| 完整 full | all（含扩展集与转译集 1,011 条） | 跑（上限 6000） | 全字典 + 全端口 | 全面评估 |
| 穷尽 exhaustive | all（1,011 条） | 跑（上限 12000） | 最大字典 | 授权目标的最终验证，耗时最长 |

> 模板池总量：afrog 1,699 条（878 条可运行、转出 1,051 条检查）+ nuclei 模板池（远程同步）；
> 内置「验证型 check」是手写强判据（命中即证明漏洞存在），与模板池是两套引擎，不要混为一谈。
> 默认档不跑模板池，避免默认扫描请求量上涨；需要覆盖模板库请选深度及以上。
## 安装包版本区别

> 交付口径（2026-11）：5.2.3 的正式交付形态是桌面安装器
> `SiteLens-Setup-5.2.3.exe`（Wails 壳 + 引擎二进制 `sitelens-engine`，安装即用）。
> 5.2 起**引擎与 CLI 拆成两个二进制**：桌面安装包只含引擎（serve + update-seed），
> 命令行能力（scan / audit / doctor / history / update 等）经 npm 线
> `@fengqiao666/sitelens-cli`（TUI，唯一命令行入口）独立分发，不随桌面安装包发布。
> 下表的 full / lite 区分是 3.0 期打包口径，仅供了解历史差异。

| | **full 完整版** | **lite 精简版** |
|---|---|---|
| 体积 | ~1GB（zip，含模板池） | ~10MB（zip） |
| sitelens.exe 主程序 | ✅ | ✅ |
| 指纹规则 / 字典 | ✅ | ✅ |
| 漏洞情报库（31,541 条关联情报） | ✅ 内置 | ❌ 需自行放置 `data/intel_dump.json.gz` |
| Nuclei 模板库（117,889 可运行，含协议族） | ✅ 内置 | ❌ 可用 `update-nuclei` 在线拉取 |
| OSV / NVD / KEV 在线同步 | ✅ | ✅ |
| 适用场景 | 开箱即用、离线环境 | 网络/体积受限，或自行维护数据 |

> **数据说明**：`intel_dump.json.gz`（漏洞情报库）与 `tpl_intel.json.gz`
> （模板情报行）随本仓库分发；NVD 字典（37MB）经 `update-nvd` 在线再生。
>
> 安装方式：桌面安装器 `SiteLens-Setup-5.2.3.exe` 提供向导式安装、自动覆盖升级、
> 开始菜单/桌面快捷方式与完整卸载器；启动后由桌面壳内部拉起引擎。

## 使用

1. 安装并启动桌面版（桌面壳内部拉起引擎，默认监听 http://127.0.0.1:5000）。
2. 浏览器打开控制台，「设置」页可调整爬取/扫描参数、API Token、触发 OSV 同步；
   「反馈」页可生成本机脱敏诊断包。
3. 扫描选择器三维合成：范围（Web/子域/端口服务）× 验证（被动/主动/深度盲态）×
   强度（5.3 起五档：快速/标准/深度/完整/穷尽，见下表）；「利用级验证」总闸默认关；
   高级 Web 检测（越权/逻辑/上传/反序列化/协议面）默认关、逻辑与上传默认 dry-run，
   开启即对授权目标生效
   （授权判断与合规责任由使用者承担，`gov.cn` 目标代码级强制拒绝）。
4. 输入地址可直接粘贴聊天里的脏 URL（如 `hxxp[:]//example[.]com。`），
   系统自动归一化并在结果里记录修正项；`target.auto_normalize: false` 可关闭。
5. 企业化：`store.driver=sqlite|postgres` 切换存储；`web.auth_mode=token` +
   `web.auth_secret` 启用 RBAC/租户；`batch.use_worker_pool: true` 启用 worker 池。
6. MCP：`sitelens mcp --api-url http://127.0.0.1:5000 --api-token <token>`
   为智能体提供 stdio 工具面；主动工具需 `--allow-active`，接口契约见
   `docs/生态扩展-辰星接口.md`。
7. 数据更新：桌面版由引擎随包种子在版本变化后自动覆盖更新；npm 线用
   `sitelens update <目标>`（nuclei / afrog / fp / ehole / nvd / osv / tplintel）。
8. 回归验证：`sitelens regression <scan_id>`（退出码 0=无回归，1=存在回归；
   npm 线为该命令的唯一入口）。

## 已知限制

- 5.1.0 全代码库体检发现的历史缺陷与处置状态见 `docs/bug清单-5.1.0.md`；
  5.2.0 未单独发版，其修复范围已并入 5.2.3（见
  `docs/release-5.2.3/release-body-5.2.3.md`，内部明细见
  `docs/release-5.2.0/release-body-5.2.0.md`）；5.2.3 的新增限制见下。
- **高级 Web 检测默认关**：越权矩阵需调用方提供多角色会话（`Options.Sessions`），
  业务逻辑/上传默认 dry-run 只出计划；这是安全姿态，不是能力缺失。
- **企业化为“已接线、待规模验证”**：SQLite/PG、RBAC/租户、worker pool 已可用，
  但无 SSO/HA/多节点，未做万级资产压测；SQLite 实测可用，PostgreSQL 未连真实实例验证。
- **召回只有子集基线**：5.2.3 已用自建合成靶场（10 目标，P/R/F1=1.0）与 WSL 标准靶场子集
  （DVWA low/xss-labs/upload-labs，7 目标，P/R/F1=0.8333，CSRF 误报已修）完成首轮验收；
  完整 DVWA/pikachu 矩阵与授权站点尚未跑，upload 主动检测默认 dry-run；
  对外“准”的宣称仍以能力与证据链为主，不承诺具体召回率。
- **安装包为内部自签名**：5.2.3 安装器/壳/引擎已用自签名证书签名（内部验收口径），
  公网分发会显示“未知发布者”，正式发布前需替换受信任代码签名证书；真机安装/升级/
  启动/卸载/重装已验，托盘/Mica/通知为目视项。
- **`-race` 与 govulncheck 的 ONNX 标签**：已用 MinGW-w64 gcc + `CGO_ENABLED=1` 本地跑通
  `go test -race ./internal/... ./cmd/...` 与 `govulncheck -tags onnx ./...`；CI 复核后以 CI 结果为准。
- **无常驻埋点 / 匿名统计 / 崩溃自动上报**（《用户服务协议》承诺）：反馈只能
  由用户主动生成本地诊断包并自行提交，不采集任何使用行为。
- npm 线默认不带漏洞情报库与 ONNX 严重度模型资产（自备数据/资产后启用，
  缺失时静默跳过）；完整能力形态为桌面安装器。
- 模板来源存活率门禁目前只固化 afrog 一个来源，其余来源的通过率基线尚未成为
  CI 门禁；白盒污点分析无「净化器」概念；非 HTTP 协议通道的 DNS 重绑定缺口未修。
- 品牌更名「晦明」暂缓；正式交付仍仅 Windows 桌面，macOS/Linux 桌面规划中。
