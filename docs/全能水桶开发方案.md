# SiteLens 全能水桶漏洞扫描器 · 开发方案

> 定位升级：从「指纹识别 + 漏洞情报关联工具」→「验证型全能漏洞扫描器」。
> 四大支柱：被动指纹（已有）/ 情报关联（已有）/ **主动验证（缺，核心）** / **DAST 检测（缺）**。

## 一、核心架构演进：统一 Check 框架

把"检测"抽象成统一的 **Check 单元**（数据驱动，yaml 定义，加检测不改代码）：

```yaml
id: web-git-leak            # 唯一 id
type: active                 # passive 被动 / active 主动请求 / dns / tls / sast
level: standard              # 最低所需扫描等级
auth: false                  # 是否属授权限定模块
request:                     # 主动型：请求模板
  method: GET
  path: "/.git/HEAD"
match:                       # 判定规则（全部满足才算命中）
  status: 200
  body_contains: "ref: refs/"
severity: high
title: "Git 仓库泄露"
advice: "删除 Web 根下 .git 目录，部署流程加导出过滤"
```

`CheckRunner` 按**扫描等级**调度：等级递进（快速→标准→深度→全面），高级自动包含低级全部
check；指纹结果作为 **tag** 触发产品专属 check 集（识别出 WordPress 才跑 WP 专项）。
结果写入新表 `check_results`，与现有情报关联并列展示为「已验证漏洞」。

## 二、模块开发清单（8 个模块）

### M1 验证型 Check 引擎 + 50 条无害 check（核心，Phase 1）
- CheckRunner：请求模板执行 + matchers（status / body_contains / body_regex /
  header_contains / not_contains 排除误报）+ 软 404 基线复用
- 首批 50 条 check 全部为**只读类**：.git/.env/.svn/.DS_Store 泄露、备份文件
  (.bak/.sql/.zip)、Spring Actuator、Swagger/druid 控制台、phpinfo、Debug 页面、
  示例页面（tomcat/nginx 默认页）、CORS Origin 反射、Host 头注入回显、
  开放重定向参数探测、目录列表开启、错误详情泄露
- 命中的 check 升级为「已验证漏洞」，与情报关联分开呈现

### M2 版本区间判定引擎（Phase 1）
- `vuln_kb` 增加 `affected` 字段（区间语义：`>=8.3,<8.3.7`、`*`、`<=2.4.1`）
- 版本比较器：语义化版本 + 通配（2.x、8.3.*）
- 情报面板三级输出：**确认受影响**（有版本且落在区间）/ 可能受影响（同名无版本）/
  不受影响（版本落在区间外）——误报率断崖式下降

### M3 Web DAST 基础 12 项（Phase 2）
反射 XSS（唯一标记注入+回显定位+上下文判定）、报错型 SQL 注入（' 触发数据库
错误特征）、参数级目录遍历（../ 逐层）、开放重定向、CRLF 注入、mixed content、
表单缺 CSRF token、隐藏参数发现（常见参数名探测）、Cookie 属性缺陷
（Secure/HttpOnly/SameSite）、文件上传点识别、.map 源码地图、email/手机号收集。
全部基于「发标记→看回显/状态」，不含破坏性 payload。

### M4 认证扫描（Phase 3）
- 会话注入：扫描选项支持 Cookie 串 / 自定义 Header，爬取与全部 check 带会话执行
- 自动登录：可选提供登录页 URL + 用户名/密码字段名，引擎 POST 登录后校验会话
- 认证前后结果 diff（后台攻击面单独面板）

### M5 CMS 联动专项检查（Phase 2）
- WordPress：?author=N 用户枚举、xmlrpc.php 开关、wp-json 用户泄露、
  readme.html 版本、主题/插件目录遍历指纹
- Joomla / Drupal / Typecho / ThinkPHP 各 5-8 条特征 check
- 调度：指纹 tag → check 集，未识别的产品不空跑

### M6 TLS / DNS 检测（Phase 3）
- TLS：证书过期/自签/弱算法（SSLv3、TLS1.0）、证书与域名不匹配（sslscan 级别的
  精简版，纯连接层）
- DNS：SPF/DMARC/DKIM 记录缺失检测、Zone AXFR 尝试、CNAME 悬挂 →
  子域接管判定（指纹页返回 404/NXDOMAIN + CNAME 指向已知可接管服务）

### M7 JS 攻击面提取（Phase 4）
- .map 源码地图泄露检测（主动请求 .map）
- bundle 内 API 端点/云存储 bucket/第三方 key 形态提取（正则池 + 情报联动）
- Webpack/Vite manifest 中的依赖版本 → 版本区间判定引擎

### M8 工程化（Phase 4，贯穿）
- 并发：CheckRunner 线程池化（每目标 8 并发，跨目标 3），jobs 表作队列
- 插件化：checks 目录热加载，丢 yaml 即生效
- API 鉴权：Bearer token（.env 配置）
- 报告：HTML 报告加入已验证漏洞分区 + 执行摘要；PDF 导出
- 回归靶场：用 DVWA/pikachu 自动跑，断言检出率的测试集（最硬的可信度证据）

## 三、数据模型演进

```sql
ALTER TABLE vuln_kb ADD COLUMN affected TEXT DEFAULT '';     -- 版本区间语义
CREATE TABLE checks (                                        -- check 定义可入库也可纯 yaml
  id TEXT PRIMARY KEY, type TEXT, level TEXT, auth BOOL,
  severity TEXT, title TEXT, advice TEXT, spec JSONB);
CREATE TABLE check_results (                                 -- 已验证漏洞
  scan_id BIGINT, check_id TEXT, target TEXT,
  evidence TEXT, severity TEXT, verified_at TIMESTAMPTZ DEFAULT now());
```

## 五、合规红线（贯穿所有模块）

1. Check 库只收**只读/无害**类：不投破坏性 payload、不写数据、不打暴力点
2. 主动类模块维持"默认关闭 + 等级显式选择 + 授权警告"
3. 速率上限与并发硬编码封顶；robots 继续遵循
4. 登录爆破模块独立保留（授权专属），不混入任何等级默认链路

## 六、风险与对策

| 风险 | 对策 |
|---|---|
| 误报损害可信度 | matchers 排除规则 + 软 404 基线 + 靶场回归断言 |
| 全面级扫描耗时 | 并发池 + 等级设计（用户按需选）+ 进度面板已就绪 |
| 情报时效性 | vuln_kb 保持导入管线可重复执行；后续可加更新脚本 |
| 工作量 | 分四期，每期独立可用；Phase 1 完成即实现定位升级 |
