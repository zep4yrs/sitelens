# SiteLens 站点透视 — 完整开发文档

## 1. 项目定位

**SiteLens 站点透视**是一个结构完整的全类别验证型 Web 漏洞扫描器（当前版本
**2.0 验证器**），覆盖指纹识别、模板验证、DAST、认证扫描、网络层检测、源码审计
六大类攻击面。核心价值链：指纹识别 → 漏洞情报关联 → 模板验证引擎（117,883 条
可运行模板）→ 证据链报告（请求/响应/信号/复现命令）。

## 4. 设计原则

| 原则 | 落位 |
|---|---|
| 单二进制零依赖 | go:embed 前端 + 文件式存储 + 进程内出带 beacon（serve 与引擎同进程） |
| 全阈值可配 | .sitelens.yml 全量阈值注册表，零值/负值回退默认 |
| 宁少报不误报 | 漏斗准入（dsl Compile 静态校验，子集外整模板淘汰）+ 运行期类型错误一律不命中 + 命中二次确认 |

| 可再生数据 | 模板池/情报库不入仓库：update-* 子命令镜像 + full 版 Release 私有资产 |

## 6. 功能模块

### 6.1 模板验证引擎（核心）

多来源模板漏斗：YAML → convertAny 转换准入（不可运行整条淘汰）→ 同名去重
→ 索引缓存（data/state/nuclei_index.json，schema v5，文件数失配自动重建）。

调度：MoE 三路 Select——① tag 硬匹配置顶（severity 升序）；② lastRun LRU
（从未运行的优先）+ 词面相关度（词频余弦）；③ 分批全覆盖保证（⌈全集/n⌉ 次
扫描后全池必跑一遍），lastRun 持久化于 data/state，重启不丢进度。

求值：dsl 安全子集求值器（Compile 准入 + Eval 求值，覆盖真实模板 96%+ 用法）；
多请求模板与 extractor 抽取变量贯通（Match.Extracts + respEnv vars），抽取版本
喂情报三级判定——possible → confirmed 的关键链路。

### 6.2 漏洞情报三级判定

confirmed：版本落在 OSV/GitHub Advisory 区间内。
possible：同名提示（无版本或无区间数据）。
excluded：版本不在区间，跳过不展示。

### 6.3 安全响应头评分

8 项加权（HSTS 20/CSP 20/XFO 10/XCTO 10/RP 10/PP 10/COOP 10/CORP 10），A+~F。

### 6.4 认证扫描

authn 登录流：配置凭证对登录端点表单提交，捕获会话 Cookie 全扫描复用
（爬虫/DAST/目录探测共用认证态）；凭证只从配置读取，不写日志、不落证据。

### 6.5 可选主动模块（默认关）

目录探测（软 404 基线+403 绕过表）/ 子域名枚举（DNS 并发）/
端口服务识别（nmap banner）/ FingerDir 路径指纹 / 子域接管探测（18 服务
CNAME+特征页双条件）/ 登录爆破（授权闸+宽容表单解析+基线判定）。

### 6.6 DAST

参数级无害注入（XSS/SQLi/重定向/遍历）+ 布尔差分盲注（真假 payload 双向
差分+双确认）+ SSRF 出带回调（进程内 beacon，/b/<token> 回连即确认）+
反序列化入口面探测（Java 序列化魔数 aced0005 响应特征，保守低危）。
全部探针命中带 curl 复现命令（证据链）。

### 6.7 被动检测

Cookie 属性 + CSRF token 只读检查（零额外请求）。

### 6.8 网络层

TLS 证书检查 / 邮件安全（SPF/DMARC/MX）/ 端口服务识别。

### 6.9 辅助能力

JS 攻击面（bundle API 端点枚举 + SourceMap 泄露检测）/ 无头浏览器渲染
（chromedp，SPA 链接可见，默认关）/ 验证码识别（本机 ddddocr HTTP sidecar，
未配置明确报错）/ 源码审计（16 规则静态匹配，RE2 兼容改写）。

## 8. 安全设计

SSRF 三层防护（协议白名单+保留地址黑名单+DNS 逐 IP+重定向逐跳复检，
internal/target）。serve X-Token 鉴权。主动模块默认关。请求默认 400ms
间隔限速+封顶（全阈值可配）。robots.txt 遵循。凭证只从配置读取，不写日志、
不落证据；运行时头（UA/Cookie）不进报告。

## 12. 同类对比与改进路线

对比对象：Nuclei（引擎，MIT）与 Wapiti（同栈整车，GPL-2.0）。详细对比分析文档为内部资料，不在本仓库分发。

| 维度 | Nuclei | Wapiti | SiteLens |
|---|---|---|---|
| 形态 | 检测引擎（YAML DSL） | Python 扫描器（httpx 异步） | 扫描工作台 + 模板验证引擎（Go 单二进制） |
| 检测面 | 模板库 7000+，DSL/多请求/OOB | 29 主动模块（注入类深）+9 被动 | 模板池 117,883（MoE 调度 + tcp/dns/ssl 协议模板）+ 42 内置 check + DAST（注入/盲注/SSRF/反序列化）+ 利用级无害验证 + 验证回归 |
| 指纹/情报 | 无指纹情报层 | Wappalyzer 指纹，无情报层 | 2,853 指纹（372 自建 + 2,481 社区）+ 情报三级判定 + KEV |
| 吞吐 | 150 req/s | 异步并发 | 默认 400ms 间隔限速（合规取舍，全阈值可配） |
| 资产 | 无状态 | 无状态 | 文件式历史 + 双扫描 diff + JSON/CSV/HTML/MD 四格式导出 |

双向结论：检测面广度与注入深度对手占优（如实口径）；情报层、结果资产、源码审计、合规内建是我们独有。

改进路线：
- 已落地：命中二次确认 + 回显路径剔除（防自指误报，双向独有）；多源情报与来源追踪；CVSS 本地计分
- 已落地 P1：Cookie 属性/CSRF token 只读检测（passive 模块）；子域接管指纹表（takeover：18 服务 CNAME+特征页双条件判定，opt-in，候选封顶）
- 计划 P1 余项：同路径模板请求聚类提速
- 已落地 P2（部分）：DAST 表单字段探测（四类无害判定与 URL 参数同语义）
- 已落地 P2：模板 extractor 版本抽取喂三级判定（Match.Extract + refineVersion 回填技术版本，possible→confirmed 的关键链路）
- 不做：payload 注入类（与无害只读红线冲突）；GPL 代码零拷贝（只借鉴思路与数据格式）

### 13.1 设计决策记录

1. **存储**：PG → 文件式 JSON（data/state/history.json，tmp+rename 原子写）。
   单二进制可携带；行为契约（API 字段）不变。
2. **指纹匹配性能**：字面量门控（literalGate）先以子串存在性预筛，
   仅命中候选才执行正则——剖析驱动的 2.6x 优化（bench_test.go 固化）。
3. **Set-Cookie 保真**：Go http.Header 逐条分离，替代 Python 版
   合并头启发式切分（passive 模块因此删去全部切分判据）。
4. **规则形状容错**：technologies.json 历史导出中 194/370 条 html 通道为
   {dom,html} 对象形状，加载器双形状兼容（unmarshalRules）。
5. **取消语义**：JobManager 状态轮询在引擎阶段边界与 check 循环内生效，
   取消后局部结果不入库（对齐 Flask 版行为）。

### 13.2 遗留差距

已补齐（原差距 → 现状）：验证码 OCR → captcha 包接本机 ddddocr sidecar；
Nuclei 头匹配/dsl 匹配器 → internal/nuclei 漏斗 + internal/dsl 求值器全量
落地（多请求/抽取变量证据链已贯通，模板池 117,883 条）。

仍在：Python 污点分析（audit 为 16 规则静态匹配，非数据流污点）、
语义向量路由（语义检索以词频余弦近似）。3.0 起的范围见第 14 节。

## 14. 3.0 利用器开发实况（2026-09-12 立项并完成主体开发）

3.0 定位「利用器（Exploit Validation）」：从证明漏洞真实存在，到证明漏洞
能够影响。P1–P3 主体已落地（非 HTTP 协议检测 / 利用级无害验证 / 验证回归，
详见 docs/todo-3.0.md 勾选状态与 CHANGELOG v3.0.0），待发布流程（P6）。
开发范围定稿：

1. **利用级无害验证**：在 2.0 证据链（请求/响应/信号/复现命令）之上追加
   「影响证明」层——利用验证保持无害红线（不落盘、不提权、不持久化），
   以可观测副作用（回显/时延/出带）为影响证据。
2. **验证回归**：命中可重放、可回归断言；靶场回归门禁向利用级扩展。
3. **非 HTTP 协议检测**（2026-09-12 定入 3.0）：
   - 现状（立项时）：引擎与模板库均为 HTTP 专用——模板库仅镜像官方
     http/ 目录，network/dns/ssl/file 模板族不在池内；internal/httpx
     只会说 HTTP。【已落地：netx + 漏斗 v7 + 引擎路由，见 CHANGELOG】
   - 引擎侧：新增原始拨号层（TCP/UDP + TLS 握手 + DNS 查询），与 httpx
     并列；目标校验复用 internal/target 的协议白名单与保留地址闸。
   - 模板侧：漏斗准入 network/dns/ssl 模板族，索引与去重口径同现有来源。
   - DSL 侧：求值环境扩展原始响应（字节/行/多轮 send-receive），匹配
     语义与 HTTP 形态对齐。
   - 编排侧：按目标开放端口路由——Web 端口走现有流水线，服务端口走
     协议模板。
