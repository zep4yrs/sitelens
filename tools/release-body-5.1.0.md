# SiteLens v5.1.0 — 模板调度收口 + 判定通道补齐

发布日期：2026-10-11 ｜ 上个版本：[v5.0.0](../../releases/tag/v5.0.0) ｜ GPL-3.0

这一版两条主线：

1. **模板调度收口**——把「模板池里瞄着这台目标的那几百条」找出来先跑；
2. **桌面交付切到 Wails 壳**——安装包从 Electron 壳换成 Wails（Go + 系统
   WebView2），单文件壳约 12MB。

以及把上几轮攒下的一批判定通道/爬取缺陷收口。不改判定语义。

## 升级前必读

- **桌面壳换了（重要）**：从本版起安装包使用 **Wails 壳**。壳换了，但引擎、
  扫描能力、配置项语义完全不变。注意用户数据区路径随壳变化
  (`%APPDATA%\SiteLens-Wails`)，**从旧版升级需手工迁移配置与历史**
  （把 `%APPDATA%\SiteLens` 下的配置/`state`/`pools` 拷到新目录）。
- **自动更新已接线**：本版起 Wails 壳内建自动更新——启动静默检查一次 + 托盘
  「检查更新」，下载后 **静默就地覆盖安装**并自动重开。因本版是 Wails 线**首个
  发布**，升级到本版仍需**手动下载安装包**（旧版没有能识别 Wails 更新源的更新器）；
  装到本版后，后续版本即可走自动更新。
- **用户数据区**：Wails 线为 `%APPDATA%\SiteLens-Wails`，与旧 Electron 壳
  （`%APPDATA%\SiteLens`）不同，**从 5.0.0 升级需手工迁移配置与历史**。
- **安装包未签名**：首次运行 SmartScreen 可能拦一下，选「更多信息 → 仍要运行」。

## 这版做了什么

### 模板调度：不再让「瞄错目标」的模板吃光预算

模板池有八万多条。此前挑哪些先跑，只有两路：**tag 词面硬匹配**和
**最久没跑优先（LRU 轮转）**。问题出在：大量模板只用 CVE 命名、不带产品 tag，
在 tag 那一路永远是空集，只能等轮转轮到——而轮转**对单次扫描不承诺结论**。

这一版接上第三路：**指纹识别出的技术 → 这技术实际受影响的 CVE（情报库关联）
→ 声明这些 CVE 的模板置顶**。命中的模板优先于 tag 命中，
「这台机器真的中的」比「tag 词面对得上」更值得先花预算。

- 预算配比不变：命中集（CVE + tag）合计最多占 2/3，剩下留给轮转——
  保证「模板池迟早跑完一遍」的数学性质不被更强的匹配破坏。
- 没轮到的模板不丢，退回轮转池继续竞争。
- 情报库没挂载 / 指纹无关联时，行为与旧版**逐条一致**（有等价性测试兜底）。
- 单次扫描纳入通道的 CVE 数封顶 64，防止指纹繁多的目标把反查集撑爆。

**边界（不粉饰）**：这条通道只调**调度优先级**，不碰任何判定逻辑——
跑出来的结论仍由模板自己的 matcher + 二次确认负责。所以它零误报风险，
收益是「对的有机会跑」，不是「把库存变成命中」。

### 报告里能看见预算去哪了

扫描结果的 `extras.nuclei` 现在多出两个数，且在 **Web 页面、HTML 报告、
Markdown 报告**里都能看到一行「模板调度」摘要：

```
候选池 82709 · tag 命中 12 · 受影响 CVE 7 · CVE 命中模板 3 · 本轮选入 100/150 · 来源 http/cves 40 · legacy 60
```

`受影响 CVE` 和 `CVE 命中模板` **刻意分开列**——前者为 0 是指纹没对上情报，
后者为 0 是模板池里没有声明这些 CVE 的模板，两者含义不同，合成一个数就看不出来了。
这是这条通道唯一的在线判读口径（此前只进了 JSON，页面和报告都没渲染）。

### 爬虫：robots.txt 不再让爬取静默塌缩到首页

一个会让真实目标只爬出入口页的缺陷：旧实现只认 `Disallow` 前缀、忽略 `Allow`
和通配，一旦目标 robots.txt 写 `Disallow: /`（封禁整站），**每一条同域链接
都会被静默跳过**，扫描只有一页，报告却毫无线索。

- robots 解析重写：按 UA 分组、组内 `Allow`/`Disallow` 最长匹配优先、
  支持 `*` 通配与 `$` 锚点、剥离行内注释。
- 命中整站封禁时，扫描进度里**明确提示**，并给出 `crawler.respect_robots=false`
  的覆盖指引——是否遵循仍是配置项，但结果不再无声无息。

### 判定通道补齐（前几轮累积，本版一并发布）

- 验证码识别重放 / 越权 / 加密实现弱点 / 开放 API 四条判定通道。
- 命令注入回显通道 + 出带回调（OOB）通道；存储型 XSS；缓存卫生；
  弱会话 Cookie；弱随机标识；CSRF / 弱会话 ID / CSP 三个检查类扩面。
- 深度探测面扩容：SSTI / 命令注入 / CRLF / NoSQL / XPath / LDAP / JNDI(Log4Shell) /
  XXE / 上传受理面 / Cookie-头注入；目录遍历加多编码形态。
- 覆盖率两处修复：**首页带参探测点曾被爬取结果覆盖丢失**（`Search.asp?tfSearch`
  这类 GET 表单入口整块测不到）；**报错只回通用 500 页**的目标新增报错状态差分通道。
- 指纹误判噪声消除、目录端点扩展与目录列表识别、模板来源分列标注。

### 桌面交付：从 Electron 壳切到 Wails 壳

- 壳本体换成 Go 实现（`desktop-wails/`），窗口走系统 WebView2，**单文件壳
  约 12MB**（对比 Electron 安装包 ~100MB）；壳与引擎同语言栈。
- 引擎目录、端口决策、配置落点、启动页、托盘、退出树杀引擎——产品行为
  逐条对齐原 Electron 壳（端口默认仍是 `127.0.0.1:5087`，被占用才换随机）。
- 启动页、主窗交接时序、托盘、品牌图标沿用原有设计与资产。
- 发版链路同步切换：`tools/release_local.sh` 改走 Wails 构建 + NSIS 打包，
  打包前做**壳/引擎 PE 魔数校验**与**版本一致性硬闸**。

### 桌面交付续：自动更新 + 覆盖更新（本版一并交付）

切壳之后紧接着补齐了 Wails 线的自动化升级链路，本版一并发布：

- **自动更新**：启动静默检查一次 + 托盘「检查更新」→ 读更新源 `latest.yml`
  → 版本比对 → 下载安装包并 **sha512 校验**（截断/损坏当场发现，不碰已安装文件）
  → 以 `/S` **静默就地覆盖安装**（无向导页，安装器按注册表 `InstallDir` 不挪窝）
  → 装完自动重开新版。
- **覆盖更新（种子按版本交付）**：壳启动调引擎 `update-seed`，把随包只读种子
  （NVD 快照 / 情报行 / 指纹规则）按**包版本**覆盖到用户数据区。旧 Electron 壳
  是「用户区不存在才拷」，包内快照永远进不来（升了版本情报还是旧的）；现在
  **版本变化才覆盖、同版本 no-op**，`state/`（历史）、`pools/nuclei/`（模板池）、
  `plugins/`、`data/wordlists/` 永不覆盖——「覆盖更新」与「不伤用户成果」同时成立。
- **顺带修掉一个真实缺陷**：Wails 壳此前只写 `web.listen`，引擎按 cwd 解析的
  可写路径（`store.data_dir` 等）全落到安装目录 `$PROGRAMFILES64\SiteLens\engine\data`
  ——普通用户对该目录只读，写入即失败（Electron 壳 v3.0.0 首启 EPERM 的同一个坑）。
  现在受管键把可写路径全归到用户数据区（`internal/usercfg`，有跨平台单测）。

**边界（如实说）**：安装器是机器级（`RequestExecutionLevel admin`），非提权进程
拉起的自动更新**会弹一次 UAC**——是就地覆盖、无向导页，但不是零交互；零 UAC 需改
用户级安装，另行评估。**崩溃自愈、单实例**两块仍未接线。详见 `desktop-wails/README.md`
的「已知边界」。

## 验证

- `go build ./...`、`go test -count=1 ./internal/... ./cmd/...` 全绿；
  `go test -race ./internal/...` 全绿（实抓过竞态的包列为阻断门禁）。
- `gofmt -l`、`go vet ./...` 干净；vendor 与 go.mod 一致，无新依赖。
- 前端转义回归 + 三维选择器映射 + CI 配置门禁单测全绿。
- 新增 CVE 通道单测：CVE 优先于 tag/severity、空集时与 `Select` 逐条等价、
  命中集不饿死轮转；端到端 `nucleiSubset` 在 cap=1 且存在 tag 命中诱饵时
  仍选中受影响 CVE 的模板（关闭通道时该测试失败——先让红过）。
- 新增调度摘要单测：`受影响 CVE` 与 `CVE 命中模板` 分列、字段缺失安全返回、
  HTML/MD 双通道呈现。
- Wails 壳：跨平台端口决策单测全绿；`GOOS=windows` 构建 + `go vet` 通过；
  发版脚本的壳/引擎版本一致性硬闸与 PE 魔数校验在打包前生效。
- 自动更新/覆盖更新：`internal/seedrefresh`（白名单、版本相同跳过、源缺失原子性）、
  `desktop-wails/internal/updater`（版本比较含预发布/回滚、清单解析、下载地址拼接）、
  `desktop-wails/internal/usercfg`（可写路径必落用户区、受管键与引擎 yaml tag 对齐）
  单测全绿；`cmd/sitelens update-seed` 端到端（覆盖 + 清单落地 + 用户成果存活 + 幂等）。

## 已知边界（如实说）

- CVE 集合来自情报关联，可能含 possible 级。本通道只改优先级，不改判定。
- 这条仍是「让对的有机会跑」，天花板在准入层：缩小候选、不保证命中。
- 把模板命中抬到「可信一档」还需 source 字段分列口径 + 软 404/回显自证收口，
  属下一版范围。
- **Wails 桌面线**：崩溃自愈 / 单实例两块尚未接线；自动更新会弹一次 UAC
  （机器级安装）；用户数据区与旧 Electron 壳不同（`SiteLens-Wails`），从 5.0.0
  升级需手工迁移。详见 `desktop-wails/README.md`。
