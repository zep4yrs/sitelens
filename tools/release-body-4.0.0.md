# SiteLens v4.0.0 — 攻击链还原

发布日期：2026-09-18 ｜ 上个版本：[v3.0.0](../../releases/tag/v3.0.0) ｜ GPL-3.0

4.0 做了三件事。让软件**轻下来**：以前它开着不动就要吃掉将近 1GB 内存，现在空闲只要 130MB，全量扫描的峰值也压进了 800MB。让报告**连起来**：新增事实图和攻击链——扫完不只回答"哪里有漏洞"，还能回答"攻击者从哪进来、进来后能走到哪"，每一步都带证据。让界面**换过来**：整个工作台重排，源码审计变成带文件树和代码预览的正经工作台，暗色模式这次是真黑，不是偏蓝。

从 3.0 桌面版升级：设置 → 检查更新，或直接下载安装包覆盖安装。配置、历史、模板池全部兼容，零迁移。

## 升级前必读

- 数据与配置**零迁移**：`.sitelens.yml`、扫描历史、模板池与情报库沿用 3.0，覆盖安装即继承
- 新能力（事实图 / 攻击链）**默认不勾选**，不勾时扫描行为与 3.0 一致；勾选后扫描会多收集结构化证据，时长略有增加
- 自动更新源现在只有 GitHub（CNB 更新通道已下线）。大陆网络下载慢的话，直接用下面的安装包手动覆盖，效果一样
- 安装包未做代码签名：Windows 首次运行若弹 SmartScreen，点「更多信息」→「仍要运行」

## 新能力

**攻击链还原（事实图）**
以前扫完拿到的是一张漏洞清单，每条各自独立。4.0 在扫描时把入口点（哪个 URL 的哪个参数）、每条命中（检查规则 / 模板 / 被动指纹 / 参数注入 / JS 分析）、证据和影响收成一张图，再用真实的因果关系把它们连起来：这个入口点进来的，落在它身上的发现有哪些，验证到哪一步。扫完到「攻击链」页看，可复制 JSONL 给其他工具接着用。想复验历史发现，3.0 的 `regression` 命令不变。

**源码审计工作台**
工作台 → 源码审计，现在是完整的代码审计台：选一个文件夹（或直接拖进来），左边是可折叠的文件树，点开文件右侧显示代码，**有漏洞的行直接标红标黄**，下面的发现列表点一条就跳到对应行居中高亮。大文件不再有 512KB 的预览上限（二进制除外）。上传的文件审计完即删，不留存。

**内存治理**
情报库从"启动就全量装进内存"改成"用到才解码"，加上 GC 软上限和扫描结束归还内存，空闲占用从 977MB 降到 129MB——8GB 内存的机器上同时干别的事不再被它拖累。代价是垃圾回收更勤快了一点，我们做了对照实测：同机开关治理各跑五轮，扫描时长 13.90 秒对 13.98 秒，差异在误差范围内。

**全新工作台**
主动功能（综合扫描 / 网络层检测 / 登录爆破 / 源码审计 / 批量扫描）收进左侧控制栏，画布归结果；被动页（设置 / 情报库 / 历史 / 攻击链）同一套侧栏，来回切换不迷路。所有页站内切换，不再整页刷新。

## Bug 修复

这一版修了不少陈年问题，按你遇到的症状分组：

**登录爆破：之前可能一直在白跑**
- 选「无验证码」跑完显示"未命中"——实际上一次都没有真正提交过，所有尝试在内部被验证码流程拦下跳过了。已修复
- 明明试出了弱口令，结果页却显示"未命中"——命中结果在最后一步被丢掉了。已修复
- 每跑一次任务，后台就多一个每秒一次的隐藏轮询，跑得越多越卡。已修复

**源码审计：三个"打不开"**
- 文件夹里的嵌套子目录文件点不开。已修复
- 有漏洞的代码行不标红标黄。已修复
- 大于 512KB 的文件打不开——现在取消了这个上限，多大的文本文件都能打开（二进制除外）
- 文件夹上传偶尔第一次失败要重选一次。已修复

**界面**
- 暗色模式的黑是偏蓝的。现在是中性黑
- 窗口拖窄时左侧功能按钮挤成一团。现在自动收成图标
- 部分页面有多余的说明文字占地方。清理了七处

## 如何启用事实图

扫描页「验证」组勾选「事实图」，扫完到「攻击链」页查看。利用级验证的开关位置不变（设置 → 引擎配置），3.0 开过的升级后仍保持开启。
